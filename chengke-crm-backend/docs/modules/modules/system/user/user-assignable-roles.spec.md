## 1. 接口概述

- **用途与调用场景**：新增 / 编辑用户表单的角色选择器（可搜索单选器）加载选项：仅展示当前管理员有权授予且状态正常的角色（已确认，PRD §4.9、§8.4.2）；已停用角色不可选；无可用角色时禁止提交（已确认，PRD §8.2）。
- **功能权限**：`system:user:create` 或 `system:user:update`（总览 §8.1）。
- **成功状态码**：200。
- **是否修改数据**：否，**不改变任何数据**。
- **引用章节清单**：
  - 总览 §4.2 全局约定、§5.4 授权边界（不能分配高于自身的权限 / 数据范围）
  - 总览 §8 权限、§11.2 错误码总表
  - 总览 §18 P0-2（角色数据源未实现）、P0-8（可授予判定机制）

---

## 2. 请求示例

```
GET /api/v1/system/users/assignable-roles
```

无请求参数。

---

## 3. 请求参数（Controller 层契约）

无请求参数。返回状态正常（`active`）且操作者有权授予的角色。

---

## 4. 参数校验与业务校验

**参数校验**：无参数。

**业务校验**

- 候选角色必须 `status=active`（已停用角色不可分配，角色管理 PRD §15.1 已确认）。
- 候选角色必须在操作者「有权授予」范围内（授权边界，总览 §5.4）；判定机制依赖角色管理模块，**待确认**（总览 §18 P0-8）。
- 角色数据源（角色表）尚未实现，本接口数据访问 **待确认**（总览 §18 P0-2）。

---

## 5. 业务逻辑（Service 层）

```
请求 + JWT
→ 功能权限校验（create 或 update）
→ 读取状态正常的角色（数据源待确认，总览 §18 P0-2）
→ 按「有权授予」边界过滤（判定机制待确认，总览 §18 P0-8）
→ 返回 200 + 角色选项列表
```

提交表单时只传角色 ID（已确认，PRD §8.4.2）；选项接口同时返回稳定 ID 与名称，禁止前端写死角色数据。

## 9. 成功 / 失败行为

**成功**：权限校验通过 → 返回可分配角色集合；不改变任何数据。无可用角色时返回空数组（前端禁止提交，已确认，PRD §8.2）。

**失败**（数据均不变化）：

| 场景 | 错误码（总览 §11.2） | HTTP | 业务是否终止 |
| --- | --- | --- | --- |
| 无 `system:user:create` 且无 `system:user:update` | `USER_OPERATION_FORBIDDEN` | 403 | 是 |
| 数据库错误 | `USER_DATABASE_OPERATION_FAILED` | 500 | 是 |
