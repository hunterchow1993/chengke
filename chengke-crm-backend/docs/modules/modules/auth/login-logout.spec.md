## 1. 接口概述

- **用途与调用场景**：用户主动退出；无可用菜单页上的「退出登录」（登录 PRD §7.4、§12.9、§12.10）。撤销当前会话及对应保持登录刷新凭证。
- **功能权限 / 数据权限**：无业务权限码。需要**有效会话**才能标识「当前会话」。会话已失效时的重复退出见 §12。
- **成功状态码**：**待确认**；设计建议 HTTP 200。
- **是否修改数据**：是。当前会话及关联刷新凭证立即失效（登录 PRD §7.4）；写会话撤销审计（登录 PRD §9.4）。不修改用户密码、`status`、`forcePasswordChange`。
- **引用章节清单**：
  - 总览 §4.2 全局约定、§5.4 会话撤销、§5.7 安全
  - 总览 §6.3 会话状态
  - 总览 §7.3 数据变化、§9 一致性、§10.2 重复退出
  - 总览 §11.2 `SESSION_REVOKED` / `AUTHENTICATION_REQUIRED`
  - 总览 §13 审计

本接口**不是**「撤销该用户全部设备会话」的管理端能力；全量撤销见总览 §2.1 / §16。主动退出是否只撤销当前设备 **待确认**（与总览 §18 P0-10 设备数相关）。登录 PRD §7.4 对主动退出的表述为「保持登录凭证立即失效」，针对的是该次保持登录 / 当前会话，未明确是否踢掉其他设备。

## 2. 请求示例

PRD 未定义 Body。无已确认 JSON 字段。

```
POST /api/v1/auth/logout
```

会话凭证如何携带：请求头 `Authorization: Bearer <accessToken>`（总览 §4.3，已确认）。不接受 Body 中的用户 ID 以退出他人会话。

## 4. 参数校验与业务校验

**参数校验**：无已确认业务 Body。

**业务校验**

- 能识别当前会话：撤销该会话及与之绑定的刷新凭证。
- 不能通过参数指定其他用户 ID 完成强制下线（强制下线是另一能力，总览 §16）。
- 会话已不存在 / 已撤销：幂等语义 **待确认**（总览 §18 P1-3）。

---

## 5. 业务逻辑（Service 层）

```text
提交退出
↓
解析当前会话
  无法解析 → 按「未登录」处理（是否仍 200 待确认）
↓
撤销当前会话
↓
撤销与该会话绑定的刷新凭证（保持登录立即失效，登录 PRD §7.4）
↓
是否同时撤销同一用户其他设备：待确认（默认不得自行扩展为全设备退出）
↓
写审计：会话撤销结果、用户 ID、时间、IP、设备摘要（登录 PRD §9.4）
↓
响应成功语义；前端清菜单与权限缓存并回登录页（前端职责，登录 PRD §12.9）
```

| 当前会话 | 允许退出 | 系统行为 |
| --- | --- | --- |
| 有效 | 是 | 当前会话与对应刷新凭证失效 |
| 已撤销 / 已过期 | **待确认** | 不得复活会话 |
| 强制改密未完成 | 是 | 允许退出回到登录页（登录 PRD §12.10 无权限页亦提供退出） |

## 6. 数据操作与 SQL（DAO 层）

| 操作 | 目的 | 数据来源 | 数据变化 |
| --- | --- | --- | --- |
| 定位当前会话 | 确定撤销范围 | 请求中的凭证 | 无 |
| 将会话与刷新凭证标为撤销 | 主动退出后不可再用 | 会话 ID | 修改会话存储；介质 **待确认**，**无 SQL 示例** |
| 写审计 | 登录 PRD §9.4 | 用户 ID、结果、IP、UA | 新增；无凭证原文 |

不 UPDATE `sys_user` 业务列。

| 字段 | 类型 | 是否必定存在 | 空值规则 | 业务含义 | 来源 |
| --- | --- | --- | --- | --- | --- |
| （正式字段表） | — | — | — | **待确认** | — |

若使用全局 `ApiResponse`，成功时 `code=OK`、`data` 是否为空 **待确认**。不得返回仍有效的访问令牌或刷新凭证。

## 8. 响应示例

无法确认 JSON。成功语义：当前会话已不可用于受保护 API。

---

## 9. 成功 / 失败行为

**成功**：当前会话及对应刷新凭证已失效 → 审计已记录撤销结果 → 调用方清除前端授权缓存并回登录页。

**失败**

| 场景 | 数据是否变化 | 错误码 | 业务是否终止 |
| --- | --- | --- | --- |
| 无法识别会话 | 否 | `AUTHENTICATION_REQUIRED` 或按幂等成功（**待确认**） | 是或视为已退出 |
| 系统异常 | 不得出现「响应成功但凭证仍有效」 | `SYSTEM_UNAVAILABLE` | 是 |

退出后访问受保护 API：资源服务器拒绝；业务编码 `SESSION_REVOKED` 与 HTTP 401 关系见总览 §18 P0-7。

---

## 10. 事务与并发要点

- **原子组**（总览 §7.3）：当前会话与绑定的刷新凭证必须一并失效；不允许只清客户端内存令牌却服务端会话仍可用。
- **并发**：退出与在途业务请求交错时，最终该会话不能继续被授权（总览 §10.1）。
- **幂等**：重复退出不得创建新会话；不得报成登录成功。具体 HTTP 总览 §18 P1-3。

---

## 11. 验收标准（本 API）

- [ ] 主动退出后，原访问令牌 / 刷新凭证不能访问受保护 API。
- [ ] `rememberMe` 会话退出后 7 天凭证立即失效。
- [ ] 不修改用户密码与账号状态。
- [ ] 审计含撤销结果，不含完整凭证。
- [ ] 不能通过本接口撤销其他用户会话。
- [ ] 强制改密中的用户可以退出。
