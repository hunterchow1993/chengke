## 1. 接口概述

- **用途与调用场景**：认证已成功但 `forcePasswordChange=true` 时，用户提交新密码；系统更新密码、撤销其他旧会话、创建新登录会话，之后才允许进入首页流程（登录 PRD §8.2）。
- **功能权限 / 数据权限**：无 `system:user:*`。需要**有效会话**，且该会话对应用户处于强制改密（总览 §5.5、§8.1）。
- **成功状态码**：**待确认**；设计建议 HTTP 200。
- **是否修改数据**：是。修改用户密码凭据与 `forcePasswordChange`；撤销其他旧会话；创建新会话；写审计（总览 §7.3）。
- **引用章节清单**：
  - 总览 §4.2 全局约定、§4.3（强制改密会话可调接口）
  - 总览 §5.4 会话撤销、§5.5 首次改密闸门、§5.7 安全
  - 总览 §6.2 改密状态、§6.3 会话状态
  - 总览 §7.1 本模块可写用户字段、§7.2 `sys_user`
  - 总览 §9 事务、§10 幂等、§11.2 错误码、§13 审计
  - 用户管理总览 §7.1 密码不可逆、禁止明文日志（单一事实来源）

## 2. 请求示例

登录 PRD 只确认「完成新密码和确认密码校验」，未给出 JSON 字段名。`confirmPassword` 在用户管理中为前端校验不提交（用户管理 PRD / user-create Spec）。本接口**不编造**已确认 Body。能确定的业务数据只有「新密码」本身。

示意为**设计建议**（字段名未在登录 PRD 出现，正式字段名 **待确认**）：

```json
{
  "newPassword": "<user-input>"
}
```

若评审要求与登录一样用 `password` 表示新密码，须先确认后改本节，不得同时发明多套字段。

不接受：`tenantId`、目标用户 ID（用户只能改自己）、管理员重置用的 `forcePasswordChange` 开关（改密成功后必须变为 `false`，不是请求传入）。

## 3. 请求参数（Controller 层契约）

| 参数 | 类型 | 来源 | 必填 | 默认值 | 校验规则 | 业务含义 |
| --- | --- | --- | --- | --- | --- | --- |
| 新密码 | string | Body | 是 | — | 长度至少应符合登录密码 8–32 且不 trim 内部空格（登录 PRD §6.1 为登录输入规则）；复杂度是否复用用户管理初始密码规则 **待确认**（总览 §18 P1-2） | 替换后的登录凭据 |
| `confirmPassword` | string | Body | **待确认** | — | 登录 PRD 要求完成确认校验；是否仅前端 **待确认** | 确认新密码 |
| 当前用户 | UUID | 当前登录会话 | 是 | — | 会话有效且对应强制改密用户 | 禁止改他人 |
| 租户 | UUID | 当前登录会话 | 是 | — | 与用户行一致 | 隔离 |
| 旧密码 | string | Body | **待确认** | — | 总览 §18 P1-1 | 是否必须再验一次 |

会话凭证来自 `Authorization: Bearer`（总览 §4.3，已确认）。

---

## 4. 参数校验与业务校验

**参数校验**

- 新密码必须存在；长度 8–32（与登录输入上限对齐，已确认的登录字段规则）。
- 更强复杂度（字母 / 数字 / 特殊字符至少两类等）**待确认**。
- 若 Body 包含 `confirmPassword`：必须与新密码一致；若仅前端校验则后端不接收该字段。

**业务校验**

- 必须有有效会话；否则 `AUTHENTICATION_REQUIRED` / `SESSION_REVOKED`（映射总览 §18 P0-7）。
- 会话用户必须 `forcePasswordChange=true`；已为 `false` 时是否拒绝 **待确认**（总览 §10.2）。
- 用户须仍为 `active`；若改密前已被停用，应无法继续（停用须撤销会话，总览 §5.4）。
- 是否禁止与旧密码相同 **待确认**（总览 §18 P1-2）。
- 无有效角色时登录本不会给出可进入系统的路径；改密过程中角色被停用 **待确认** 是否仍允许改密完成。

## 5. 业务逻辑（Service 层）

```text
提交首次改密
↓
会话是否有效？否 → 认证失败，不改密码
↓
用户是否仍 forcePasswordChange=true？否 → 待确认（拒绝或幂等成功）
↓
（若需要）校验旧密码 → 失败则不得改密；错误码待确认（未在登录 §11.3 单列「旧密码错误」；不得擅自增加未登记错误码，须先登总览 §11.2）
↓
新密码参数校验失败 → 拒绝，密码不变
↓
事务内：
  更新密码凭据为不可逆哈希
  forcePasswordChange = false
  撤销该用户其他旧会话及刷新凭证（登录 PRD §8.2「撤销其他旧会话」）
  创建新登录会话（保持登录是否继承原 rememberMe：待确认）
  写审计（禁止写密码）
↓
返回成功；随后前端拉授权上下文（登录 PRD §8.1 步骤 8）
```

| 当前 forcePasswordChange | 会话有效 | 允许改密 | 系统行为 |
| --- | --- | --- | --- |
| `true` | 是 | 是 | 更新密码、清闸门、换会话 |
| `true` | 否 | 否 | 不改数据 |
| `false` | 是 | **待确认** | — |

改密成功后 `authContextRequired` 语义：登录 PRD 要求改密完成后请求授权上下文。本接口是否复用登录结果五字段 **待确认**（总览 §18 P1-6 同类）。

## 6. 数据操作与 SQL（DAO 层）

| 操作 | 目的 | 数据来源 | 数据变化 |
| --- | --- | --- | --- |
| SELECT 当前用户行 | 确认开关、状态、租户 | 会话中的用户 ID + tenant | 无 |
| UPDATE 密码凭据与 `force_password_change` | 首次改密完成 | 新密码哈希；开关 false | 修改 `sys_user` 对应列；`version` 是否 +1 **待确认**（用户管理乐观锁字段，本 PRD 未要求） |
| 撤销其他会话 / 刷新凭证 | 旧密码会话不可再用 | 用户 ID，排除即将创建的新会话 | 旧会话失效；存储 **待确认** |
| INSERT 新会话 | 改密后继续使用系统 | 用户、租户、有效期规则 | 新增会话 |
| 写审计 | 可追溯 | 操作者即本人、结果 | 新增；无密码 |

```sql
UPDATE sys_user
   SET /* 密码凭据列 */ = :passwordHash,
       force_password_change = false
       -- updated_at / updated_by / version 是否更新：待确认
 WHERE id = :userId
   AND tenant_id = :tenantId
   AND force_password_change = true;
```

影响行数为 0：开关已变或用户不存在 → 按 §5 待确认分支处理，不编造错误码。

会话表 SQL **待确认**。

## 7. 响应结构

登录 PRD 未定义本接口响应字段。不得补全 `code` 以外、又不属于已确认登录结果的业务字段。

**设计建议（需评审）**：成功时复用登录结果五字段：`success=true`，`forcePasswordChange=false`，`authContextRequired=true`，`requiresCaptcha=false`，`errorCode` 为空。失败时使用总览 §11.2 已登记编码（认证类用 `AUTHENTICATION_*` / `SESSION_REVOKED`；系统用 `SYSTEM_UNAVAILABLE`）。

| 字段 | 类型 | 是否必定存在 | 空值规则 | 业务含义 | 来源 |
| --- | --- | --- | --- | --- | --- |
| （正式字段表） | — | — | — | **待确认** | — |

不得返回新密码、哈希、完整刷新凭证。

## 9. 成功 / 失败行为

**成功**：密码生效 → `forcePasswordChange=false` → 其他旧会话不可用 → 新会话可用 → 用户可进入授权上下文 / 首页流程（仍可能 `NO_AVAILABLE_MENU`）。

**失败**

| 场景 | 数据是否变化 | 错误码 | 业务是否终止 |
| --- | --- | --- | --- |
| 无会话 / 已撤销 | 否 | `AUTHENTICATION_REQUIRED` 或 `SESSION_REVOKED` | 是 |
| 参数非法 | 否 | 全局参数校验；无新登录枚举 | 是 |
| 系统异常 | 整笔回滚 | `SYSTEM_UNAVAILABLE` | 是 |

失败不得出现「密码已改但旧会话仍全部有效」或「开关已关但密码仍是旧值」。

---

## 10. 事务与并发要点

- **原子组**（总览 §7.3、§9）：密码凭据 + `forcePasswordChange=false` + 撤销其他旧会话 + 新会话，必须同时成功或全部不生效。
- **并发**：改密与其他设备用旧密码并行时，最终旧会话全部不可用（总览 §10.1）。
- 重复提交：总览 §10.2，行为 **待确认**。

---

## 11. 验收标准（本 API）

- [ ] 仅持有强制改密会话的用户可成功改密。
- [ ] 成功后旧密码不能再登录；其他旧会话不能访问受保护 API。
- [ ] `forcePasswordChange` 为 `false`。
- [ ] 响应与日志不含密码。
- [ ] 新密码满足已确认长度规则；复杂度按评审结论执行。
- [ ] 失败时用户行与会话不处于部分更新状态。
