## 1. 功能目标

### 1.1 业务问题

澄客 CRM 需要为企业内部授权员工提供统一身份入口（登录 PRD §1、§2）：

- 用已由管理员创建的账号完成身份验证，而不是公开注册或营销获客。
- 在认证成功后由后端统一计算菜单、功能权限和数据范围，前端不得按角色名称自行推断菜单（登录 PRD §12.1）。
- 对连续失败、异常登录进行限制并留下可审计记录（登录 PRD §3.1、§9）。

### 1.2 使用方

| 使用方 | 说明 |
| --- | --- |
| 普通员工 / 部门管理员 / 系统管理员 / 超级管理员 | 使用用户名或手机号 + 密码进入各自权限范围内的后台（登录 PRD §4，已确认） |
| 登录页前端 | 提交登录、按需展示验证码、按 `forcePasswordChange` 跳转改密、拉取授权上下文、退出登录 |
| 认证与授权模块（资源服务器） | 消费本模块签发的 JWT Claims，不负责签发（认证 Spec §1，已确认） |
| 用户管理模块 | 提供账号、密码凭据、`status`、`forcePasswordChange`；重置密码 / 停用账号后须使本模块会话失效（登录 PRD §7.4、§9.2；用户管理总览 §12） |
| 角色管理模块（未实现） | 提供角色状态、功能权限编码、数据范围、菜单筛选所需权限集合（登录 PRD §12.2；用户管理总览 §18 P0-2） |

### 1.3 期望结果

- 授权员工可用用户名或 11 位中国大陆手机号 + 密码完成登录（登录 PRD §3.1、§16 v1.0）。
- 系统校验账号状态、角色是否有效、以及是否必须首次改密（登录 PRD §8）。
- 支持最长 1 天、可撤销的保持登录；前端不得用 Local Storage 保存密码或长期访问令牌（登录 PRD §7.4、§9.2）。
- 失败可恢复、可限制、可审计；错误用稳定英文编码，前端不依赖中文原文判断（登录 PRD §11.2、§11.3）。
- 登录成功后由后端生成授权上下文；无可用菜单时不进入空白后台（登录 PRD §12）。

## 2. 功能范围

### 2.1 本次包含

- 用户名或手机号 + 密码登录（登录 PRD §16 v1.0）。
- 账号状态、角色有效性、`forcePasswordChange` 校验。
- 图形验证码挑战的签发与一次性校验（登录 PRD §6.2、§9.1）。
- 连续失败达到阈值后的验证码要求与临时锁定（阈值数值为建议基线，是否采用见 §18 P0-4）。
- 常规会话与最长 1 天保持登录会话（登录 PRD §7.4、§9.3）。
- 首次登录修改密码（登录 PRD §8.2；页面原型不在本期后端范围）。
- 登录后独立获取授权上下文（菜单树、功能权限码、数据范围摘要、默认首页、权限版本）（登录 PRD §12；是否与登录响应合并见 §18 P0-11）。
- 主动退出并撤销当前会话。
- 登录审计日志（登录 PRD §9.4）。
- 服务端具备「撤销指定用户全部会话」的能力，供密码重置、账号停用、角色失效、管理员强制下线消费（登录 PRD §7.4、§9.2、§9.3）。该能力的**独立管理端 API** 不在本期登录页接口内（见 §16）。

### 2.2 本次不包含

- 用户自主注册（登录 PRD §3.2）。
- 短信登录、二维码登录、第三方扫码、单点登录、多因素认证（登录 PRD §3.2、§16 后续版本）。
- 用户通过短信或邮件自助重置密码（登录 PRD §7.5、§3.2）。
- 登录设备列表与会话管理界面（登录 PRD §16 后续版本候选）。
- 公开产品介绍、客户案例、营销信息接口。
- 用户管理、角色配置、菜单配置的维护 API（由对应用户 / 角色模块负责）。
- 业务接口上的功能权限与数据权限校验（由认证模块 + 各业务模块执行；本模块只负责签发与授权上下文计算）。
- 前端埋点事件实现（登录 PRD §13 为埋点建议，非后端 API）。

## 3. 业务对象

| 业务对象 | 说明 | 关键字段 | 与其他对象关系 |
| --- | --- | --- | --- |
| 用户账号 | 管理员创建的登录身份；本模块读取不维护 | id、username、mobile、密码凭据、status、forcePasswordChange、roleId、tenantId、name、avatarUrl | 归属租户；v1.0 拥有一个角色（用户管理 PRD / 用户管理总览 §3，已确认） |
| 角色 | 权限载体；本模块读取不维护 | id、name、status、功能权限集合、数据范围 | 一个用户 v1.0 一个角色；停用或无有效角色则不可进入系统（登录 PRD §8.3） |
| 登录会话 | 认证成功后的受控会话 | 用户 ID、租户、是否保持登录、有效期、撤销状态 | 一对多 用户；凭证撤销后不可再访问受保护 API |
| 刷新凭证 | 保持登录时签发、最长 1 天、可撤销（登录 PRD §7.4） | 与会话绑定；具体字段 **待确认** | 从属于登录会话；退出 / 重置密码 / 停用 / 角色失效 / 强制下线时立即失效 |
| 访问令牌 | 受保护 API 使用的短时凭证 | 须含认证 Spec §2.2：`sub`、`tenant_id`、`permission_version`；`scope`、`manageable_department_ids` 见认证 Spec | 由本模块签发，由认证模块校验；投递为 JSON `accessToken` + 后续请求 `Authorization: Bearer`（已确认，§4.3） |
| 图形验证码挑战 | 风控触发后的一次性校验 | captchaToken、captchaCode、60 秒失效（登录 PRD §6.2） | 与登录提交绑定；一次使用后失效 |
| 失败计数 / 临时锁定 | 连续失败风控状态 | 主体、窗口、次数、锁定截止时间（阈值见 §5.3） | 登录成功后清除当前账号连续失败计数（登录 PRD §9.1） |
| 授权上下文 | 后端统一计算的菜单与权限快照 | user、role、menus、permissionCodes、dataScope、homeRoute、permissionVersion（登录 PRD §12.4） | 依赖用户 + 有效角色 + 权限 / 菜单配置 |
| 菜单节点 | 授权上下文中的树节点 | 见 §4.2 MenuNode 字段表 | 由功能权限筛选；空目录删除（登录 PRD §12.2） |
| 登录审计日志 | 登录尝试与会话结果 | 用户 ID（无法识别则不记）、时间、结果、失败原因分类、IP、设备或浏览器摘要、会话创建或撤销结果（登录 PRD §9.4） | 多对一 用户（可空） |

依赖关系：

- 登录 **依赖** 用户账号（密码凭据、状态、`forcePasswordChange`）。
- 登录 **依赖** 角色（必须有效才创建会话）。
- 授权上下文 **依赖** 角色权限与菜单配置（角色管理未实现，见 §18 P0-6）。
- 访问令牌 **被依赖**：认证模块按 Claims 解析操作者上下文。

## 4. API 总览与全局约定

### 4.1 API 总览（唯一索引）

> Method / URL 列为**设计建议**（登录 PRD 只定义字段与流程，未定义 HTTP 路径）。新增 / 删除 / 改名 API 时必须先更新本表，再同步 API Spec 文件。

| # | API 名称 | Method | URL | 用途 | 调用场景 | 功能权限 | 成功 HTTP | Spec 文件 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 登录 | POST | `/api/v1/auth/login` | 校验账号密码与风控，创建会话 | 登录页提交表单 | 无（公开） | **待确认**（见 §4.3）；设计建议 200 | [login.spec.md](./login.spec.md) |
| 2 | 获取图形验证码 | GET | `/api/v1/auth/captcha` | 签发一次性验证码挑战 | 需要验证码时展示 / 刷新图片 | 无（公开） | **待确认**；设计建议 200 | [login-captcha.spec.md](./login-captcha.spec.md) |
| 3 | 首次登录修改密码 | POST | `/api/v1/auth/first-password-change` | 强制改密完成后更新密码、撤销旧会话、创建新会话 | `forcePasswordChange=true` 的改密页提交 | 有效会话（含强制改密会话） | **待确认**；设计建议 200 | [login-change-password.spec.md](./login-change-password.spec.md) |
| 4 | 获取授权上下文 | GET | `/api/v1/auth/context` | 返回菜单树、权限码、数据范围摘要、首页、权限版本 | 登录成功且无需改密后；改密完成后；刷新 / 恢复会话；权限版本变化后 | 有效会话 | **待确认**；设计建议 200 | [login-auth-context.spec.md](./login-auth-context.spec.md) |
| 5 | 退出登录 | POST | `/api/v1/auth/logout` | 撤销当前会话及对应刷新凭证 | 用户主动退出；无可用菜单页的「退出登录」 | 有效会话 | **待确认**；设计建议 200 | [login-logout.spec.md](./login-logout.spec.md) |

**索引一致性要求**：不允许总览表里有而文件不存在的 API，也不允许文件存在而总览表里没有的 API。

**未列入本期独立 API、但 PRD 要求具备的能力**（见 §16、§18）：

| 能力 | 说明 | 状态 |
| --- | --- | --- |
| 刷新访问令牌 | 保持登录签发刷新凭证（登录 PRD §7.4），但未定义刷新请求字段 | 是否独立接口 **待确认**（§18 P0-3） |
| 撤销指定用户全部会话 | 密码重置 / 停用 / 角色失效 / 强制下线时调用 | 对内能力，无登录页 URL |
| 维护状态查询 | 登录区展示维护说明（登录 PRD §10.3） | 是否独立接口 **待确认**（§18 P1-5） |

### 4.2 全局约定

**认证与操作者上下文**

| 接口 | 认证要求 |
| --- | --- |
| 登录、获取图形验证码 | **公开**。必须加入认证模块 HTTP 白名单（认证 Spec §2.1 当前白名单不含本模块路径，落地时需同步，见 §18 P0-1） |
| 首次改密、授权上下文、退出登录 | 必须已有本模块签发的有效会话 / 访问令牌；请求体不接受 `tenantId`、操作者字段 |

- 租户：JWT 需要 `tenant_id`（认证 Spec §2.2，已确认）；登录请求体**没有**租户字段。登录时如何解析租户 **待确认**（§18 P0-5）。
- 公开接口没有 JWT 操作者上下文；`requestId` 是否仍写入统一外壳 **待确认**（认证 Spec 对未认证请求的响应体格式亦待确认）。

**统一响应外壳 `ApiResponse<T>`（项目既有实现，已确认存在；登录结果如何嵌套见 §4.3）**

| 字段 | 类型 | 一定存在 | 业务含义 |
| --- | --- | --- | --- |
| `code` | String | 是 | 业务码；成功为 `OK` |
| `message` | String | 是 | 展示消息 |
| `data` | T | 成功时 | 业务数据 |
| `requestId` | String | 是 | 请求追踪 ID |
| `timestamp` | OffsetDateTime | 是 | 响应时间 |

登录 PRD §11.2 另外定义了业务结果字段 `success` / `errorCode` / `requiresCaptcha` / `forcePasswordChange` / `authContextRequired`。这些字段是登录结果的**已确认**内容；它们与 `ApiResponse.code`、HTTP 状态的映射为**设计建议**（§4.3），不得把未在 PRD 出现的业务字段塞进 `data`。

**分页外壳**：本模块无分页接口。

**共享枚举**

| 枚举 | 取值 | 说明 | 状态 |
| --- | --- | --- | --- |
| 登录错误 `errorCode` | `INVALID_CREDENTIALS` / `ACCOUNT_DISABLED` / `ROLE_UNAVAILABLE` / `CAPTCHA_REQUIRED` / `CAPTCHA_INVALID` / `ACCOUNT_TEMP_LOCKED` / `RATE_LIMITED` / `SYSTEM_UNAVAILABLE` | 稳定英文编码；前端按编码映射文案，不依赖中文原文（登录 PRD §11.3） | 已确认 |
| 授权异常编码 | `AUTH_CONTEXT_LOAD_FAILED` / `NO_AVAILABLE_MENU` / `ROUTE_FORBIDDEN` / `ACTION_FORBIDDEN` / `PERMISSION_VERSION_CHANGED` / `SESSION_REVOKED` | 登录 PRD §12.12 | 已确认（本模块接口直接返回哪些见各 API Spec；`ROUTE_FORBIDDEN` / `ACTION_FORBIDDEN` / `PERMISSION_VERSION_CHANGED` 主要由业务接口消费） |
| 用户状态 `status` | `active` / `disabled` | 沿用用户管理总览 §4.2 | 已确认 |
| 菜单节点 `type` | `directory` / `page` | 登录 PRD §12.5 | 已确认 |
| 是否强制改密 `forcePasswordChange` | `true` / `false` | 用户管理创建 / 重置时设置；本模块读取；改密成功后必须变为 `false`（登录 PRD §8.2 流程） | 已确认 |

**通用参数约定**

- 用户 ID、租户 ID：UUID（沿用用户管理 / 认证 Spec）。
- 时间：项目既有 `OffsetDateTime`；登录审计需要登录时间（登录 PRD §9.4），展示格式 **待确认**。
- 账号 `account`：去除首尾空格；最大 32 个字符；不自动改变字母大小写（登录 PRD §6.1）。当前前端 schema 为最大 64（`login.schema.ts`），以 PRD 为准，差异见 §17。
- 密码：8–32 个字符；不去除用户主动输入的内部空格；不进行自动格式化（登录 PRD §6.1）。当前前端 schema 为 8–128，以 PRD 为准，差异见 §17。
- 验证码：4–6 位；不区分大小写；60 秒后自动失效；一次使用后失效（登录 PRD §6.2）。

**通用错误行为**

- 账号或密码错误使用统一提示，**避免未通过密码验证的请求判断账号是否存在**（登录 PRD §8.3，已确认）。对应编码：`INVALID_CREDENTIALS`。
- 服务端不返回包含敏感内部信息的原始异常文本（登录 PRD §11.2）。
- 登录响应和错误日志不得返回密码、密码哈希或完整会话凭证（登录 PRD §9.2）。
- 错误码唯一注册表见 §11.2；API Spec 只能引用该表中的错误码。
- `ROUTE_FORBIDDEN` / `ACTION_FORBIDDEN` / `PERMISSION_VERSION_CHANGED` / `SESSION_REVOKED` 是登录后业务访问的稳定编码（登录 PRD §12.12）；除本模块接口外，业务 API 亦应能返回后三者中与会话 / 权限版本相关的编码。`PERMISSION_VERSION_CHANGED` 的 HTTP 为 **409**（已确认）。`SESSION_REVOKED` 与 401 的映射仍 **待确认**（§18 P0-7）。

### 4.3 关键设计决策（设计建议，需评审）

| 决策点 | PRD / 既有约定 | 本 Spec 决策 | 理由 |
| --- | --- | --- | --- |
| API 基础路径 | PRD 未给 URL | `/api/v1/auth/*` | 与 `/api/v1/system/*` 业务资源路径区分；登录为认证入口 |
| 登录业务失败的 HTTP | PRD 定义 `success` + `errorCode`，未定义 HTTP | 认证类业务失败（§11.3 各码）返回 HTTP 200，`ApiResponse.code=OK`，失败原因只放在 `data.errorCode`；参数校验失败 400；未处理系统异常 500 且 `errorCode=SYSTEM_UNAVAILABLE` 或外壳 `code` 对应系统错误 | 保留 PRD 的 `success` 字段；同类失败同一 HTTP，降低枚举账号的旁路 |
| 凭证投递 | PRD：访问令牌和刷新凭证优先 HttpOnly / Secure / SameSite Cookie；认证 Spec 当前校验 `Authorization: Bearer` | **已确认（2026-09-05）**：统一使用 `Authorization: Bearer`。登录 / 首次改密 / 刷新成功只在 JSON `data.accessToken` 返回访问令牌；受保护 API、授权上下文、刷新、退出均携带该头。不使用 Cookie 投递访问令牌或刷新凭证，JSON 中不返回独立刷新凭证明文 | 与资源服务器只验 Bearer 对齐；覆盖 PRD「优先 Cookie」 |
| 授权上下文独立接口 | PRD §12.3 建议独立；§15-11 待确认是否与登录合并 | 本期按独立 GET 列入 §4.1；登录成功只返回 §11.2 字段，`authContextRequired=true` | 与「建议独立、刷新可复用」一致；若评审改为合并，必须同步删除或改写 API #4 并更新登录响应 |
| 强制改密会话能调的接口 | 「不允许直接进入业务系统」（PRD §8.2） | 强制改密未完成前，除「首次改密」「退出登录」外，拒绝业务 API 与授权上下文 | 防止未改密进入后台；授权上下文是否也拒绝见 §18 P1-1 |
| 公开路径白名单 | 认证 Spec §2.1 | 登录、验证码必须匿名可访问 | 否则无法登录 |

## 5. 共享业务规则与决策表

> 本章只收录影响多个 API 的规则。

### 5.1 账号识别

**触发** → 登录提交 `account`。

**判断（已确认）**

- 接受用户名或 11 位中国大陆手机号（登录 PRD §6.1）。
- 去除首尾空格；不自动改变字母大小写。
- 用户名在租户内忽略大小写唯一（用户管理总览 §5.5）。
- 用户名必须以英文字母开头（用户管理创建规则）；因此 11 位纯数字按手机号匹配，其余按用户名匹配（该分流是对两份已确认规则的组合，不是新规则）。
- 是否还支持工号：**待确认**（登录 PRD §15-1；v1.0 范围是用户名或手机号）。

**行为** → 在已解析租户内查找对应用户；找不到与密码错误走同一失败语义（§5.2）。

### 5.2 防枚举（凭证失败）

**触发** → 账号不存在，或账号存在但密码不匹配。

**判断** → 尚未通过密码验证。

**行为** → 统一 `INVALID_CREDENTIALS`，提示口径「账号或密码错误，请重新输入」（登录 PRD §8.3）。不揭示账号是否存在。

**不适用于**：已通过密码验证之后的 `ACCOUNT_DISABLED`、`ROLE_UNAVAILABLE`（登录 PRD §8.3 为这两种提供了不同提示）。

临时锁定提示是否在密码验证前返回（可能泄露账号存在性）**待确认**（§18 P0-9）。

### 5.3 连续失败、验证码与临时锁定

登录 PRD §9.1 **建议**首版基线（阈值必须由后端配置，不允许写死在前端）。是否采用下列数值 **待确认**（登录 PRD §15-4，本 Spec §18 P0-4）。下列内容标记为**建议基线**，不是已确认业务规则。

| 条件（建议基线） | 系统行为（建议基线） |
| --- | --- |
| 同一账号 15 分钟内连续失败 5 次 | 下次登录必须完成图形验证码 |
| 同一账号 15 分钟内连续失败 10 次 | 临时锁定 30 分钟 |
| 同一 IP 请求频率超过安全评审阈值 | `RATE_LIMITED`；阈值本身 **待确认** |
| 登录成功 | 清除**当前账号**的连续失败计数（已确认，登录 PRD §9.1） |
| 管理员重置密码 | 清除临时锁定状态（已确认，登录 PRD §9.1）；是否允许管理员单独解锁 **待确认**（登录 PRD §15-6） |

**已确认（与建议数值无关）**

- 验证码不在默认登录页常驻，按风险条件出现（登录 PRD §6.2）。
- `captchaToken` 由服务端签发，一次使用后失效；`captchaCode` 4–6 位、不区分大小写、60 秒失效（登录 PRD §6.2）。
- 需要验证码而未提供 → `CAPTCHA_REQUIRED`；提供但错误或失效 → `CAPTCHA_INVALID`（登录 PRD §11.3）。

**待确认（§18 P0-9）**：失败计数主体是账号、IP 还是账号+IP；账号不存在时是否计入失败、是否触发验证码。

### 5.4 会话创建与撤销

**创建（已确认）**

- 账号、密码、账号状态、角色均通过后，服务端创建会话并记录成功日志（登录 PRD §8.1）。
- 未勾选保持登录：常规会话；浏览器关闭后的时长由安全策略决定（登录 PRD §7.4）；具体时长 **待确认**（§18 P0-10）。
- 勾选保持登录：签发最长 1 天的可撤销刷新凭证（登录 PRD §7.4）。
- 普通会话和保持登录会话统一使用 1 天有效期（登录 PRD §9.3）。
- 同一账号允许同时登录的设备数量 **待确认**（登录 PRD §15-2）。

**必须立即失效的触发（已确认，登录 PRD §7.4、§9.2）**

| 触发 | 系统行为 |
| --- | --- |
| 用户主动退出 | 当前会话及保持登录凭证立即失效 |
| 密码重置（用户管理） | 相关会话立即撤销 |
| 账号停用 | 相关会话立即撤销 |
| 角色失效 | 保持登录凭证立即失效；登录时亦不创建会话 |
| 管理员强制下线 | 指定用户全部会话可被主动撤销（登录 PRD §9.3） |
| 首次改密成功 | 撤销**其他**旧会话，再创建新登录会话（登录 PRD §8.2） |

访问令牌在撤销后不得继续访问受保护 API（认证 Spec §5「不允许」）。资源服务器按 JWT `jti` 查会话是否未撤销；已撤销则拒绝。权限版本不一致走 §5.6 的 409，不是本条。JWT 算法与 `iss`/`aud`/`exp` 取值仍 **待确认**（§18 P0-2 剩余项）。

### 5.5 首次改密闸门

**触发** → 认证成功且用户 `forcePasswordChange=true`（登录 PRD §8.2）。

**行为（已确认）**

- 不允许直接进入业务系统。
- 登录结果带 `forcePasswordChange=true`，且登录成功后 `authContextRequired=true`（字段表已确认；前端应先改密再拉授权上下文，登录 PRD §8.1 步骤 7–8）。
- 用户完成新密码校验后：更新密码、撤销其他旧会话、创建新会话、进入首页流程。
- 改密页原型不在本 PRD 范围内（登录 PRD §8.2）。

新密码复杂度是否与用户管理「初始密码」规则完全一致 **待确认**（§18 P1-2）。`confirmPassword` 是否提交给后端 **待确认**（用户管理已确认仅前端校验不提交；登录 PRD 只说「完成新密码和确认密码校验」）。

### 5.6 授权上下文计算（跨登录成功后的读取）

**顺序（已确认，登录 PRD §12.2）**

1. 获取当前会话对应用户。
2. 校验用户状态是否为 `active`。
3. 获取用户当前有效角色。
4. 获取角色关联的功能权限编码。
5. 根据功能权限筛选可访问菜单和页面路由。
6. 删除没有任何可访问子菜单的空目录节点。
7. 根据角色数据范围计算数据权限摘要。
8. 计算用户可进入的默认首页。
9. 生成权限版本 `permissionVersion`。
10. 返回完整授权上下文。

超级管理员同样走该流程，不允许前端「超级管理员显示全部菜单」（登录 PRD §12.2）。

**空菜单（已确认，登录 PRD §12.10）**

- 不进入空白后台框架。
- 记录 `NO_AVAILABLE_MENU` 授权异常日志。
- 不允许前端默认补充首页或其他菜单。

**权限变更（已确认，登录 PRD §12.11；2026-09-05 闭合延迟与 HTTP）**

- 角色权限定义、用户角色、部门范围或账号状态变更并提交后，后端将 Redis 租户授权版本 `chengke:authorization:version:{tenantId}` +1，并使相关权限缓存失效。改角色的功能权限 / 数据范围 / 敏感字段定义时同样必须 +1，不只在改用户角色绑定时才加。
- `permissionVersion` 与该 Redis 租户授权版本对齐。签发 / 刷新 Access Token 时写入 JWT Claim `permission_version`。
- 受保护业务请求进入业务前：比对 JWT `permission_version` 与 Redis 当前版本。不一致（含 JWT 缺该 Claim）→ **不执行业务**，HTTP **409**，编码 `PERMISSION_VERSION_CHANGED`。
- 下列请求不按版本不一致返回 409，以便前端能拿到新快照并换 Token：`GET /auth/context`、`POST /auth/refresh`（若已提供）、`POST /auth/logout`。
- 权限收回的安全底线是下一次业务请求即拒绝旧权限；不依赖用户手动刷新浏览器。
- 在线会话菜单更新的最大延迟：等到该用户**下一次业务请求**（空闲挂着页面时侧栏可以暂时仍是旧菜单，已确认可接受）。不做 WebSocket 推送，不做定时拉菜单。
- 账号被停用时撤销会话（`SESSION_REVOKED`），不走本条 409。

`homeRoute` 由角色配置、菜单配置还是单独规则决定 **待确认**（登录 PRD §15-13）。`homeRoute` 为空时，进入菜单树中第一个可访问 `page` 节点（登录 PRD §12.9，已确认，此条是前端跳转规则，后端仍须给出可空的 `homeRoute`）。

### 5.7 凭证与日志安全（跨接口）

| 规则 | 来源 |
| --- | --- |
| 全程 HTTPS | 登录 PRD §9.2 |
| 密码只在提交时短暂存在于内存；不写入日志、埋点、URL、缓存或持久化存储 | 登录 PRD §9.2 |
| 服务端使用安全密码哈希，不保存可逆明文 | 登录 PRD §9.2 |
| 响应与错误日志不得返回密码、密码哈希或完整会话凭证 | 登录 PRD §9.2 |
| 登录日志禁止记录账号输入原文之外的敏感凭证；无法识别账号时不记录用户 ID；手机号是否脱敏按系统日志权限 | 登录 PRD §9.4 |
| 前端不得使用 Local Storage 保存密码或长期访问令牌 | 登录 PRD §7.4（前端约束；后端不得在 JSON 中提供可被长期存到 Local Storage 的刷新凭证） |

## 6. 状态流转

### 6.1 用户账号状态（本模块只消费）

沿用用户管理总览 §6：`active` / `disabled`。本模块不修改 `status`。

| 当前状态 | 操作 / 条件 | 是否允许登录 | 业务说明 |
| --- | --- | --- | --- |
| `active` | 密码正确且角色有效 | 是 | 创建会话 |
| `active` | 密码正确且角色无效 / 无角色 | 否 | `ROLE_UNAVAILABLE`，不创建会话 |
| `disabled` | 密码已通过验证 | 否 | `ACCOUNT_DISABLED`，不创建会话 |
| 任意 | 密码未通过 | 否 | `INVALID_CREDENTIALS`，不揭示状态 |

### 6.2 强制改密状态

| 当前 `forcePasswordChange` | 操作 / 条件 | 新值 | 是否允许进入业务系统 |
| --- | --- | --- | --- |
| `true` | 登录认证成功 | 不变 | 否 |
| `true` | 首次改密成功 | `false` | 是（随后拉授权上下文） |
| `false` | 登录认证成功 | 不变 | 是（仍可能无可用菜单） |
| 任意 | 管理员重置密码且打开改密开关 | `true`（由用户管理写入） | 下次登录走改密闸门 |

初始值由用户管理创建 / 重置决定（用户管理总览 §4.2），本模块不在登录接口改写该字段。

### 6.3 会话状态

```text
无会话 ──登录成功──→ 有效会话 ──退出 / 撤销 / 过期──→ 已撤销或已过期
                              └──首次改密成功──→ 新有效会话（旧会话撤销）
```

| 当前状态 | 操作 / 条件 | 新状态 | 是否允许 | 业务说明 |
| --- | --- | --- | --- | --- |
| 无会话 | 登录成功 | 有效会话 | 是 | 含常规或保持登录 |
| 无会话 | 登录失败 | 无会话 | — | 不创建会话 |
| 有效会话 | 退出登录 | 已撤销 | 是 | 刷新凭证一并失效 |
| 有效会话 | 密码重置 / 停用 / 强制下线 / 角色失效 | 已撤销 | 是 | 全部相关会话 |
| 有效会话 | 首次改密成功 | 新有效会话 | 是 | 其他旧会话撤销 |
| 有效会话 | 超过会话或空闲超时 | 已过期 | 是 | 超时时长 **待确认**（§18 P0-10） |
| 已撤销 / 已过期 | 访问受保护 API | — | 否 | `SESSION_REVOKED` 或认证 401（映射 **待确认**，§18 P0-7） |

- 初始状态：无会话。
- 中间状态：有效会话（含「已登录但必须改密」）。
- 终态：已撤销、已过期（可再次登录回到有效会话）。

### 6.4 验证码挑战状态

| 当前状态 | 操作 / 条件 | 新状态 | 是否允许用于登录 |
| --- | --- | --- | --- |
| 未签发 | 获取验证码 | 已签发（未使用，未过期） | 是 |
| 已签发 | 60 秒到期 | 已失效 | 否 → `CAPTCHA_INVALID` |
| 已签发 | 登录使用一次 | 已使用 | 否（不可再次使用） |
| 已签发 | 登录使用但码错误 | 已失效（须刷新） | 否 → `CAPTCHA_INVALID` |

### 7.3 数据变化汇总

| 操作 | 新增什么 | 修改什么 | 删除什么 | 是否必须原子 |
| --- | --- | --- | --- | --- |
| 登录成功 | 会话（及可选刷新凭证）；成功审计 | 清除该账号失败计数 | — | 会话创建与成功日志必须一致；不得出现已发凭证但无成功日志或相反（见登录 API Spec §10） |
| 登录失败 | 失败审计；可能累加失败计数 | 可能进入需验证码或锁定 | — | 审计与计数不得包含密码 |
| 获取验证码 | 一条验证码挑战 | — | — | 否（只读业务结果；存储新挑战） |
| 首次改密成功 | 新会话（及按规则的刷新凭证）；审计 | 密码凭据、`forcePasswordChange=false` | 撤销其他旧会话 / 刷新凭证 | 是：密码 + 改密开关 + 旧会话撤销 + 新会话必须一致 |
| 获取授权上下文 | 可能写授权异常日志（如 `NO_AVAILABLE_MENU`） | — | — | 否（不改变账号 / 会话数据） |
| 退出登录 | 撤销结果审计 | 当前会话及刷新凭证改为已撤销 | — | 是：会话与刷新凭证一并失效 |
| 外部触发的全量撤销 | 撤销审计 | 该用户全部会话 / 刷新凭证 | — | 是 |

各操作的详细流程以对应 API Spec 第 5 / 6 节为准。

## 8. 权限

### 8.1 功能权限

登录页相关接口**不使用** `system:user:*` 等业务权限码。

| 接口 | 谁可以调用 |
| --- | --- |
| 登录、获取验证码 | 匿名调用者（仍受风控与限流约束） |
| 首次改密 | 持有**有效且对应强制改密未完成用户**的会话（精确判定 **待确认**，§18 P1-1） |
| 授权上下文 | 持有有效会话的用户；用户须为 `active` 且角色有效，否则失败（登录 PRD §12.2） |
| 退出登录 | 持有有效会话的用户 |

业务 API 的功能权限与数据权限仍由认证模块 + 各业务模块按 JWT / 授权结果校验（登录 PRD §12.1、§12.7，已确认）。前端隐藏按钮不能替代后端校验。

### 8.2 数据权限

本模块登录接口不按组织范围过滤「能否登录」。数据范围只进入授权上下文的 `dataScope` 摘要，以及写入 JWT 的 `manageable_department_ids` / `manage:all`（如何从角色数据范围算出 JWT 组织范围 **待确认**，§18 P0-8）。

### 8.3 租户

所有用户查询必须限定租户（用户管理总览 §7.2）。登录请求如何得到 `tenantId` **待确认**（§18 P0-5）。不得接受客户端在 Body / Header 中自行指定并覆盖已解析租户（与认证 Spec 「不得用请求参数覆盖 JWT 租户」同一方向的约束；登录阶段尚无 JWT）。

## 9. 事务与数据一致性

单个接口内部的原子性写在该接口 API Spec 第 10 节。本章只列跨接口、系统级要求。

| 关系 | 必须保证 |
| --- | --- |
| 登录成功 ↔ 会话 / 刷新凭证 | 认证成功则会话存在且可被后续请求识别；失败则不留下可用会话 |
| 首次改密 ↔ 旧会话 | 新密码生效时，其他旧会话不可继续使用 |
| 用户管理重置密码 / 停用 / 角色失效 ↔ 本模块会话 | 触发后相关会话立即不可用（登录 PRD §7.4、§9.2） |
| 授权上下文 ↔ 角色权限 | 菜单、`permissionCodes`、写入 JWT 的 `scope` 必须来自同一套后端权限计算，不允许前端或登录接口另算一套（登录 PRD §12.1） |
| `permissionVersion` ↔ 权限缓存 | 角色权限、用户角色、账号状态变更后更新版本并使旧权限缓存失效（登录 PRD §12.11） |
| JWT Claims ↔ 认证模块 | 签发的 `sub` / `tenant_id` 必须合法 UUID；写入 `permission_version`；`scope` 与 `manageable_department_ids` 的写入规则须与认证 Spec §2.2 可消费 |

任一步失败不得出现：密码已改但旧会话仍有效；会话已发但用户仍被锁定计数错误阻断下一次合法登录；授权上下文与 JWT 权限码长期不一致。降级策略 **待确认**。

## 10. 并发与幂等

### 10.1 并发风险与必须保证的结果

| 场景 | 可能问题 | 系统必须保证 |
| --- | --- | --- |
| 同一账号并发多次登录 | 超出允许设备数；或互相覆盖会话 | 最终会话集合符合「同时登录设备数」规则；该数量 **待确认**（§18 P0-10）时不得自行发明「只保留最后一次」或「无限设备」作为已确认规则 |
| 登录失败与登录成功并发 | 成功后失败计数未清或锁定误伤 | 成功必须清除该账号连续失败计数（登录 PRD §9.1） |
| 改密与其他设备使用旧密码 | 旧会话继续访问 | 改密成功后其他旧会话立即不可用 |
| 停用 / 重置密码与在途请求 | 已撤销会话仍被接受 | 撤销后受保护 API 不得继续授权 |
| 并发拉取验证码 | 多个 token 同时有效 | **待确认** 是否仅最新 token 有效 |

不指定 Redis 锁 / 数据库锁等实现，除非项目另有明确技术约束。

### 10.2 幂等与重复提交

| 接口 | 重复提交 |
| --- | --- |
| 登录 | 前端提交期间禁止重复发送（登录 PRD §7.3）；后端仍须限流。每次成功登录是否创建新会话 **待确认**（与设备数相关） |
| 获取验证码 | 每次签发新挑战，旧挑战是否立即失效 **待确认** |
| 首次改密 | 成功后 `forcePasswordChange` 已为 `false`；重复提交是否按普通改密拒绝 **待确认** |
| 授权上下文 | 只读，可安全重试 |
| 退出登录 | 会话已撤销后的重复退出：应视为会话已不存在；HTTP / 错误码 **待确认**（§18 P1-3） |

| 参数异常（缺失 / 超长 / 类型） | 拒绝认证，不创建会话 | 设计建议 HTTP 400；是否仍返回 `requiresCaptcha` **待确认** |

| 并发异常 | 见 §10；不得产生未撤销的旧会话与已生效新密码并存 | — |

### 11.2 错误码总表（唯一注册表）

登录 PRD 已给出稳定英文编码，本表**原样登记**，不改写为 `LOGIN_` 前缀（以免与前端约定不一致）。项目其他模块使用 `USER_` / `DEPARTMENT_` 前缀；是否统一全局注册表 **待确认**。

| 错误码 | 场景 | 含义 | HTTP |
| --- | --- | --- | --- |
| `INVALID_CREDENTIALS` | 账号或密码错误（含未通过密码验证时的不存在账号） | 账号或密码错误 | **待确认**；设计建议 200 + `data.success=false`（§4.3） |
| `ACCOUNT_DISABLED` | 密码已通过且账号 `disabled` | 账号已停用 | 同上 |
| `ROLE_UNAVAILABLE` | 角色已停用或无有效角色 | 账号暂时无法访问系统 | 同上 |

| `ACCOUNT_TEMP_LOCKED` | 账号临时锁定 | 账号临时锁定 | 同上 |
| `RATE_LIMITED` | 请求过于频繁 | 操作过于频繁 | **待确认**（200 vs 429） |
| `SYSTEM_UNAVAILABLE` | 系统不可用 / 服务异常 | 系统暂时不可用 | **待确认**；设计建议 500 |
| `AUTH_CONTEXT_LOAD_FAILED` | 授权上下文加载失败 | 授权上下文加载失败 | **待确认** |
| `NO_AVAILABLE_MENU` | 认证成功但菜单树为空 | 无可用菜单 | **待确认** |
| `ROUTE_FORBIDDEN` | 当前路由无权限 | 当前路由无权限 | 主要由前端 + 业务路由消费；后端业务 API 对应 403 **待确认** |
| `ACTION_FORBIDDEN` | 当前操作无权限 | 当前操作无权限 | 业务 API 功能权限不足；与既有 403 码关系 **待确认** |

## 14. 缓存

登录 PRD 要求：

- 权限缓存在权限变更后及时失效，不允许旧会话继续使用已撤销权限（登录 PRD §9.3、§12.11）。
- 前端授权上下文仅在当前会话内缓存，不使用长期 Local Storage（前端约束）。

需求**没有**要求为本模块增加登录用户读缓存。本 Spec **不新增**账号数据缓存方案。

`permissionVersion` 与「租户授权版本」Redis 机制已对齐（§5.6）：同一 key `chengke:authorization:version:{tenantId}`。签发 JWT 时写入 `permission_version`；业务请求比对不一致则 HTTP 409 `PERMISSION_VERSION_CHANGED`，不执行业务。当前代码尚未做比对，实现须补上，不得把「Token 过期前旧权限仍可用」当成已交付。

若实现阶段引入验证码 / 会话 / 失败计数缓存，必须先回到本文档补充读写失效与不一致容忍度。

## 15. 横切验收标准

每个 API 自己的验收标准写在该 API Spec 的第 11 节。

### 业务规则

- [ ] 用户名或 11 位手机号 + 正确密码，在账号正常且角色有效时可登录。
- [ ] 账号不存在与密码错误均为 `INVALID_CREDENTIALS`，不泄露账号是否存在。
- [ ] 密码正确但停用 → `ACCOUNT_DISABLED`；角色无效 → `ROLE_UNAVAILABLE`，均不创建会话。
- [ ] `forcePasswordChange=true` 时不得进入业务系统。
- [ ] 保持登录不把密码或长期访问令牌返回为可被 Local Storage 保存的 JSON 字段。
- [ ] 菜单、权限码、数据范围以后端授权上下文为准。

### 数据 / 数据库

- [ ] 登录成功有会话与成功审计；失败无可用会话且有失败分类审计。
- [ ] 审计不含密码、验证码、完整凭证。
- [ ] 首次改密后旧会话不可用、`forcePasswordChange=false`、新密码生效。

### 状态

- [ ] 用户 `active`/`disabled` 与改密开关流转符合 §6。
- [ ] 会话撤销后受保护 API 不可继续访问。

### 权限

- [ ] 登录 / 验证码匿名可访问；改密 / 上下文 / 退出需要有效会话。
- [ ] 超级管理员也通过统一授权计算，无前端「全部菜单」后门。

### 事务

- [ ] 改密的密码、开关、旧会话撤销、新会话无部分成功。
- [ ] 登录失败不产生有效会话。

### 并发 / 幂等

- [ ] 登录成功清除该账号连续失败计数。
- [ ] 撤销与在途请求的最终结果是已撤销会话不能访问。

### 异常

- [ ] §11.3 登录错误枚举均可按场景出现，且前端可只依赖编码。
- [ ] 验证码一次一用、过期失效。
- [ ] 系统异常不返回内部堆栈。

| 现状缺口 | 角色表、菜单表、完整数据范围枚举未实现 | 登录角色校验与授权上下文阻塞 | 待确认（§18 P0-6） |
