## 1. 职责与非职责

### 1.1 当前职责

`LoginForm` 负责：

- 渲染账号、密码和登录按钮。
- 使用 React Hook Form 管理字段值、字段错误和提交事件。
- 使用 `loginSchema` 和 Zod resolver 完成客户端校验与账号规范化。
- 展示页面传入的登录通用错误。
- 管理密码显示/隐藏的局部交互状态。
- 根据 `isSubmitting` 禁止重复提交并展示按钮加载状态。
- 把通过校验的 `LoginValues` 交给 `onSubmit`，不自行处理认证流程。

### 1.2 非职责

`LoginForm` 不负责：

- 发起登录或授权上下文接口请求。
- 写入 Access Token、Redux、缓存或浏览器存储。
- 执行登录成功后的路由跳转。
- 计算菜单、页面权限、按钮权限或数据范围。
- 校验真实账号、密码、账号状态、角色、租户或风控策略；后端必须重新校验。
- 决定 Refresh Token Cookie、保持登录有效期或会话撤销策略。

## 2. Props、回调与 children

`LoginForm` 不接收 children。

| 名称           | 类型                         | 必填 | 默认值      | 含义                                                         |
| -------------- | ---------------------------- | ---- | ----------- | ------------------------------------------------------------ |
| `errorMessage` | `string \| null`             | 否   | `undefined` | 页面级登录失败消息；有值时在表单顶部使用 `role="alert"` 展示 |
| `isSubmitting` | `boolean`                    | 是   | 无          | 登录流程是否进行中；控制提交按钮禁用和加载文案               |
| `onSubmit`     | `SubmitHandler<LoginValues>` | 是   | 无          | 接收已通过 Zod 校验并完成规范化的账号密码；组件不处理返回值  |

当前 `onSubmit` 数据结构：

```ts
interface LoginValues {
  account: string;
  password: string;
}
```

组件不会把原始未校验表单值传给父页面。

## 3. 状态与数据流

### 3.1 状态归属

| 状态           | 所有者                         | 初始值    | 用途                                           |
| -------------- | ------------------------------ | --------- | ---------------------------------------------- |
| `showPassword` | `LoginForm` 本地 state         | `false`   | 决定密码输入框使用 `password` 还是 `text` 类型 |
| `account`      | React Hook Form                | 空字符串  | 保存账号输入，提交时由 schema trim             |
| `password`     | React Hook Form                | 空字符串  | 保存当前密码输入；schema 不执行 trim           |
| `errors`       | React Hook Form + Zod resolver | 空        | 渲染账号和密码字段错误                         |
| `isSubmitting` | 父页面                         | 必填 Prop | 禁用提交按钮，防止用户重复点击                 |
| `errorMessage` | 父页面                         | 可选 Prop | 展示接口或响应解析失败                         |

密码只在表单和提交调用所需的内存状态中存在，不得写入 Redux DevTools、URL、日志、埋点、Query 缓存或持久化存储。

### 3.2 提交流程

1. 原生 `<form>` 接收点击提交按钮或字段内 Enter 提交。
2. React Hook Form 调用 Zod resolver 校验当前字段。
3. 校验失败时更新 `errors`，不调用父级 `onSubmit`。
4. 校验成功时，账号已去除首尾空格，密码保持用户原始输入。
5. 调用父页面传入的 `onSubmit(values)`。
6. 实际登录请求、Token、Redux 和跳转由 `LoginPage` 编排。

## 4. 当前字段与校验契约

`src/features/auth/schemas/login.schema.ts` 是当前客户端字段校验的唯一来源。

| 字段       | 当前规则                  | 规范化                     | 自动填充           |
| ---------- | ------------------------- | -------------------------- | ------------------ |
| `account`  | trim 后必填，最多 64 字符 | 去除首尾空格，不改变大小写 | `username`         |
| `password` | 8–128 字符                | 不 trim，不自动格式化      | `current-password` |

当前字段错误：

- 空账号：`请输入账号`。
- 密码不足 8 字符：`密码至少需要 8 个字符`。
- 超长字段使用 schema 定义的对应提示。

客户端校验只提供即时反馈。后端仍须校验字段长度、账号密码、账号状态、角色、租户、验证码、限流及会话安全。

## 5. 副作用与安全边界

`LoginForm` 当前没有接口、路由、Redux、TanStack Query、Token、缓存、Web Storage、日志或埋点副作用。

它唯一的组件边界输出是调用 `onSubmit`。安全要求：

- 不记录或持久化账号密码。
- 不阻止密码粘贴和密码管理器填充。
- 不通过中文错误消息决定认证安全逻辑。
- 表单禁用只能阻止前端重复操作，后端仍须进行幂等、限流和风控处理。
- 未来 `rememberMe` 只能表达会话申请，不能让前端保存明文密码或长期 Access Token。

## 6. 组件状态与交互

### 6.1 当前实现

| 场景       | 当前表现                                                            |
| ---------- | ------------------------------------------------------------------- |
| 默认       | 账号、密码为空；密码使用掩码；登录按钮可用                          |
| 字段错误   | 错误文字显示在对应字段下方，并设置 `aria-invalid=true`              |
| 页面级错误 | 表单顶部展示 `errorMessage`，容器使用 `role="alert"`                |
| 密码显隐   | 图标按钮切换输入类型；`aria-label` 在“显示密码”和“隐藏密码”之间切换 |
| 提交中     | 登录按钮 disabled，显示旋转图标和“正在登录…”                        |
| Enter 提交 | 由原生 form 和 React Hook Form 提交流程支持                         |
| 忘记密码   | 按钮可见，但没有事件、对话框、链接或其他副作用                      |

### 6.2 目标设计

- 首次进入页面时账号字段获得焦点；首个校验错误出现时焦点移动到该字段。
- 字段错误使用稳定 ID，通过 `aria-describedby` 与输入框建立程序化关联。
- 密码显隐切换后保持输入焦点和光标位置。
- 输入框覆盖默认、悬停、聚焦、已填写、禁用、错误和浏览器自动填充状态。
- 密码显隐按钮在桌面和触屏环境满足足够点击热区，并提供 Tooltip 和可访问名称。
- 忘记密码按 PRD 打开“无法登录？”对话框；未接入前不应表现为已完成功能。
- 风控要求时动态加入验证码字段；阈值、令牌和校验结果全部以后端为准。
- 支持 `rememberMe` 字段，但其副作用由后端 Refresh Cookie 策略实现。

## 7. 当前实现与目标设计差异

| 项目         | 当前实现                                                    | 目标设计 / 处理要求                                                 |
| ------------ | ----------------------------------------------------------- | ------------------------------------------------------------------- |
| 账号最大长度 | 64 字符                                                     | PRD 为 32 字符；实现前需与后端 OpenAPI/Bean Validation 统一         |
| 密码最大长度 | 128 字符                                                    | PRD 为 32 字符；不得仅在前端单方面修改                              |
| 手机号格式   | 只做通用字符串校验                                          | PRD 接受用户名或 11 位大陆手机号；是否校验格式需与账号规则统一      |
| 保持登录     | 无字段                                                      | 增加 `rememberMe`，默认未选中，并由后端决定会话时长                 |
| 验证码       | 无字段                                                      | 仅在后端风控要求时动态展示                                          |
| 忘记密码     | 无事件按钮                                                  | 打开联系管理员说明对话框，复用管理员联系配置                        |
| 错误关联     | 只有 `aria-invalid` 和可见文字                              | 使用 `aria-describedby` 关联字段与错误信息                          |
| 错误焦点     | 未显式管理                                                  | 提交失败后聚焦首个错误字段                                          |
| 密码光标     | 未验证显隐切换后的位置                                      | 切换后保持焦点和光标位置                                            |
| 控件高度     | 共享 Input/Button 当前为 40px                               | 登录控件目标为 44px，应通过共享组件的 auth 尺寸实现                 |
| 字体         | 依赖全局继承；目前只对 `button, input` 声明 `font: inherit` | 所有表单控件统一继承全局字体，覆盖自动填充和未来 select/textarea    |
| 触屏与软键盘 | 没有组件级验收                                              | 保证 320px 起无溢出、输入字号和热区合规、软键盘下可滚动访问提交按钮 |

## 8. 全局 CSS 与字体约束

`LoginForm` 不拥有独立字体。字体一致性由 `src/app/styles/index.css` 和共享基础组件负责。

当前全局样式在 `:root` 定义统一字体栈，并让 `button`、`input` 使用 `font: inherit`。后续实现和验收要求：

- Label、Input、Button、错误文字、占位文字和浏览器自动填充值使用同一全局字体栈。
- 不在 `LoginForm`、`Input` 或 `Button` 中单独声明页面专用中文字体。
- 全局继承规则应覆盖 `button`、`input`、`select` 和 `textarea`，保证未来保持登录、验证码或其他表单控件不会出现字体分叉。
- 浏览器自动填充和密码管理器注入内容时，字体、字号、行高、文字颜色和控件高度应保持稳定。
- 若系统字体不可用，应按设计系统顺序安全回退，不因字体加载失败造成布局不可操作。
- 字体问题应在全局 CSS 或共享基础组件修复；页面组件不得重复覆盖。

## 9. 无障碍与响应式

### 9.1 当前实现

- 使用语义化 `<form>`，支持键盘 Enter 提交。
- 账号和密码具有可见 `<label>`，并通过 `htmlFor/id` 关联。
- 前缀图标使用 `aria-hidden="true"`。
- 密码显隐按钮提供动态 `aria-label`。
- 页面级错误使用 `role="alert"`。
- 字段错误设置 `aria-invalid`，但没有 `aria-describedby`。
- 提交按钮使用原生 `disabled`。

### 9.2 目标验收

- 所有功能仅使用键盘即可完成，焦点指示清晰可见。
- 错误不仅依赖颜色，并能被辅助技术关联和播报。
- 密码显隐按钮具有 Tooltip、动态名称以及桌面/触屏足够热区。
- 浏览器缩放、320px 窄屏和移动软键盘下字段与按钮不被裁切。
- 账号输入在移动端保持合适的输入模式；密码允许粘贴和密码管理器填充。
- 动画或加载图标在 `prefers-reduced-motion` 下不影响提交状态理解。
- 字段 Label、输入内容、占位、错误和按钮在所有断点保持字体一致。

## 11. 依赖与已知限制

### 11.1 直接依赖

- React Hook Form 和 `SubmitHandler`。
- `@hookform/resolvers/zod` 与 `loginSchema`。
- 共享 `Button`、`Input`。
- Lucide 的账号、密码、显隐和加载图标。
- 全局 CSS 字体、颜色、焦点和减少动效规则。

### 11.2 已知限制

- schema 字段长度与 PRD 不一致，尚未与后端契约完成统一。
- 未实现保持登录、风险验证码和忘记密码对话框。
- 字段错误缺少 `aria-describedby`，首次错误焦点行为没有验证。
- 密码显隐的焦点、光标保持和触屏热区缺少测试。
- 登录 Input/Button 当前为 40px，与设计系统 auth 控件 44px 目标不一致。
- 字体一致性依赖全局规则；未来新增控件时需把 `select/textarea` 纳入统一继承。
