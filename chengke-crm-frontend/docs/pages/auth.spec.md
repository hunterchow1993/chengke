## 1. 功能目标

- **页面解决什么问题**：让后台使用者用账号密码进入系统；同一标签页内用访问令牌维持会话（刷新浏览器后仍可恢复）；没有任何可访问功能时给出明确说明并可退出；他人调整本账号权限后，用户下一次业务请求能拿到新菜单，而不是继续使用旧授权。
- **面向什么用户**：持有本系统账号、需要进入管理端的后台使用者。
- **用户为什么需要**：没有登录无法使用业务功能；刷新浏览器后 JavaScript 内存会丢，需要用本标签页保存的访问令牌静默恢复；无菜单账号不能看到空白后台；权限被改后不能继续操作已收回的页面。
- **用户最终要完成的业务目标**：
  - 用账号密码登录，进入被授权的首页或「暂无可用功能」页。
  - 同一浏览器标签页内继续使用当前访问令牌；刷新页面后仍保持已登录，用该令牌请求授权上下文（接口仍带 `Authorization: Bearer`，不使用 Cookie）。
  - 需要时退出，回到登录页。
- **页面最终产生什么结果**：创建或恢复浏览器内会话与授权快照；退出时撤销当前会话并清除本机授权与业务缓存。本功能不写入用户、角色、部门等业务主数据。

登录页不使用管理端侧栏外壳。未认证用户不能看到管理端外壳。

## 2. 业务对象 / 数据模型

| 业务对象 | 说明 | 关键属性 | 对象关系 |
| --- | --- | --- | --- |
| 登录凭据 | 用户在登录页提交的身份证明 | 账号、密码 | 提交给登录接口；前端不持久化密码 |
| 访问凭证 | 短期访问令牌 | 令牌字符串 | 登录或刷新成功后存在于当前页面进程内存，并写入本标签页会话存储；请求受保护接口时携带 `Authorization: Bearer` |
| 刷新凭证 | 用于换取新访问凭证 | 前端不可读独立刷新串 | 本期不单独投递；换票时携带当前 `Authorization: Bearer` 访问令牌（已确认） |
| 会话 | 当前浏览器是否已认证 | 未开始 / 恢复中 / 已认证 / 匿名 | 决定能否进入 `/app` |
| 用户 | 当前操作者摘要 | `id`、显示名称、头像地址（可空） | 属于租户 |
| 租户 / 当前组织 | 授权上下文中的组织摘要 | `id`、名称 | 用户隶属于该租户 |
| 授权上下文 | 后端算出的菜单与权限快照 | 用户、租户、菜单树、权限码、数据范围摘要、敏感字段权限、过期时间、授权首页、权限版本（可选） | 登录成功后、会话恢复时、权限版本变更恢复后写入；前端不自行计算权限 |
| 菜单树 | 后端按权限筛选后的导航 | 节点 `id`、展示名、路由键（可空）、图标键（可空）、子节点 | 空数组表示没有任何可访问功能 |
| 授权首页 | 后端指定的登录后站内路径 | 必须以 `/app` 开头，且不能是协议相对外部地址 | 菜单非空时作为跳转目标 |
| 权限版本 | 租户授权是否已相对当前访问凭证发生变化 | 稳定业务码 `PERMISSION_VERSION_CHANGED`；HTTP 409 | 业务请求发现不一致时触发恢复，不执行原业务 |

对象依赖：

- 登录凭据 → 访问凭证 + 刷新凭证。
- 访问凭证（必要时先刷新）→ 授权上下文。
- 授权上下文 → 会话已认证、用户、租户、菜单、授权首页。
- 菜单为空 → 「暂无可用功能」页，不进入带侧栏的管理端外壳。
- 菜单非空 → 管理端外壳（见布局 Spec）。

前端不得按角色名或用户类型补默认菜单。角色摘要若后端返回，当前登录页与空菜单页均不展示。

## 3. 页面结构

本功能包含两张独立全屏页，以及进入 `/app` 前的会话恢复画面。管理端侧栏与顶栏不属于本 Spec（见布局 Spec）。

### 3.1 登录页（路由 `/login`）

| 区域 | 展示什么 | 用户可以做什么 | 显示 / 隐藏 / 不可用 |
| --- | --- | --- | --- |
| 左侧品牌区 | 品牌名「澄客 CRM」、主标题「让每一次客户连接，沉淀为清晰增长。」、能力说明三条、版权「© 2026 澄客 CRM · 企业客户经营管理平台」、装饰插图 | 只读 | 当前实现始终展示。窄屏如何改版 **待确认**（登录页响应式设计尚未作为本 Spec 已交付项） |
| 右侧顶部「遇到问题」 | 文案「遇到问题」+ 按钮「联系管理员」 | 当前实现：点击无任何效果 | 始终展示 |
| 右侧标题区 | 英文辅助文案 `Secure workspace`、标题「欢迎回来」、说明「登录后将根据后端授权加载你的菜单、操作权限与数据范围。」 | 只读 | 始终展示 |
| 登录表单 | 账号、密码、登录按钮；可选顶部通用错误 | 输入、提交、切换密码显隐 | 会话已认证时整页不展示，直接离开本页 |
| 「忘记密码？」 | 密码标签右侧文字按钮 | 当前实现：点击无任何效果 | 始终展示 |
| 底部安全说明 | 「连接受安全策略保护」；按钮「隐私与安全」 | 当前实现：点击无任何效果 | 始终展示 |

根路径 `/`：进入后替换为 `/login`。

### 3.2 「暂无可用功能」页

已登录且授权菜单为空时展示。不展示管理端侧栏、顶栏，不展示「401」字样。

| 区域 | 展示什么 | 用户可以做什么 | 显示条件 |
| --- | --- | --- | --- |
| 标题 | 「暂无可用功能」 | 只读 | 已认证且 `menus` 为空 |
| 中间提示 | 「当前账号尚未分配可访问功能，请联系管理员。」位于页面正中 | 只做说明，不可点击，不打开联系渠道，不复用登录页「联系管理员」入口 | 同上 |
| 操作 | 「退出登录」 | 先二次确认，确认且接口成功后进入登录页 | 同上 |

### 3.3 会话恢复画面

进入 `/app` 且会话尚未判定为已认证或匿名时展示。

| 区域 | 展示什么 | 用户可以做什么 | 显示条件 |
| --- | --- | --- | --- |
| 全屏提示 | 「正在恢复安全会话…」 | 不可操作 | 会话状态不是已认证、也不是匿名 |

超过多久改为骨架屏 **待确认**。

### 3.4 不在本功能页面内、但由本功能触发的界面

- 登录成功且菜单非空 → 进入管理端外壳 + 授权首页。
- 已认证用户再次打开 `/login` → 不停留在登录页，替换进入当前授权首页；若菜单为空，随后落到「暂无可用功能」页。

## 4. 页面数据

| 数据 | 类型 | 来源 | 用途 | 是否影响页面行为 |
| --- | --- | --- | --- | --- |
| 账号 | 字符串 | 用户输入 | 登录请求 | 客户端校验失败则不能提交 |
| 密码 | 字符串 | 用户输入 | 登录请求 | 同上 |
| 密码是否可见 | 是 / 否 | 用户点击显隐 | 仅改变输入框展示，不改变密码值 | 否（不影响提交） |
| 是否正在提交登录 | 是 / 否 | 登录流程进行中 | 锁定登录按钮、显示「正在登录…」 | 是 |
| 登录通用错误 | 字符串或空 | 登录或授权上下文失败 | 表单顶部展示 | 是 |
| 会话状态 | 未开始 / 恢复中 / 已认证 / 匿名 | 会话恢复或登录/退出结果 | 决定登录页、恢复画面、空菜单页、管理端外壳 | 是 |
| 用户摘要 | 对象或空 | 授权上下文 | 布局展示姓名；本功能页面不展示 | 间接（退出后清空） |
| 租户摘要 | 对象或空 | 授权上下文 | 布局展示组织名；本功能页面不展示 | 间接 |
| 菜单树 | 数组 | 授权上下文 | 空则独立提示页；非空进入外壳 | 是 |
| 权限码 / 数据范围 / 敏感字段权限 | 字符串数组 | 授权上下文 | 供后续页面鉴权展示；登录页不使用 | 权限码不决定空菜单页（空菜单只看 `menus`） |
| 授权首页 | 站内路径 | 授权上下文；未加载时当前默认 `/app/dashboard` | 登录成功或已认证回访登录页时的跳转目标 | 是 |
| 过期时间 | 带时区的日期时间 | 授权上下文 | 当前实现写入会话状态，页面不展示 | 当前不影响本功能页面展示 |
| 权限版本 | 字符串，可选 | 授权上下文 | 当前实现可接收；本功能页面不展示、不本地比对 | 业务接口 409 时触发恢复，不依赖本字段展示 |
| 访问凭证 | 字符串或空 | 登录 / 刷新接口 | 后续请求鉴权 | 是（丢失则需刷新或重新登录） |
| 原目标路径 | 字符串 | 未登录访问 `/app` 时会话边界带回 | 当前实现写入跳转状态，登录页不读取 | 当前不影响登录后跳转 |
| 路由 | `/login`、`/app/*` | 浏览器地址 | 决定展示哪一页 | 是 |

数据从哪里来 → 存在哪里 → 用于什么：

- 账号密码只存在登录表单提交过程，不写入跨页会话快照，不写入 LocalStorage / SessionStorage / URL。
- 访问凭证存在当前页面进程内存，并写入本标签页会话存储；关闭标签页或退出后清除。不写入 LocalStorage。
- 授权上下文存在跨页会话快照，供登录后跳转、空菜单判断、布局菜单使用。
- 刷新凭证不单独投递给前端；换票使用当前访问令牌的 Bearer 头。

## 5. 页面状态

### 5.1 UI 状态

| 状态 | 可选值 | 何时进入 | 页面结果 |
| --- | --- | --- | --- |
| 登录提交中 | 是 / 否 | 通过客户端校验并开始登录请求时为是；成功或失败结束后为否 | 是：登录按钮不可用，文案为「正在登录…」 |
| 登录通用错误 | 有文案 / 无 | 新一次提交开始时清空；失败时写入 | 有文案时在表单顶部以警示区域展示 |
| 密码可见 | 是 / 否 | 点击显隐切换；默认否 | 只改变密码是否以明文显示 |
| 字段错误 | 账号错误 / 密码错误 / 无 | 提交时客户端校验失败 | 对应字段下方展示错误文案 |

### 5.2 业务状态

| 状态 | 可选值 | 何时进入 | 页面结果 |
| --- | --- | --- | --- |
| 会话 | 未开始 | 应用刚打开、尚未判定 | 访问 `/app` 时先进入恢复中 |
| 会话 | 恢复中 | 开始请求授权上下文 | 显示「正在恢复安全会话…」 |
| 会话 | 已认证 | 登录成功并写入上下文，或恢复成功 | 可进入 `/app`；若菜单空则空菜单页 |
| 会话 | 匿名 | 恢复失败、退出完成、或恢复流程判定无有效会话 | 访问 `/app` 时进入登录页 |
| 菜单是否为空 | 空 / 非空 | 以最新授权上下文 `menus` 为准 | 空：独立全屏页；非空：管理端外壳 |
| 权限版本是否需恢复 | 是 / 否 | 业务请求返回 HTTP 409 且编码 `PERMISSION_VERSION_CHANGED` | 换取新访问凭证、重拉上下文、再决定是否重试原请求 |

依赖关系：

- 已认证 + 菜单空 → 空菜单页（优先于管理端外壳）。
- 匿名 → 不能看到空菜单页，只能看到登录页。
- 已认证 + 打开 `/login` → 离开登录页，去授权首页（菜单空则落到空菜单页）。

## 6. 用户行为

### 6.1 打开根路径

前置条件：无。

用户操作：访问 `/`。

系统行为：用替换方式进入 `/login`。

页面结果：看到登录页。

### 6.2 打开登录页（未认证）

前置条件：会话不是已认证。

用户操作：访问 `/login`。

系统行为：展示登录页。不自动提交。

页面结果：可输入账号密码。

### 6.3 已认证时打开登录页

前置条件：会话为已认证。

用户操作：访问 `/login`。

系统行为：不展示登录表单；用替换方式进入当前授权首页。

页面结果：菜单非空则进入管理端；菜单空则进入「暂无可用功能」页。

### 6.4 输入账号 / 密码

前置条件：登录页可见且未在提交中。

用户操作：在对应输入框输入。

系统行为：更新表单值。账号提交时去除首尾空格；密码不去除内部或首尾空格。

页面结果：字段内容变化。提交中时输入是否仍可改 **待确认**（当前实现未禁止输入，只禁用登录按钮）。

### 6.5 切换密码显隐

前置条件：登录页可见。

用户操作：点击密码框右侧显隐按钮。

系统行为：在「隐藏」与「显示」之间切换；不修改密码值。

页面结果：按钮可访问名称在「显示密码」与「隐藏密码」之间切换。

### 6.6 点击「忘记密码？」「联系管理员」「隐私与安全」

前置条件：登录页可见。

用户操作：点击对应文字按钮。

系统行为：当前实现无跳转、无弹窗、无请求。

页面结果：页面不变。产品目标行为 **待确认**。

### 6.7 提交登录（客户端校验失败）

前置条件：登录页可见且未在提交中。

用户操作：点击「登录」或在表单内提交。

系统行为：不调用登录接口。

页面结果：

- 账号为空（去空格后仍空）→ 「请输入账号」
- 账号超过 32 个字符 → 「账号不能超过 32 个字符」
- 密码少于 8 个字符 → 「密码至少需要 8 个字符」
- 密码超过 32 个字符 → 「密码不能超过 32 个字符」

长度规则已与登录 PRD §6.1 对齐：**已确认**。账号去除首尾空格后非空、最大 32 个字符、不自动改变字母大小写。密码 8–32 个字符，不去除用户主动输入的内部空格，不进行自动格式化。

### 6.8 提交登录（客户端校验通过）

前置条件：字段通过客户端校验。

用户操作：提交登录。

系统行为：

1. 进入提交中，清空通用错误。
2. 请求登录接口，Body 为规范化后的账号、密码（本次不发送 `rememberMe`、验证码字段）。
3. 先看 HTTP：参数校验失败为 400；无响应按网络异常。业务成败都在 HTTP 200 的 `data` 里判断（见 §12.1）。
4. `data.success=false` → 不写入访问凭证、不请求授权上下文；按 `errorCode` 展示文案（§12.1）。`INVALID_CREDENTIALS`、`ACCOUNT_DISABLED` 清空密码、保留账号（登录 PRD §8.3）。
5. `data.success=true` 且 `forcePasswordChange=true` → 不请求授权上下文、不进入 `/app`。改密页未交付；登录页展示「请先完成密码修改」（与后端拒绝未改密访问的现有文案一致）。正式改密页 **待确认**。
6. `data.success=true` 且不必改密 → 将 `accessToken` 写入当前页面进程内存及本标签页会话存储 → 请求授权上下文。
7. 授权上下文校验通过 → 写入会话与权限快照 → 用替换方式进入 `authorizedHome`。
8. 授权上下文失败 → 不跳转；展示错误；结束提交中。访问凭证若已写入、上下文失败时是否清除：**待确认**。

页面结果：

- 成功且不必改密、菜单非空：离开登录页，进入管理端授权首页。
- 成功且不必改密、菜单为空：离开登录页，进入 `/app` 后落到「暂无可用功能」页。
- 成功但必须先改密：停留登录页，不进入业务系统。
- 业务失败 / HTTP 失败：停留登录页；顶部展示对应文案。

### 6.9 刷新或直接打开 `/app`（仍有访问令牌）

前置条件：当前页面进程内存或本标签页会话存储中仍有访问令牌（含同一标签页硬刷新）。

用户操作：站内路由切换到 `/app` 及其子路径，或刷新当前管理端页面。

系统行为：

1. 进入恢复中，展示「正在恢复安全会话…」。
2. 请求授权上下文（`Authorization: Bearer`）。
3. 若该请求为 HTTP 401：用同一访问令牌调用刷新接口一次，再请求一次授权上下文。
4. 成功 → 已认证；按菜单空/非空分支。
5. 非 401 失败，或刷新后再失败 → 匿名，进入登录页，并带上原路径（登录页当前不使用该路径）。

页面结果：恢复成功则进入外壳或空菜单页；失败则登录页。

### 6.10 打开 `/app`（无访问令牌）

前置条件：内存与本标签页会话存储都没有访问令牌（未登录、已退出、或新开/关闭后的标签页）。不使用 Cookie 恢复。

用户操作：访问 `/app`。

系统行为：恢复失败 → 匿名 → 替换进入 `/login`。不请求授权上下文或刷新接口。

页面结果：登录页。不是「暂无可用功能」页，不展示「401」作为空菜单文案。

### 6.11 点击「退出登录」

前置条件：已认证；位于空菜单页或管理端外壳。

用户操作：点击「退出登录」。

系统行为：

1. 打开二次确认弹窗，标题「确认退出登录」。不立刻请求接口。
2. 用户点「取消」、点遮罩或按 Escape → 关闭弹窗，停留当前页，不请求退出接口。
3. 用户点「确认退出」→ 请求 `POST /api/v1/auth/logout`，请求头带 `Authorization: Bearer`，无 Body。确认按钮进入「正在退出…」并不可用，取消也不可用。
4. 请求成功（HTTP 200、`code=OK`）→ 清除访问凭证（内存与本标签页会话存储）、清空业务缓存、将会话与权限恢复为未登录、关闭弹窗、用替换方式进入 `/login`。
5. 请求失败 → 不清除访问凭证、不清缓存、不跳转；弹窗内展示错误；可再次确认或取消。

页面结果：未确认则仍留在当前页；确认且成功则看到登录页，不能再作为已登录使用旧菜单。

### 6.12 使用过程中业务请求返回权限已更新

前置条件：已认证；当前请求不是登录 / 授权上下文 / 刷新 / 退出 / 验证码 / 首次改密。

用户操作：触发任意会调用受保护业务接口的操作。

系统行为：见 §7、§8。用户无需主动刷新页面。系统不轮询、不推送。

页面结果：侧栏与权限快照更新为最新；当前路径仍被新菜单覆盖则留在原页并重试该次业务请求一次；不再被覆盖则进入新的授权首页；新菜单为空则进入「暂无可用功能」页；恢复失败则进入登录页。

## 7. 业务规则

1. 前端不计算最终权限，不按角色名补菜单。菜单、权限码、数据范围、授权首页一律以后端授权上下文为准。
2. `menus` 为空 → 不进入带侧栏的管理端外壳 → 独立全屏「暂无可用功能」页。这与 HTTP 401 / 会话无效不是同一件事。
3. 空菜单页中间「请联系管理员」只做说明，不可点，不打开联系渠道。
4. 空菜单页不展示「401」字样。
5. 会话无效或未登录访问 `/app` → 登录页，不得用空菜单页代替。
6. 访问凭证保存在当前页面进程内存和本标签页会话存储；不写入 LocalStorage 或普通 Cookie；退出时必须同时清除。请求受保护接口仍携带 `Authorization: Bearer`。
7. 不单独保存刷新凭证；`POST /auth/refresh` 与受保护 API 一样携带 `Authorization: Bearer`。
8. 授权首页必须是以 `/app` 开头的站内路径，且不得是 `//` 开头的外部地址；否则视为响应不合法，登录流程失败。
9. 登录请求超时 15 秒仍无 HTTP 响应 → 按网络异常处理。
10. 登录业务失败以 `data.errorCode` 映射页面文案（登录 PRD §8.3 / §11.3），不使用外壳 `message`（成功时固定为 `success`）。无 HTTP 响应时展示「网络连接异常，请稍后重试」。结构无法解析时展示「登录响应格式异常，请联系管理员」。
11. 提交登录过程中登录按钮不可用，防止同一轮重复提交。
12. 退出必须先二次确认。仅当退出接口成功后，才清除访问凭证、业务缓存与授权快照并进入登录页。失败时留在当前页并在弹窗内提示。
13. 业务接口 HTTP 409 且编码 `PERMISSION_VERSION_CHANGED` → 不把该次业务结果当成成功 → 先换新访问凭证 → 再拉最新授权上下文 → 再决定页面去向；原业务请求最多自动再执行一次。
14. `GET` 授权上下文、`POST` 刷新、`POST` 退出、`POST` 登录，以及验证码、首次改密路径，不得因 409 再走权限恢复，避免循环。
15. 账号被停用 / 会话撤销走会话失效（登录页），不是本功能的 409 恢复。`SESSION_REVOKED` 与 401 的前端映射细节 **待确认**。
16. 权限变更不主动推送、不轮询；空闲用户可等到下一次业务请求。
17. 密码、访问凭证、完整联系方式不得写入 URL 或页面可见日志文案。
18. 登录页占位符写「请输入账号或手机号」，客户端不做手机号格式校验；账号识别规则由后端执行。

## 12. API

统一约定（当前实现）：

- 前端请求前缀 `/api/v1`。
- 成功响应解包后使用其中的业务 `data`。
- 存在访问凭证时，请求头携带 `Authorization: Bearer`。
- 不使用 Cookie 投递访问令牌或刷新凭证。
- 每个请求带请求追踪头。
- 有 HTTP 响应的失败：使用后端 `code`、`message`、HTTP 状态。
- 无 HTTP 响应：编码 `NETWORK_ERROR`，文案「网络连接异常，请稍后重试」。

### 12.1 POST 登录

契约来源：本机 Swagger `POST /api/v1/auth/login`（schema `LoginRequest` / `ApiResponseLoginResultVO` / `LoginResultVO`），并与 2026-09-05 本地联调响应核对。OpenAPI summary：**公开接口；失败时 HTTP 200 并返回 errorCode**。

| 项目 | 内容 |
| --- | --- |
| API | `/api/v1/auth/login` |
| Method | POST |
| 用途 | 用账号密码创建登录会话 |
| 调用时机 | 登录表单通过客户端校验后提交 |
| 调用条件 | 未处于提交中 |

**请求参数**（OpenAPI `LoginRequest`）

| 参数 | 类型 | 必填 | 来源 | 说明 |
| --- | --- | --- | --- | --- |
| `account` | 字符串 | 是 | 用户输入（已去首尾空格） | OpenAPI `maxLength` 32 |
| `password` | 字符串 | 是 | 用户输入（不 trim） | OpenAPI `minLength` 8、`maxLength` 32 |
| `rememberMe` | 布尔 | 否 | — | 本次登录页**不发送**；后端缺省按 false |
| `captchaCode` | 字符串 | 否 | — | 本次登录页**不发送**；OpenAPI 长度 4–6 |
| `captchaToken` | 字符串 | 否 | — | 本次登录页**不发送** |

**请求示例（本次页面实际发送）**

```json
{
  "account": "admin",
  "password": "<user-input>"
}
```

接口还允许 `rememberMe` / `captchaCode` / `captchaToken`。未接入保持登录与验证码前，请求不得带这三项。

**外层响应（`ApiResponseLoginResultVO`，HTTP 层解包 `data` 前）**

| 字段 | 类型 | 说明 | 页面用途 |
| --- | --- | --- | --- |
| `code` | 字符串 | HTTP 200 业务结果时为 `OK`；参数错误为 `INVALID_REQUEST` | 200 时不作为登录成败依据 |
| `message` | 字符串 | 200 时为 `success` | 登录业务失败**不要**展示该字段 |
| `data` | `LoginResultVO` | 业务结果 | 判断成败与取令牌 |
| `requestId` | 字符串 | 追踪 | 不展示 |
| `timestamp` | 带时区日期时间 | 响应时间 | 不展示 |

**`data`（`LoginResultVO`）**

| 字段 | 类型 | 说明 | 页面用途 |
| --- | --- | --- | --- |
| `success` | 布尔 | 是否认证成功 | 唯一业务成败开关（HTTP 200 时） |
| `errorCode` | 字符串或空 | 失败稳定编码 | 映射文案；成功时为 `null` |
| `requiresCaptcha` | 布尔 | 下次是否需要验证码 | 本次只影响文案，不展开验证码控件 |
| `forcePasswordChange` | 布尔或空 | 是否必须先改密 | 成功且为 `true` 时不拉上下文、不进 `/app`；失败时为 `null` |
| `authContextRequired` | 布尔或空 | 成功时为 `true` | 成功且不必改密后请求授权上下文；失败时为 `null` |
| `accessToken` | 字符串或空 | 短期访问凭证 | 仅 `success=true` 时使用；失败时为 `null` |

**成功响应示例（无需改密；令牌不写原文）**

```json
{
  "code": "OK",
  "message": "success",
  "data": {
    "success": true,
    "errorCode": null,
    "requiresCaptcha": false,
    "forcePasswordChange": false,
    "authContextRequired": true,
    "accessToken": "<access-token>"
  },
  "requestId": "<request-id>",
  "timestamp": "<offset-date-time>"
}
```

**成功但必须先改密（`data` 形态，OpenAPI 与本地实现一致）**

```json
{
  "success": true,
  "errorCode": null,
  "requiresCaptcha": false,
  "forcePasswordChange": true,
  "authContextRequired": true,
  "accessToken": "<access-token>"
}
```

此时仍算认证成功，但前端不得请求 GET `/auth/context`，不得进入业务系统。

**业务失败响应示例（HTTP 200，账号或密码错误；本地联调实测字段）**

```json
{
  "code": "OK",
  "message": "success",
  "data": {
    "success": false,
    "errorCode": "INVALID_CREDENTIALS",
    "requiresCaptcha": false,
    "forcePasswordChange": null,
    "authContextRequired": null,
    "accessToken": null
  },
  "requestId": "<request-id>",
  "timestamp": "<offset-date-time>"
}
```

**参数校验失败示例（HTTP 400；本地联调实测）**

```json
{
  "code": "INVALID_REQUEST",
  "message": "请求参数不正确",
  "data": [
    {
      "field": "account",
      "message": "不能为空"
    },
    {
      "field": "password",
      "message": "个数必须在8和32之间"
    }
  ],
  "requestId": "<request-id>",
  "timestamp": "<offset-date-time>"
}
```

页面顶部展示外壳 `message`「请求参数不正确」。不必把字段级 `data[].message` 拼进登录通用错误（客户端已做长度校验）。

**`errorCode` → 页面文案（登录 PRD §8.3 / 总览 §11.2，已确认）**

| `errorCode` | 页面提示 | 是否清空密码 | 是否保留账号 |
| --- | --- | --- | --- |
| `INVALID_CREDENTIALS` | 账号或密码错误，请重新输入 | 是 | 是 |
| `ACCOUNT_DISABLED` | 账号已停用，请联系管理员 | 是 | 是 |
| `ROLE_UNAVAILABLE` | 账号暂时无法访问系统，请联系管理员 | 否 | 是 |
| `CAPTCHA_REQUIRED` | 请完成验证码后重试 | 否 | 是 |
| `CAPTCHA_INVALID` | 验证码错误或已失效 | 否 | 是 |
| `ACCOUNT_TEMP_LOCKED` | 账号临时锁定 | 否 | 是 |
| `RATE_LIMITED` | 操作过于频繁，请稍后再试 | 否 | 是 |
| `SYSTEM_UNAVAILABLE` | 系统暂时不可用，请稍后重试 | 否 | 是 |
| 未登记编码 | 登录响应格式异常，请联系管理员 | 否 | 是 |

`ACCOUNT_TEMP_LOCKED` 是否展示剩余锁定时间：**待确认**（PRD 未给登录页倒计时字段）。`ACCOUNT_DISABLED` 的「联系管理员」入口仍是登录页现有无事件按钮，不新开渠道。

**成功后**（`success=true` 且不必改密）：写入访问凭证 → 立刻调用 §12.2。不在本步跳转。

**失败后**：不跳转；按上表处理密码；展示映射文案。不关闭页面（无弹窗）。

HTTP 200 且 `success=false` **不是** HTTP 层失败，前端必须读 `data`，不能把「有 200」当成登录成功。

### 12.2 GET 授权上下文

| 项目 | 内容 |
| --- | --- |
| API | `/api/v1/auth/context` |
| Method | GET |
| 用途 | 获取用户、租户、菜单、权限与授权首页 |
| 调用时机 | 登录成功写入访问凭证后；进入 `/app` 会话恢复时；权限版本 409 恢复时 |
| 调用条件 | 应携带有效访问凭证；本接口本身不因 409 再触发权限恢复 |

**请求参数**：无 Query、无 Body。身份来自访问凭证。

**响应：当前前端校验并使用的字段**

| 字段 | 类型 | 说明 | 页面用途 |
| --- | --- | --- | --- |
| `user.id` | 非空字符串 | 用户 ID | 写入会话 |
| `user.displayName` | 非空字符串 | 显示名称 | 布局展示；本功能页不展示 |
| `user.avatarUrl` | URL 或空 | 头像 | 写入会话；登录页不展示 |
| `tenant.id` | 非空字符串 | 租户 ID | 写入会话 |
| `tenant.name` | 非空字符串 | 租户名称 | 布局展示 |
| `menus` | 菜单节点数组，可空 | 授权菜单树 | 空则空菜单页 |
| `menus[].id` | 非空字符串 | 节点 ID | 树标识 |
| `menus[].label` | 非空字符串 | 展示名 | 布局菜单文案 |
| `menus[].routeKey` | 字符串或空 | 路由键 | 映射站内路径；空为目录 |
| `menus[].icon` | 字符串或空 | 图标键 | 布局图标 |
| `menus[].children` | 同结构数组 | 子节点 | 递归 |
| `permissionCodes` | 字符串数组，缺省按空数组 | 功能权限码 | 后续页面；不决定空菜单页 |
| `dataScopes` | 字符串数组，缺省按空数组 | 数据范围摘要 | 后续页面 |
| `sensitiveFieldPermissions` | 字符串数组，缺省按空数组 | 敏感字段权限 | 后续页面 |
| `expiresAt` | 带偏移的日期时间 | 上下文过期时间 | 写入会话；本功能页不展示 |
| `authorizedHome` | 以 `/app` 开头的站内路径 | 授权首页 | 登录成功跳转；已认证回访登录页；409 后无权限时跳转 |
| `permissionVersion` | 非空字符串，可选 | 权限版本 | 可接收；本功能页不展示 |

后端视图还可能同时带 `user.name`、`role`、`homeRoute`、`dataScope` 对象、菜单 `name`/`path` 等。当前前端 schema **不要求**这些字段；页面行为以本表为准。与登录 PRD 字段名是否最终统一 **待确认**。

**菜单非空时的响应示例（只含前端已用字段）**

```json
{
  "user": {
    "id": "1001",
    "displayName": "张三丰",
    "avatarUrl": null
  },
  "tenant": {
    "id": "tenant-1",
    "name": "澄客集团"
  },
  "menus": [
    {
      "id": "system",
      "label": "系统管理",
      "routeKey": null,
      "icon": "settings",
      "children": []
    }
  ],
  "permissionCodes": ["system:user:view"],
  "dataScopes": ["department_and_descendants"],
  "sensitiveFieldPermissions": [],
  "expiresAt": "2026-08-09T12:00:00+08:00",
  "authorizedHome": "/app/dashboard"
}
```

**空菜单示例**

```json
{
  "user": {
    "id": "1001",
    "displayName": "张三丰",
    "avatarUrl": null
  },
  "tenant": {
    "id": "tenant-1",
    "name": "澄客集团"
  },
  "menus": [],
  "permissionCodes": [],
  "dataScopes": [],
  "sensitiveFieldPermissions": [],
  "expiresAt": "2026-08-09T12:00:00+08:00",
  "authorizedHome": "/app/dashboard"
}
```

`permissionVersion` 有则接收；示例不编造具体版本值。

**成功后**：

- 登录流程：写入已认证会话与权限快照 → 替换进入 `authorizedHome`。
- 会话恢复：写入已认证 → 按菜单空/非空展示。
- 409 恢复：写入最新快照 → 按 §8.5 决定是否跳转，然后原业务请求可再执行一次。

**失败后**：

- 登录流程：见 §6.8。
- 会话恢复：HTTP 401 则走刷新再试一次；其他失败 → 匿名 → 登录页。失败时不展示空菜单页。
- 409 恢复失败：匿名 → 登录页。是否展示额外提示 **待确认**。

本 GET 在会话有效时即使权限刚变也应返回最新快照，**不**返回 409 `PERMISSION_VERSION_CHANGED`（已确认，授权上下文 API Spec）。

### 12.3 POST 刷新访问凭证

| 项目 | 内容 |
| --- | --- |
| API | `/api/v1/auth/refresh` |
| Method | POST |
| 用途 | 用当前 `Authorization: Bearer` 访问令牌换取写入最新权限版本的访问令牌 |
| 调用时机 | 仍有访问令牌且授权上下文返回 401；权限版本 409 恢复时 |
| 调用条件 | 多个并发恢复共用同一次刷新，避免连续多次刷新 |

**请求参数**：无显式 Body。请求头必须带当前访问令牌。同一标签页硬刷新后仍可从会话存储取出访问令牌再换票。

**响应使用字段**：与登录相同，`accessToken` 非空字符串。

```json
{
  "accessToken": "<new-access-token>"
}
```

**成功后**：用新访问凭证覆盖内存与本标签页会话存储中的旧凭证；不单独改菜单。调用方继续请求授权上下文。

**失败后**：清除访问凭证；会话恢复场景进入登录页；409 恢复场景进入匿名并进入登录页。

当前实现：进入 `/app` 恢复会话、以及 409 恢复会调用本接口。普通业务接口返回 401 时，**不会**自动刷新并重放。该能力是否交付 **待确认**（未落地）。

### 12.4 POST 退出登录

契约来源：本机 Swagger `POST /api/v1/auth/logout`（schema `ApiResponseVoid`），并与 2026-09-05 本地联调响应核对。OpenAPI summary：**退出登录**；description：**撤销当前会话；重复退出视为成功**。

| 项目 | 内容 |
| --- | --- |
| API | `/api/v1/auth/logout` |
| Method | POST |
| 用途 | 撤销当前设备会话 |
| 调用时机 | 二次确认弹窗中点击「确认退出」 |
| 调用条件 | 用户已确认；当前不在提交中；请求头带访问令牌 |

**请求参数**：无 Query、无 Body。不传他人用户 ID。身份来自 `Authorization: Bearer <accessToken>`。

**请求示例（本次页面实际发送）**

```http
POST /api/v1/auth/logout
Authorization: Bearer <access-token>
Accept: application/json
```

无 JSON Body。

**外层响应（`ApiResponseVoid`，HTTP 层解包 `data` 前）**

| 字段 | 类型 | 说明 | 页面用途 |
| --- | --- | --- | --- |
| `code` | 字符串 | 成功为 `OK` | 成功才清缓存 |
| `message` | 字符串 | 成功为 `success` | 不展示 |
| `data` | `null` | OpenAPI `ApiResponseVoid.data` 无业务字段 | 页面不读业务字段 |
| `requestId` | 字符串 | 追踪 | 不展示 |
| `timestamp` | 带时区日期时间 | 响应时间 | 不展示 |

**成功响应示例（HTTP 200；本地联调实测）**

```json
{
  "code": "OK",
  "message": "success",
  "data": null,
  "requestId": "<request-id>",
  "timestamp": "<offset-date-time>"
}
```

同一访问令牌重复退出仍返回 HTTP 200、`code=OK`、`data=null`（与 OpenAPI「重复退出视为成功」一致）。

**未携带或无效访问令牌（HTTP 401；本地联调实测无响应体）**

```http
HTTP/1.1 401
Content-Length: 0
```

页面不把空 body 当成功。展示 HTTP 层失败文案（无 `message` 时为「请求失败，请稍后重试」）。

**成功后**：清除访问凭证（内存与本标签页会话存储）；清空业务缓存；会话与权限恢复未登录；关闭弹窗；替换进入 `/login`。

**失败后**：不清除访问凭证，不清业务缓存，不跳转；弹窗内展示错误。

## 13. API 与页面状态关系

登录：

```text
用户提交
↓
提交中 = 是；通用错误清空
↓
POST 登录
├── HTTP 无响应 / 400 → 提交中 = 否；展示错误；会话不变
├── HTTP 200 且 data.success=false → 提交中 = 否；按 errorCode 展示；不写令牌
├── HTTP 200 且必须改密 → 提交中 = 否；不拉上下文；不进 /app
└── HTTP 200 且成功且不必改密 → 写入访问凭证
        ↓
        GET 授权上下文
        ├── 失败 → 提交中 = 否；展示错误；停留登录页
        └── 成功 → 会话 = 已认证；写入菜单与授权首页
                  ↓
                  提交中 = 否
                  ↓
                  进入 authorizedHome
                  ↓
                  菜单为空 → 「暂无可用功能」
                  菜单非空 → 管理端外壳
```

会话恢复：

```text
进入 /app 且会话未开始
↓
会话 = 恢复中
↓
GET 授权上下文
├── 成功 → 已认证 → 按菜单分支
├── HTTP 401 → POST 刷新 → 再 GET 授权上下文 → 成功则已认证，否则匿名
└── 其他失败 → 匿名 → 登录页
```

权限版本：

```text
业务请求
↓
HTTP 409 且 PERMISSION_VERSION_CHANGED（非豁免、未重试）
↓
POST 刷新（并发共用一次）
↓
GET 授权上下文
├── 失败 → 匿名 → 登录页
└── 成功 → 更新会话与菜单
          ├── 菜单空 → 空菜单页
          ├── 当前路径仍有权 → 原请求再执行一次
          └── 当前路径无权 → 进入新授权首页
```

## 14. API 依赖关系

```text
POST 登录 成功（得到访问凭证）
↓
GET 授权上下文（必须带该访问凭证）

进入 /app
↓
GET 授权上下文
↓（仅当该次为 HTTP 401）
POST 刷新（得到新访问凭证）
↓
GET 授权上下文（必须带新访问凭证）

业务接口 409 PERMISSION_VERSION_CHANGED
↓
POST 刷新
↓
GET 授权上下文
↓
原业务请求再执行一次（最多一次）

用户点击退出
↓
二次确认弹窗
├── 取消 / 遮罩 / Escape → 停留当前页
└── 确认退出 → POST /auth/logout
```

登录不得依赖授权上下文先成功；顺序必须是登录成功后再拉上下文。

刷新不得依赖用户再次输入密码。

## 15. 权限

| 问题 | 结论 |
| --- | --- |
| 谁可以打开登录页 | 未认证用户；已认证用户会被送走 |
| 谁可以提交登录 | 登录页上的任何人；无业务权限码 |
| 谁可以看到空菜单页 | 仅已认证且 `menus` 为空的账号 |
| 谁可以退出 | 能看到空菜单页或管理端外壳的用户；不要求业务权限码 |
| 按钮是否按权限码隐藏 | 登录页与空菜单页无业务权限码控制 |
| 数据权限 | 本功能不按数据范围过滤列表；数据范围只写入快照供后续页面 |

不得用角色名称推断菜单。前端不得因「像管理员」而补菜单。

图形验证码、首次改密页的访问规则：本功能未交付对应页面，见不包含范围。

## 16. 页面边界情况

| 场景 | 行为 |
| --- | --- |
| Loading（登录提交） | 登录按钮不可用，文案「正在登录…」 |
| Loading（进入 `/app`） | 「正在恢复安全会话…」 |
| Empty（菜单为空） | 「暂无可用功能」页，可退出 |
| Empty（登录表单未填） | 提交后字段错误，不调用接口 |
| Error（登录/上下文失败） | 登录页顶部展示错误，保留输入 |
| Error（会话恢复失败） | 登录页；不是空菜单页 |
| Error（退出接口失败） | 弹窗保持打开并展示错误；不清缓存、不进入登录页 |
| Disabled | 登录提交中按钮不可用 |
| Partial Data / 结构不合法 | 登录流程展示「登录响应格式异常，请联系管理员」；恢复流程视为失败进入登录页 |
| Rapid Operation（连续点登录） | 提交中按钮不可用 |
| Rapid Operation（连续点退出） | 确认提交中两个按钮不可用，不重复发请求 |
| Null / Undefined | 授权首页非法则登录失败；用户/租户空对象不能通过上下文校验 |
| Duplicate Operation（重复退出） | 后端重复退出仍成功；前端成功后已清令牌，不会用旧令牌再退 |
| 授权首页为外部地址 | 拒绝，登录失败 |
| 业务 401（非恢复阶段） | 当前不自动刷新重放 **待确认 / 未落地** |

## 18. 数据变更 / 持久化

| 数据 | 可否改 | 何时提交 | 提交到哪 | 成功后刷新什么 | 失败后 |
| --- | --- | --- | --- | --- | --- |
| 账号密码 | 仅登录表单 | 点击登录且校验通过 | POST 登录 | 不刷新列表；改为拉上下文 | 保留输入 |
| 访问凭证 | 系统写入 | 登录或刷新成功 | 内存 + 本标签页会话存储 | — | 退出成功后清除；退出失败则保留 |
| 授权快照 | 系统写入 | 上下文成功 | 跨页会话快照 | 覆盖旧菜单与权限 | 登录流程保留未认证；恢复失败变匿名 |
| 刷新凭证 | 本期不单独投递 | — | — | — | — |
| 用户主数据 | 本功能不改 | — | — | — | — |

持久化：

- 访问凭证：当前页面进程内存 + 本标签页会话存储；同一标签页刷新后可恢复。关闭标签页、退出登录后清除。不写入 LocalStorage，不使用 Cookie。
- 授权上下文：仅会话内快照，不写入 LocalStorage / SessionStorage（对齐登录 PRD：授权上下文仅会话内缓存）。
- URL：不把密码或令牌放入查询参数。登录后进入 `authorizedHome`。
- 草稿：无。
- 原目标路径：会话边界可写入跳转状态；登录页当前不读、登录成功后不据此跳转。是否应回跳 **待确认**。

| 异常场景 | 页面行为 |
| --- | --- |
| 字段校验失败 | 不请求接口；字段下展示错误 |
| 登录 HTTP 400 | 留在登录页；顶部「请求参数不正确」 |
| 登录 HTTP 200 且 `success=false` | 留在登录页；按 `errorCode` 映射文案；`INVALID_CREDENTIALS` / `ACCOUNT_DISABLED` 清空密码 |
| 登录成功但必须先改密 | 留在登录页；不请求授权上下文；展示「请先完成密码修改」 |
| 登录成功但上下文失败 / 结构非法 | 留在登录页；顶部错误；访问凭证若已写入是否清除 **待确认** |
| 授权首页不是站内 `/app` 路径 | 视为上下文非法，登录失败 |
| 会话恢复 401 | 刷新一次再拉上下文；仍失败则登录页 |
| 会话恢复其他失败 | 登录页 |
| 退出接口失败 | 留在当前页；弹窗展示错误；不清除本地会话 |
| 409 权限已更新 | 见 §8.5；不把原业务结果当成功 |
| 409 恢复失败 | 进入登录页 |
| 网络无响应 | 「网络连接异常，请稍后重试」 |
| 「联系管理员」等未接线按钮 | 无变化；产品目标 **待确认** |

不要根据中文错误文案做安全分支；安全逻辑使用 HTTP 状态与稳定编码（401、409 + `PERMISSION_VERSION_CHANGED`）。

## 21. 验收标准

### 页面

- [ ] `/` 进入后是登录页。
- [ ] 登录页展示「欢迎回来」、账号、密码、登录按钮。
- [ ] 未认证访问 `/app` 看到登录页，不是空菜单页。
- [ ] 进入 `/app` 恢复过程中可以看到「正在恢复安全会话…」。
- [ ] 已认证且 `menus` 为空时，标题为「暂无可用功能」，中间提示为「当前账号尚未分配可访问功能，请联系管理员。」，不出现「401」字样，无侧栏。
- [ ] 空菜单提示不可点击，不打开联系渠道。

### 交互

- [ ] 空表单提交出现「请输入账号」和「密码至少需要 8 个字符」。
- [ ] 账号提交前去除首尾空格；密码不 trim。
- [ ] 提交中登录按钮不可用，文案为「正在登录…」。
- [ ] 密码显隐只改变可见性，不改变密码值。
- [ ] 登录失败停留登录页并保留输入。
- [ ] 登录成功菜单非空时进入后端给出的授权首页。
- [ ] 登录成功菜单为空时进入「暂无可用功能」页。
- [ ] 已认证再打开 `/login` 不会停留在登录表单。
- [ ] 点击「退出登录」先出现确认弹窗，取消后不发退出请求、仍留在当前页。
- [ ] 确认退出且接口成功后进入登录页，且不能再作为已登录使用旧菜单。
- [ ] 退出接口失败时留在当前页，弹窗展示错误，访问凭证与业务缓存仍在。

### 业务规则

- [ ] 前端不补默认菜单。
- [ ] 空菜单与会话 401 不是同一页。
- [ ] 访问凭证不出现在 LocalStorage；本标签页会话存储仅保存访问令牌，退出成功后必须清除。
- [ ] 非法授权首页（非 `/app` 或外部地址）不能把用户带出站。
- [ ] 业务请求 409 `PERMISSION_VERSION_CHANGED` 后会换凭证、重拉上下文；当前页没权则去新首页；菜单空则空菜单页。
- [ ] 授权上下文 / 刷新 / 退出 / 登录 不会因 409 陷入恢复循环。
- [ ] 无轮询、无推送来等待权限变更。

### API

- [ ] 登录只在客户端校验通过后调用，Body 含 `account`、`password`，不含 `rememberMe` 与验证码字段。
- [ ] HTTP 200 且 `data.success=false` 时不进入 `/app`，文案按 `errorCode` 映射，不展示外壳 `message: success`。
- [ ] `INVALID_CREDENTIALS` 提示「账号或密码错误，请重新输入」，并清空密码、保留账号。
- [ ] `success=true` 且 `forcePasswordChange=true` 时不请求授权上下文。
- [ ] `success=true` 且不必改密时才使用 `accessToken` 并调用授权上下文。
- [ ] 会话恢复先拉上下文，仅 401 时刷新再拉一次。
- [ ] 退出请求无 Body、不传他人用户 ID；成功响应 `code=OK` 且 `data=null` 后才清缓存。
- [ ] 接口失败使用稳定编码与 HTTP 状态做分支，中文 `message` 仅展示。

### 表单

- [ ] 账号去空格后必填、最多 32 字符；超长提示「账号不能超过 32 个字符」。
- [ ] 密码 8–32 字符且不 trim；过短提示「密码至少需要 8 个字符」，超长提示「密码不能超过 32 个字符」。
- [ ] 无保持登录、无验证码字段（未交付则验收时不应出现，除非产品确认接入）。

## 22. 不包含范围

本功能**不包含**：

- 管理端左侧菜单、顶栏组织名/用户名、侧栏折叠（见布局 Spec）。
- 图形验证码获取与登录页验证码交互（拦截器仅豁免该路径，页面未做）。
- 首次登录修改密码**页**（登录接口会返回 `forcePasswordChange`，本次只做到不进入业务系统）。
- 「忘记密码」真实流程、「联系管理员」联系渠道、「隐私与安全」页面。
- 「7 天内保持登录」开关与 `rememberMe` 请求字段。
- 用户管理、角色配置、部门维护、业务数据 CRUD。
- 在前端计算或补齐权限、菜单、数据范围。
- 把访问凭证写入 LocalStorage 或普通 Cookie（本标签页会话存储仅用于刷新后恢复访问令牌）。
- 普通业务接口 401 的自动刷新与重放（当前未落地）。
- 登录成功后回到进入 `/app` 前的原目标路由（当前未读取）。
- 权限变更的推送或定时轮询。
- 空菜单页上的任何可点击「联系管理员」。
- 登录页最新响应式断点与设计系统换色（有设计稿，未作为本 Spec 已交付）。
