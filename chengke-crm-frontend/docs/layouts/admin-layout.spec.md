## 1. 功能目标

- **解决什么问题**：用户管理、部门管理、角色管理、线索等后台页面在设计图中都带同一套「左侧全局菜单 + 顶部 Header + 内容区」。该外壳应抽成共用布局，避免每个业务页各自再画一套导航。
- **面向什么用户**：已通过登录认证、进入 `/app` 的后台使用者。
- **用户为什么需要**：在多个业务页之间切换时，始终能看到当前有权访问的菜单、当前组织、当前账号，并能退出。
- **用户最终要完成的业务目标**：使用左侧菜单进入被授权的业务页；识别当前组织与账号；需要时退出登录。
- **页面最终产生什么结果**：不产生业务数据写入（退出除外）。布局本身只承载导航与会话身份展示；业务增删改发生在内容区的具体页面。

登录页不使用本布局。未认证用户不能看到本布局。

**已确认（2026-09-05）**：授权上下文返回的 `menus` 为空时，**不进入**带左侧菜单的管理端外壳，也不在空侧栏里写一行提示。用户只看到一张独立的全屏友好提示页（无左侧菜单、不展示「401」字样）。页面正中标题为「暂无可用功能」；中间提示为「当前账号尚未分配可访问功能，请联系管理员。」；并提供「退出登录」。这与「HTTP 401 未登录」不是同一件事：会话仍然有效，只是没有任何可访问功能。

## 2. 业务对象 / 数据模型

| 业务对象 | 说明 | 关键属性 | 对象关系 |
| --- | --- | --- | --- |
| 会话 | 当前浏览器的登录会话 | 是否已认证 | 布局仅在已认证后出现 |
| 用户 | 当前操作者摘要 | `id`、`displayName`、`avatarUrl` | 属于租户；布局展示姓名 |
| 租户 / 当前组织 | 授权上下文中的租户摘要 | `id`、`name` | 用户隶属于该租户；布局 Header 展示名称 |
| 菜单树 | 后端按权限算出的导航 | 节点 `id`、`label`、`routeKey`、`icon`、`children` | 由授权上下文返回；布局只展示，不计算权限 |
| 菜单节点 | 目录或可进入页面 | `routeKey` 为空表示目录；非空且在前端白名单内才可导航 | 可嵌套子节点 |
| 路由白名单 | 前端已注册、允许被菜单打开的站内路径 | `routeKey` → 站内路径 | 后端决定显示哪些键；前端决定哪些键能变成链接 |
| 侧栏折叠偏好 | 用户是否收起全局菜单 | 展开 / 收起 | 只影响布局宽度与文案显隐，不影响授权 |

对象依赖：

- 授权上下文 → 用户、租户、菜单树。
- 菜单树 + 路由白名单 → 可点击的左侧菜单项。
- 当前 URL → 哪一项处于选中态。

不由本布局维护、但会出现在内容区的对象（组织树、用户列表、部门详情等）不属于本布局数据模型。

无独立「租户表」或「菜单表」由本布局读写。权限明细表未落地；菜单来自授权上下文。

## 3. 页面结构

本布局是 `/app` 下所有业务页的共用外壳，不是某一个业务页。

```text
管理端整体布局
├── 左侧全局菜单（侧栏）
│   ├── 品牌区（Logo / 产品名）
│   ├── 导航列表（后端菜单树）
│   └── 收起 / 展开入口
├── 右侧
│   ├── 顶部 Header
│   │   ├── 当前组织
│   │   └── 当前账号 + 退出
│   └── 业务内容区（各业务页）
```

该结构与用户管理 UI 设计 §2「管理端框架」一致：左侧全局菜单、顶部 Header、页面内容区。内容区内的组织树、筛选、表格属于各业务页，不属于本布局。

### 3.1 左侧全局菜单（侧栏）

| 项 | 说明 |
| --- | --- |
| 展示什么 | 品牌标识；授权菜单树；底部「收起菜单 / 展开侧栏」 |
| 用户可以做什么 | 点击可导航菜单项进入对应业务页；点击底部入口切换展开/收起 |
| 何时显示 | 已认证并进入 `/app` 时始终显示 |
| 何时隐藏 | 登录页、未认证跳转登录时不显示本布局。**`menus` 为空时整侧侧栏都不显示**（连空壳侧栏也不保留） |
| 何时 disabled | 当前实现：侧栏本身无整体 disabled。无 `routeKey` 或 `routeKey` 不在白名单的节点不能作为链接点击 |

品牌区：

- 始终显示「CK」标识块。
- 展开时显示产品名「澄客 CRM」。英文副标题当前实现为 `Customer clarity`；是否为已确认产品文案 **待确认**。
- 收起时隐藏产品名与副标题，仅保留标识块。

导航列表：

- 有菜单时按树渲染。
- 可导航项：图标 +（展开时）`label`；当前路由匹配时为选中态（背景、文字，不只改图标颜色）。不使用左侧 inset 阴影条。
- 目录项（无可用路径）：展开时显示分组标题（`label`）；收起时不显示该目录标题文字。
- 有菜单时才渲染本侧栏。`menus` 为空时本布局整体不出现，见 §8.2。

底部入口：

- 展开：图标 + 文案「收起菜单」；无顶部分隔线、无独立底栏表面。
- 收起：仅图标；可访问名称为「展开侧栏」。

侧栏规格（设计系统 §5.2 + 当前实现）：展开宽 240px，收起宽 72px，视口高度贴齐。

### 3.2 顶部 Header

| 项 | 说明 |
| --- | --- |
| 展示什么 | 左侧当前组织；右侧当前用户姓名、认证说明、账号图标、退出按钮 |
| 用户可以做什么 | 点击退出 |
| 何时显示 | 与侧栏同时出现 |
| 何时隐藏 | 不使用本布局的页面不显示 |
| 何时 disabled | 退出确认提交中，弹窗内按钮不可用 |

左侧「当前组织」：

- 固定说明文字「当前组织」。
- 名称：有租户时显示 `tenant.name`；缺失时显示「未识别组织」。
- 当前实现点击组织名称无跳转、无下拉。是否可切换组织 **待确认**。

右侧账号区：

- 姓名：有用户时显示 `displayName`；缺失时显示「未知用户」。
- 次级文案当前实现为「已通过安全认证」。
- 账号区使用固定图标，当前实现不展示 `user.avatarUrl`。是否应展示头像 **待确认**。
- 退出：图标按钮，可访问名称为「退出登录」。

设计系统 §9 与用户管理 UI §2 还要求 Header 面包屑、全局搜索、通知。当前布局没有这些区域 → **待确认**（见 §23）。

Header 高度：68px。浅色表面，与侧栏不同底。

### 3.3 业务内容区

| 项 | 说明 |
| --- | --- |
| 展示什么 | 当前路由对应的业务页面（工作台、用户、部门、角色、线索等） |
| 用户可以做什么 | 由各业务页 Spec 定义 |
| 何时显示 | 布局已渲染后始终占位；具体内容随路由变化 |
| 何时隐藏 | 不隐藏外壳；无匹配路由时由应用级 404 处理，不由本布局定义页面内容 |
| 何时 disabled | 本布局不禁用内容区 |

本布局不绘制业务页标题、组织树、表格、抽屉。用户管理 UI 要求 Header 面包屑作为页面定位、正文不重复模块大标题——若面包屑未进布局，各业务页如何避免重复标题 **待确认**。

## 4. 页面数据

| 数据 | 类型 | 来源 | 用途 | 是否影响页面行为 |
| --- | --- | --- | --- | --- |
| 会话状态 | 已认证 / 加载中 / 匿名 等 | 进入 `/app` 前的会话恢复；布局出现时已是已认证 | 决定能否看到本布局 | 是（布局外拦截） |
| 当前用户 | 对象或空 | 授权上下文 `user` | Header 姓名 | 是（缺省文案） |
| 当前租户 | 对象或空 | 授权上下文 `tenant` | Header 组织名 | 是（缺省文案） |
| 菜单树 | 节点数组 | 授权上下文 `menus` | 渲染左侧导航 | 是 |
| 当前路径 | 站内路径 | 浏览器路由 | 菜单选中态；内容区页面 | 是 |
| 侧栏是否收起 | 是 / 否 | 布局内用户切换；默认展开 | 侧栏宽度、文案/图标展示 | 是 |
| 路由白名单 | `routeKey` → 路径 | 前端已注册路由的固定映射 | 无映射则不生成链接 | 是 |
| 图标键映射 | `icon` → 图标 | 前端本地白名单 | 未知键使用默认菜单图标 | 否（仅展示） |
| Access Token | 内存中的访问凭证 | 登录或会话恢复写入 | 退出时清除；布局不展示 | 退出时影响后续请求 |
| 业务页数据 | 各页自有 | 各业务页 | 内容区 | 本布局不消费 |

当前实现已登记的 `routeKey` 映射：

| routeKey | 站内路径 |
| --- | --- |
| `dashboard` | `/app/dashboard` |
| `system.users` | `/app/system/users` |
| `system.departments` | `/app/system/departments` |
| `system.roles` | `/app/system/roles` |
| `leads` | `/app/leads` |
| `lead-pools` | `/app/lead-pools` |

未出现在上表的 `routeKey`：不生成链接。是否允许扩展该表 **待确认**（新增业务页时应同步登记）。

布局**不**把菜单、权限码写入 LocalStorage / SessionStorage（登录 PRD §12.11：授权上下文仅会话内缓存）。

侧栏折叠当前只存在本次前端运行状态，刷新后默认展开。是否跨刷新记住 **待确认**。

## 5. 页面状态

### 5.1 UI 状态

| 状态 | 可选值 | 含义 | 影响 | 何时进入 |
| --- | --- | --- | --- | --- |
| 侧栏折叠 | 展开 / 收起 | 全局菜单是否紧凑 | 宽度 240px 或 72px；文案显隐 | 默认展开；用户点击底部入口切换 |
| 当前菜单选中 | 某可导航项 / 无匹配 | 当前 URL 是否等于该菜单路径 | 该项使用选中视觉 | URL 变化时按路径匹配 |
| 退出进行中 | 是 / 否 | 确认弹窗是否正在请求退出 | 弹窗按钮不可用，文案「正在退出…」 | 点击「确认退出」后 |

### 5.2 业务状态

| 状态 | 可选值 | 含义 | 影响 | 何时进入 |
| --- | --- | --- | --- | --- |
| 认证外壳 | 可见 / 不可见 | 是否已通过会话边界 | 不可见时用户看不到本布局 | 已认证进入 `/app` 可见 |
| 菜单是否为空 | 空 / 非空 | 授权菜单树长度 | 空：展开时提示无菜单；非空：渲染树 | 授权上下文写入后 |
| 租户是否可识别 | 有名称 / 无 | Header 组织文案 | 「名称」或「未识别组织」 | 授权上下文的 `tenant` |
| 用户是否可识别 | 有姓名 / 无 | Header 账号文案 | 「姓名」或「未知用户」 | 授权上下文的 `user` |

依赖关系：

- 认证外壳不可见 → 不考虑折叠、菜单、Header。
- 菜单为空 → 无选中项；内容区仍可能被路由打开（与登录 PRD「不进入空白后台」是否冲突见 §23）。
- 折叠不改变菜单数据、当前路由、用户/租户。

## 6. 用户行为

### 6.1 进入任一 `/app` 业务页

前置条件：会话已认证；授权上下文已写入。

用户操作：登录成功跳转，或刷新后恢复会话进入 `/app`。

系统行为：

1. 渲染本布局。
2. 用授权菜单树渲染左侧导航。
3. 用租户、用户渲染 Header。
4. 在内容区展示当前路由页面。

页面结果：左侧菜单 + Header + 业务页同时可见。

### 6.2 点击可导航菜单项

前置条件：该项 `routeKey` 在白名单内，已生成站内路径。

用户操作：点击该菜单行。

系统行为：导航到对应站内路径。

页面结果：内容区切换为该业务页；该项变为选中态；侧栏折叠状态保持不变。

### 6.3 点击目录（无路径）节点

前置条件：节点无白名单路径。

用户操作：点击分组标题。

系统行为：当前实现不导航。是否展开/折叠子级 **待确认**（当前实现子级始终列出，无独立展开收起）。

页面结果：路由不变。

### 6.4 点击未知 `routeKey` 节点

前置条件：`routeKey` 非空但不在白名单。

用户操作：该节点当前实现不作为链接。

系统行为：不打开外部 URL，不拼任意路径。

页面结果：用户不能通过该节点离开站内已注册路由。

### 6.5 收起菜单

前置条件：侧栏为展开。

用户操作：点击「收起菜单」。

系统行为：侧栏改为收起。

页面结果：宽度变为 72px；隐藏产品名、菜单文字、目录标题；可导航项只显示图标；收起项图标带菜单 `label` 作为悬停说明；底部变为「展开侧栏」。内容区路由与业务数据不变。

### 6.6 展开侧栏

前置条件：侧栏为收起。

用户操作：点击「展开侧栏」。

系统行为：侧栏改为展开。

页面结果：宽度 240px；恢复产品名、菜单文字、目录标题。

### 6.7 退出登录

前置条件：已认证，本布局可见。

用户操作：点击「退出登录」。

系统行为：

1. 打开确认弹窗，标题「确认退出登录」。不立刻请求接口。
2. 「取消」、点击遮罩或 Escape → 关闭弹窗，停留本布局。
3. 「确认退出」→ 请求 `POST /api/v1/auth/logout`（`Authorization: Bearer`，无 Body）。提交中两个按钮不可用。
4. 接口成功 → 清除访问凭证、业务缓存、会话与权限快照；替换进入登录页。
5. 接口失败 → 不清除、不跳转；弹窗内展示错误。

页面结果：未确认则仍看到管理端外壳；确认且成功后看到登录页。菜单与权限不留在可被下一用户看到的会话状态中。

### 6.8 点击 Header 组织 / 姓名 / 头像

当前实现无菜单、无跳转。是否打开账号菜单、个人设置、组织切换 **待确认**。

### 6.9 浏览器后退 / 前进

用户操作：使用浏览器历史。

系统行为：内容区与菜单选中态跟随 URL。侧栏折叠是否随历史变化 **待确认**（当前实现折叠不写入 URL）。

## 7. 业务规则

1. `/app` 下业务页共用同一套整体布局，不在每个业务页再画一套全局菜单。
2. 仅已认证会话可以看到本布局。
3. 登录页不使用本布局。
4. 左侧菜单只展示后端授权上下文返回的菜单树；前端不得按角色名或用户类型补默认菜单（登录 PRD §12.10、设计系统 §9）。
5. 只有同时满足「有 `routeKey`」且「`routeKey` 在前端白名单」的节点才能成为导航链接。
6. 未知 `routeKey` 不得变成任意 URL。
7. 后端只提供稳定图标键；前端只用本地白名单映射图标，不加载任意远程图标地址（设计系统 §7.1）。
8. 当前菜单选中必须同时改变背景和文字，不能只改图标颜色（设计系统 §9）。不使用左侧 inset 阴影条。
9. 侧栏是唯一大面积深色框架；Header 必须是浅色，不能与侧栏同底（设计系统 §5.2）。
10. 「收起菜单」直接放在侧栏背景中，上方不使用横线，不做成独立底栏或悬浮卡片（用户管理 UI §9、设计系统 §5.2）。
11. 产品名必须显示为「澄客 CRM」，不得写成「清客 CRM」（用户管理 UI §9）。
12. 收起/展开只改变布局外壳，不清除当前路由，也不清除内容区业务页自己的筛选、选中、分页等状态。
13. 退出登录必须先二次确认。仅当后端退出成功后才回到登录页，并清除当前会话的菜单、权限缓存与访问凭证（登录 PRD §12.9）。退出失败时不得完成本地退出。
14. 本布局不根据 `permissionCodes` 隐藏单个菜单项；菜单可见性以授权上下文的 `menus` 为准。内容区按钮级权限由各业务页处理。
15. 本布局不请求、不展示业务列表数据。
16. 他人改了本账号权限后，侧栏不轮询、不靠用户手动刷新。下一次业务请求若返回 HTTP 409 且编码 `PERMISSION_VERSION_CHANGED`，由 HTTP 层重拉授权上下文（必要时刷新 Token）；本布局只按新的 `menus` 重绘。空闲挂着页面时菜单可以暂时仍是旧的（已确认可接受）。当前页已无权则跳新 `authorizedHome`；`menus` 已空则走 §8.2。

## 8. 条件与决策表

### 8.1 菜单节点如何展示

| 有子节点 | `routeKey` | `routeKey` 在白名单 | 侧栏 | 展示 | 可否导航 |
| --- | --- | --- | --- | --- | --- |
| 任意 | 有 | 是 | 展开 | 图标 + 名称；匹配 URL 时选中 | 是 |
| 任意 | 有 | 是 | 收起 | 仅图标；悬停说明为名称 | 是 |
| 任意 | 有 | 否 | 展开 | 当前实现：不作为链接；若当目录则见下一行 | 否 |
| 任意 | 空 | — | 展开 | 分组标题（名称） | 否 |
| 任意 | 空 | — | 收起 | 不显示该标题 | 否 |
| 有 | 空或未映射 | — | 任意 | 继续渲染子节点 | 子节点各自判断 |

「有 `routeKey` 但不在白名单」时，节点是否仍显示为不可点的文字 **待确认**。当前实现与「无路径」相同：不生成链接。

### 8.2 菜单树为空（已确认：独立「暂无可用功能」页）

条件：已登录，且授权上下文 `menus` 为空数组（前端不得补默认菜单）。对齐登录 PRD §12.10。

| 条件 | 系统行为 | 页面结果 |
| --- | --- | --- |
| `menus` 为空 | 不渲染左侧全局菜单，不渲染本管理端外壳 | 用户看不到空白侧栏 |
| 同上 | 进入独立全屏页 | 不是「框架 + 空菜单」，也不展示「401」字样 |
| 未登录 / 会话无效（HTTP 401） | 不走本分支 | 进入登录页，与本页区分 |

页面正中（垂直、水平居中）展示：

| 区域 | 内容 | 状态 |
| --- | --- | --- |
| 标题 | 「暂无可用功能」 | 已确认 |
| 中间提示 | 「当前账号尚未分配可访问功能，请联系管理员。」位于页面正中。只做说明，不可点击，不打开联系渠道，不复用登录页「联系管理员」入口 | 已确认 |
| 操作 | 「退出登录」：与本布局退出同一条链路（二次确认 → 成功后清会话 → 登录页） | 已确认 |

当前代码仍会进 `AdminLayout` 并显示「当前账号暂无授权菜单」，**与本条已确认规则不符**，实现需改到本页。

### 8.3 权限版本变化后侧栏何时更新（已确认）

条件：本账号仍登录；他人已改过本账号的角色、权限定义、部门范围或状态（停用走会话撤销，不走本条）。

| 条件 | 系统行为 | 页面结果 |
| --- | --- | --- |
| 用户一直挂着页面、没有发业务请求 | 不推送、不轮询 | 侧栏可以暂时仍显示旧菜单（已确认可接受） |
| 下一次业务请求（点菜单、拉列表、保存等） | 后端 HTTP **409**，编码 `PERMISSION_VERSION_CHANGED`，不执行该业务 | HTTP 层重拉 `GET /auth/context`，必要时刷新 Access Token，写入授权状态 |
| 重拉后 `menus` 仍包含当前页 | 重试原请求 | 侧栏换成新菜单，留在当前页 |
| 重拉后当前页已无权、仍有其他菜单 | 跳转到新的授权首页 | 侧栏换成新菜单 |
| 重拉后 `menus` 为空 | 走 §8.2 | 「暂无可用功能」页 |
| 账号被停用 / 会话已撤销 | `SESSION_REVOKED`，不是本条 | 登录页 |

本布局不自己监听版本号、不设定时器。当前代码未处理 409，**与本条不符**。

## 12. API

本布局直接发起的请求只有退出。菜单、用户、租户来自进入布局前已取得的授权上下文。

### 12.1 GET 授权上下文（布局的数据来源，不由布局在渲染时重复发起）

| 项目 | 内容 |
| --- | --- |
| API | `/api/v1/auth/context` |
| Method | GET |
| 用途 | 提供用户、租户、菜单树，供布局展示 |
| 调用时机 | 登录成功后；刷新进入 `/app` 时的会话恢复。**不是**布局每次渲染都调用 |
| 调用条件 | 已有有效会话 |

请求参数：无业务 Query。凭证携带方式见认证约定（当前实现为访问令牌）。

请求示例：无 Body。

响应中本布局实际使用的字段：

| 字段 | 类型 | 说明 | 页面用途 |
| --- | --- | --- | --- |
| `user.id` | string | 用户 ID | 当前实现 Header 不展示 ID |
| `user.displayName` | string | 展示名 | Header 姓名 |
| `user.avatarUrl` | string 或空 | 头像 URL | 当前实现未用于展示 |
| `tenant.id` | string | 租户 ID | 当前实现 Header 不展示 ID |
| `tenant.name` | string | 租户名称 | Header 当前组织 |
| `menus` | 数组 | 菜单树 | 左侧导航 |
| `menus[].id` | string | 节点 ID | 列表稳定标识 |
| `menus[].label` | string | 名称 | 菜单文字 / 收起时说明 |
| `menus[].routeKey` | string 或空 | 路由键 | 映射白名单路径 |
| `menus[].icon` | string 或空 | 图标键 | 映射本地图标 |
| `menus[].children` | 数组 | 子节点 | 递归展示 |

`permissionCodes`、`dataScopes`、`sensitiveFieldPermissions`、`authorizedHome`、`expiresAt` 由会话/路由守卫/业务页使用，本布局当前实现不读取。

响应示例（仅含本布局已消费且契约已存在的字段形状）：

```json
{
  "user": {
    "id": "<user-id>",
    "displayName": "<display-name>",
    "avatarUrl": null
  },
  "tenant": {
    "id": "<tenant-id>",
    "name": "<tenant-name>"
  },
  "menus": [
    {
      "id": "<menu-id>",
      "label": "<label>",
      "routeKey": "dashboard",
      "icon": "dashboard",
      "children": []
    }
  ]
}
```

成功：布局用上述数据渲染；不关闭任何弹窗（无弹窗）。  
失败：发生在进入布局前 → 不能看到本布局（回登录或会话恢复失败）。布局已展示后上下文再失效 **待确认**。

### 12.2 POST 退出登录

契约来源：本机 Swagger `POST /api/v1/auth/logout`（`ApiResponseVoid`），2026-09-05 本地联调核对。

| 项目 | 内容 |
| --- | --- |
| API | `/api/v1/auth/logout` |
| Method | POST |
| 用途 | 撤销当前会话 |
| 调用时机 | 确认弹窗中点击「确认退出」 |
| 调用条件 | 用户处于本布局中（已认证）且已二次确认 |

**请求示例**

```http
POST /api/v1/auth/logout
Authorization: Bearer <access-token>
Accept: application/json
```

无 JSON Body。不传他人用户 ID。

**成功响应示例（HTTP 200）**

```json
{
  "code": "OK",
  "message": "success",
  "data": null,
  "requestId": "<request-id>",
  "timestamp": "<offset-date-time>"
}
```

页面不依赖 `data` 内业务字段。重复退出仍为 HTTP 200。

**失败后**：不执行本地清理与跳转；弹窗展示错误。无令牌或令牌无效时实测 HTTP 401 且无响应体。

成功后：

- 清除访问凭证、业务缓存、会话与权限快照。
- 进入登录页（替换当前历史项）。
- 用户不再看到管理端外壳。

## 15. 权限

| 问题 | 结论 |
| --- | --- |
| 谁可以进入带本布局的页面 | 已认证用户；未认证被挡在布局外 |
| 谁可以看见左侧某菜单 | 授权上下文 `menus` 包含该节点，且若要可点则 `routeKey` 须在白名单 |
| 谁可以看 Header 组织/姓名 | 能看到本布局的用户 |
| 谁可以退出 | 能看到本布局的用户，以及空菜单独立页上的用户；退出不要求业务权限码 |
| 不同权限下按钮是否显示 | 本布局无按权限码显隐的业务按钮；菜单项不按 `permissionCodes` 二次过滤 |
| 数据权限 | 本布局不展示业务列表，不应用数据范围过滤 |

角色名称不得用来推断菜单（登录 PRD）。前端布局不得因「看起来像管理员」而补菜单。

页面级无权限（打开了未授权路由）由路由权限门禁/403 页处理，不是本布局的菜单计算。无权限页是否仍包在本布局内 **待确认**（当前实现 403 在 `/app` 子路由内，因此仍有侧栏）。

## 16. 页面边界情况

| 场景 | 行为 |
| --- | --- |
| Loading | 会话恢复中不展示本布局，展示「正在恢复安全会话…」。布局自身无菜单 Loading。 |
| Empty 菜单 | 见 §8.2：独立「暂无可用功能」页，正中提示联系管理员，可退出登录。当前代码未对齐。 |
| Error（进入前上下文失败） | 不展示本布局。 |
| Error（退出接口失败） | 弹窗展示错误；不清缓存、不离开本布局。 |

| Duplicate 退出 | 后端重复退出仍成功；前端成功后已清令牌。 |

`prefers-reduced-motion` 下侧栏宽度动画是否减弱：设计系统要求支持；当前是否已做 **待确认**。

## 17. 数据联动

授权上下文写入（布局外）→ 用户、租户、菜单变化 → 布局 Header 与侧栏重绘。

当前 URL 变化 → 菜单选中态变化 → 内容区页面变化。侧栏折叠不变。

侧栏折叠变化 → 仅外壳宽度与文字显隐变化。不改菜单数据、不改 URL、不改 Header 姓名/组织、不刷新业务页数据。

退出成功后的本地清理 → 菜单、用户、租户从界面消失（离开布局）。失败则界面不变。

点击菜单 **不会** 重新请求授权上下文。

他人改了本账号权限后：不轮询。下一次业务请求返回 409 `PERMISSION_VERSION_CHANGED` 后，HTTP 层重拉授权上下文；侧栏随新 `menus` 重绘。详见 §8.3。当前代码未处理该信号。

## 18. 数据变更 / 持久化

| 数据 | 谁改 | 何时提交 | 持久化 |
| --- | --- | --- | --- |
| 菜单 / 用户 / 租户 | 用户不能在布局里直接改这些主数据 | 无保存按钮 | 不写入 LocalStorage；来自服务端授权上下文 |

保存失败保留输入：不适用（无表单）。  
草稿：无。

```text
独立全屏页（页面正中）
├── 标题：暂无可用功能
├── 中间提示：当前账号尚未分配可访问功能，请联系管理员。
└── 退出登录 → 同本布局退出链路 → 登录页
```

权限版本变化（已确认，§8.3）：

```text
他人改了本账号权限（会话仍有效）
↓
本账号下一次业务请求
↓
HTTP 409 PERMISSION_VERSION_CHANGED（业务未执行）
↓
GET /auth/context（+ 必要时刷新 Token）
↓
侧栏按新 menus 重绘
├── 当前页仍有权 → 重试原请求
├── 当前页已无权 → 新授权首页
└── menus 为空 → 「暂无可用功能」页
```

未登录 / 会话 401：

```text
无有效会话
↓
登录页（不是空菜单提示页）
```

## 20. 异常处理

| 异常场景 | 页面行为 |
| --- | --- |
| 进入 `/app` 时无有效会话 | 不展示布局，进入登录页 |
| 授权上下文校验失败 | 不能以已认证身份进入布局 |
| 菜单含未知 `routeKey` | 不生成链接，不打开站外地址 |
| 租户或用户摘要缺失 | Header 缺省文案，其余区域照常 |
| 退出接口失败 | 留在本布局；弹窗展示错误；不清除本地会话 |
| 退出过程中再次点击 | 提交中按钮不可用 |
| 业务页自身报错 | 由路由错误页处理；是否仍包在本布局内取决于错误边界挂载位置（当前 `/app` 错误页在布局外一层 **待确认** 与实现是否一致，以实现/路由配置为准） |
| 业务请求 409 `PERMISSION_VERSION_CHANGED` | 不由布局弹 Toast。HTTP 层重拉授权上下文后按 §8.3 更新侧栏或离开当前页 |

不在此自行增加 Toast、全局错误条。布局不轮询菜单；409 由 HTTP 层处理，不是布局组件自己重试。

## 21. 验收标准

### 页面

- [ ] `/app` 下用户、部门、角色、线索等业务页共用同一套左侧菜单 + Header + 内容区，而不是每页各做一套全局导航。
- [ ] 登录页没有该侧栏和 Header。
- [ ] 未登录访问 `/app` 看不到该布局。
- [ ] 侧栏展开 240px、收起 72px，Header 高 68px。
- [ ] 侧栏深色、Header 浅色，底部「收起菜单」上方无横线。
- [ ] 产品名在展开时为「澄客 CRM」。
- [ ] 空菜单时不前端补默认菜单。
- [ ] `menus` 为空时不出现左侧菜单，也不出现带空侧栏的管理端外壳。
- [ ] 空菜单独立页标题为「暂无可用功能」，不展示「401」字样。
- [ ] 页面正中提示为「当前账号尚未分配可访问功能，请联系管理员。」该提示不可点击，不打开联系渠道。
- [ ] 空菜单独立页提供「退出登录」，确认且成功后进入登录页。
- [ ] 未登录（会话 401）进入登录页，不会被空菜单提示页代替。

### 交互

- [ ] 白名单 `routeKey` 可进入对应站内路径，选中态含背景和文字，无左侧 inset 阴影条。
- [ ] 非白名单 `routeKey` 不能变成任意链接。
- [ ] 收起后菜单文字隐藏，可导航项仅图标；再展开后文字恢复；业务页状态不被收起清掉。
- [ ] 点击退出先出现确认弹窗；取消后仍留在管理端。
- [ ] 确认且接口成功后进入登录页，且菜单/权限不能再作为已登录状态使用。
- [ ] 退出接口失败时留在管理端，弹窗展示错误。

### 业务规则

- [ ] 菜单只来自授权上下文，不按角色名推断。
- [ ] 图标只走本地键映射。
- [ ] Header 展示当前组织名与当前用户展示名（或本节规定的缺省文案）。
- [ ] 收到 409 `PERMISSION_VERSION_CHANGED` 后侧栏换成新菜单，不靠用户手动刷新浏览器；空闲未发请求时允许暂时仍显示旧菜单。

### API

- [ ] 布局展示不额外为渲染而重复设计一套菜单接口。
- [ ] 退出只调用退出登录接口，Body 不传他人用户 ID。
- [ ] 仅退出成功后完成本地清理。

### 表单

- [ ] 本布局无业务表单；退出必须二次确认。

## 22. 不包含范围

本布局 Spec **不包含**：

- 登录页、验证码、首次改密页的布局与交互。
- 用户管理组织树、筛选、表格、新增/编辑抽屉（内容区业务，见用户管理 UI/PRD）。
- 部门管理树与详情、角色权限配置、线索列表/线索池的页面内容。
- 按 `permissionCodes` 隐藏表格按钮、脱敏手机号等字段级权限。
- 数据权限过滤业务列表。
- 前端根据角色补「工作台」或其他默认菜单。
- 刷新 Token 的调用时机（非本布局）。
- 全局搜索、通知中心、Header 面包屑——设计有、当前布局无，未确认前不纳入已交付范围。
- 主题切换、密度切换（架构提到 preference，当前布局未做）。
- 移动端完整适配（设计系统声明 <768px 非一期核心）。
- 管理端「强制下线他人设备」。
- 新建数据库表或菜单管理后台。
