## 1. 产品概述

澄客 CRM 是一套面向企业内部业务团队的客户经营与销售过程管理系统。当前产品信息架构包含首页、线索管理、商机管理、客户管理、资源管理和系统管理。

本期 PRD 仅覆盖系统管理中的用户管理模块，用于维护后台账号、部门归属、角色和账号状态，为后续权限控制与业务协作提供基础数据。

## 2. 背景与问题

现有页面已经具备用户查询、新增、批量删除、编辑和删除等基础能力，但存在以下体验与风险问题：

1. 查询条件横向排列过密，标签和占位提示的层级不够清楚。
2. 头像与姓名分列，占用表格空间，不利于快速识别用户。
3. 每一行都展示删除操作，高风险行为过于突出，容易误触。
4. 表格使用完整单元格边框，信息噪音较大，扫描效率偏低。
5. 顶部强渐变和内容区域的企业后台风格不统一。
6. 缺少加载、空数据、失败、无权限和批量操作反馈等完整状态。
7. 原始参考界面使用旧品牌，本项目需要统一展示为“澄客 CRM”。

## 3. 产品目标

### 3.1 本期目标

- 让有权限的管理员能够快速查询、创建、编辑和停用系统用户。
- 让用户身份、部门、角色、状态和联系方式能够在一个页面内清晰呈现。
- 降低停用、删除等高风险操作的误触概率。
- 建立可复用的列表页交互规范，包括筛选、批量操作、分页和状态反馈。
- 为角色权限、部门管理和审计日志模块提供稳定的用户基础数据。

### 3.2 非本期目标

- 不包含部门和角色的创建、编辑逻辑。
- 用户新增和编辑仅允许选择已有角色；角色、功能权限、数据权限和敏感字段权限统一在独立角色管理模块维护。
- 不包含员工入职、离职审批流程。
- 不包含线索、客户或商机的负责人转移流程。
- 不包含单点登录、企业微信、飞书或钉钉同步能力。
- 不包含移动端界面。

## 4. 用户与权限

### 4.1 目标用户

| 用户类型 | 主要诉求 |
| --- | --- |
| 超级管理员 | 管理全部账号、角色和状态，处理异常账号 |
| 系统管理员 | 在授权范围内新增、编辑和停用用户 |
| 部门管理员 | 查看并维护本部门成员，具体权限待确认 |
| 普通用户 | 默认不进入用户管理页面，仅维护个人资料，具体范围待确认 |

### 4.2 建议权限点

| 权限编码建议 | 权限说明 |
| --- | --- |
| `system:user:view` | 查看用户列表和用户详情 |
| `system:user:create` | 新增用户 |
| `system:user:update` | 编辑用户 |
| `system:user:disable` | 停用或启用用户 |
| `system:user:delete` | 删除用户，是否开放待确认 |
| `system:user:export` | 导出用户数据，非本期能力 |
| `system:user:reset-password` | 重置用户密码 |
| `system:user:mobile:full` | 查看完整手机号；无此权限时按脱敏规则展示 |

权限不足时，不展示对应操作入口。直接访问无权限页面时，显示无权限状态，并提供返回首页入口。

### 4.3 权限模型

澄客 CRM 采用 RBAC 角色权限模型，并将权限拆分为功能权限、数据权限和敏感字段权限。三类权限必须同时满足，用户才能完成对应操作。

| 权限层级 | 回答的问题 | 示例 |
| --- | --- | --- |
| 功能权限 | 用户能不能执行某项操作 | 是否可以查看用户列表、编辑用户、停用账号 |
| 数据权限 | 用户可以访问哪些组织范围内的数据 | 仅本人、本部门、本部门及下级、指定部门、全集团 |
| 敏感字段权限 | 用户能看到字段的完整值还是脱敏值 | 手机号完整显示或 `138****8006` |

权限判断顺序如下：

1. 校验账号状态和登录会话是否有效。
2. 校验功能权限，未授权则直接拒绝。
3. 根据角色的数据范围计算允许访问的组织节点集合。
4. 将允许访问的组织节点、本人条件和业务数据归属条件加入服务端查询。
5. 对返回数据执行敏感字段权限处理。
6. 编辑、停用、导出等操作再次校验目标数据是否仍在授权范围内。

前端隐藏按钮仅用于改善体验，不能替代服务端权限校验。

### 4.4 组织树与数据归属

组织结构使用树形模型。集团为根节点，部门为集团或其他部门的子节点。后续如引入子公司，可增加公司节点类型，但所有节点仍使用统一的父子关系计算权限范围。

```text
澄客集团
├── 集团人力资源部
├── 集团财务部
├── 华东事业部
│   ├── 上海销售一部
│   └── 杭州销售部
└── 华南事业部
    └── 广州销售部
```

用户必须归属一个组织节点。业务数据必须保存可用于权限判断的归属字段，不能只依赖创建人的当前部门进行实时反推。

| 数据类型 | 归属字段建议 | 权限判断说明 |
| --- | --- | --- |
| 用户 | `departmentId` | 按用户当前所属部门判断 |
| 线索 | `ownerId`、`ownerDepartmentId` | 同时支持仅本人和部门范围 |
| 客户 | `ownerId`、`ownerDepartmentId` | 负责人变更时同步更新归属部门 |
| 商机 | `ownerId`、`ownerDepartmentId` | 负责人变更时同步更新归属部门 |
| 系统日志 | `operatorId`、`operatorDepartmentId` | 依据操作人所属部门和日志查看权限判断 |

业务数据转移、员工调岗或部门合并时，需要明确归属字段的更新策略，避免历史数据因组织变化意外扩大或缩小可见范围。

### 4.5 数据范围枚举

| 提交值 | 中文名称 | 可访问范围 | 典型角色 |
| --- | --- | --- | --- |
| `self` | 仅本人 | 仅 `ownerId` 等于当前用户的数据 | 普通销售、普通员工 |
| `department` | 仅本部门 | 归属当前部门节点的数据，不包含任何下级节点 | 部门专员、部门内勤 |
| `department_and_descendants` | 本部门及下级 | 当前部门节点和全部后代节点的数据 | 部门经理、事业部负责人 |
| `selected_departments` | 指定部门 | 管理员明确选择的一个或多个部门及配置的下级范围 | 区域运营、跨部门协作角色 |
| `all` | 全集团 | 当前集团租户内所有组织节点的数据 | 超级管理员、经审批的集团审计角色 |

数据范围是稳定枚举，部门和角色仍然是动态数据。`selected_departments` 必须同时保存 `selectedDepartmentIds`，并为每个选择项配置是否包含下级部门。

### 4.6 集团员工能否查看下级部门

结论：不能仅根据“员工挂在集团节点”判断其能查看全部下级部门。组织归属表示员工在哪里，数据范围才表示员工能看哪里。

| 用户示例 | 所属节点 | 数据范围 | 能否查看集团下级部门数据 |
| --- | --- | --- | --- |
| 集团普通员工 | 澄客集团 | `self` | 不能，只能查看本人负责的数据 |
| 集团内勤 | 澄客集团 | `department` | 不能，只能查看直接归属集团根节点的数据 |
| 集团人力管理员 | 集团人力资源部 | `selected_departments` | 仅能查看被授权的部门，可按配置包含下级 |
| 华东事业部负责人 | 华东事业部 | `department_and_descendants` | 可以查看华东事业部及其全部下级，不能查看华南事业部 |
| 集团审计员 | 澄客集团 | `all` | 可以只读查看全集团数据，能否编辑由功能权限决定 |
| 超级管理员 | 澄客集团 | `all` | 可以查看全集团数据，并按功能权限执行管理操作 |

因此，如果某个集团员工需要查看集团下面所有部门，必须显式授予 `all`，或在集团根节点授予 `department_and_descendants`。普通员工默认建议使用 `self`，不能利用其处于根节点的组织位置自动扩权。

### 4.7 角色权限配置规则

本节定义用户管理依赖的权限契约；角色创建、编辑、成员维护和权限树交互以[角色管理模块 PRD v0.3](../../role-management/docs/PRD-role-management-v0.3.md)为准。

每个角色至少包含以下配置：

| 配置项 | 字段建议 | 说明 |
| --- | --- | --- |
| 角色名称 | `name` | 角色管理界面显示名称 |
| 功能权限 | `permissionCodes` | 目录、页面和操作权限编码集合；接口由后端映射操作权限 |
| 数据范围 | `dataScope` | 取 4.5 节的数据范围枚举 |
| 指定部门 | `selectedDepartmentIds` | 仅 `selected_departments` 时必填 |
| 是否包含下级 | `includeDescendants` 或逐项配置 | 指定部门是否自动包含其后代节点 |
| 敏感字段权限 | `fieldPermissionCodes` | 完整手机号、邮箱和客户联系方式等字段权限编码集合 |
| 角色状态 | `status` | 正常或已停用；已停用角色不可分配给新用户 |

v1.0 一个用户只分配一个角色，用户直接继承该角色的功能权限和数据范围，不支持用户级权限扩展。这样可以避免大量不可追踪的个人例外。

后续如果支持多角色，同一资源的数据范围默认按并集计算，但必须受“授权人不得授予高于自身权限”的规则约束，并记录完整审计日志。

### 4.8 授权边界与防越权规则

- 管理员只能查看和选择自己数据范围内的部门。
- 管理员只能创建或编辑自己数据范围内的用户。
- 管理员不能给他人分配自己不拥有的功能权限或更大的数据范围。
- 管理员不能把用户移动到自己无权管理的部门。
- 管理员不能通过批量操作绕过单条操作的权限校验。
- 当前登录用户不能修改自己的角色、数据范围或账号状态。
- 唯一超级管理员不能被降权、停用或删除。
- `all` 权限只能由超级管理员授予，并记录授予前后权限差异。
- 部门移动、角色变更和用户调岗后，权限缓存必须立即失效或在可接受的极短时间内失效。
- 导出数据时必须复用列表查询的数据权限和敏感字段权限，不允许使用独立的宽松查询。

### 4.9 用户管理页的数据权限行为

| 场景 | 页面行为 |
| --- | --- |
| 进入用户列表 | 服务端仅返回当前管理员数据范围内的用户 |
| 组织树 | 只展示当前管理员可查看的组织节点、祖先路径和权限范围内人数 |
| 新增用户 | 部门选择器只展示当前管理员可管理的节点 |
| 分配角色 | 仅展示当前管理员有权授予且状态正常的角色 |
| 编辑用户 | 目标用户不在当前权限范围内时返回无权限，不回传用户详情 |
| 批量停用 | 每个用户独立校验；默认允许部分成功并返回失败原因 |
| 查看手机号 | 有 `system:user:mobile:full` 时显示完整号码，否则显示脱敏号码 |
| 查看总数 | 总数仅统计当前数据权限范围内的结果，不能泄露全集团用户数量 |

用户从当前管理员可见部门调往不可见部门后，应立即从列表中消失。管理员打开编辑抽屉期间若目标用户被调离授权范围，保存时服务端必须拒绝并提示“该用户已不在你的管理范围内”。

## 5. 信息架构

```text
系统管理
├── 部门管理
├── 角色管理
├── 用户管理
└── 系统日志
```

用户管理页由以下区域组成：

1. 全局侧边导航
2. 顶部栏与面包屑
3. 独立组织架构卡片
4. 人员筛选卡片
5. 用户列表卡片
6. 列表上下文与操作工具栏
7. 用户数据表格
8. 分页区

顶部面包屑是页面唯一定位信息，主体不重复展示“用户管理”标题和说明。用户管理与角色管理为两个独立路由和业务模块，不使用页内 Tab 混合配置。

## 6. 核心用户流程

### 6.1 查询用户

1. 管理员进入“系统管理 / 用户管理”。
2. 系统恢复上次选择且仍有权限的组织节点；首次进入时默认选择管理员所属部门。
3. 左侧组织树加载管理员有权查看的集团和部门节点。
4. 管理员点击目标组织节点，右侧列表加载该组织人员。
5. 管理员可在“仅当前部门”和“包含下级部门”之间切换。
6. 管理员输入姓名、用户名或手机号关键词，或选择账号状态。
7. 点击“查询”或在关键词输入框中按 Enter。
8. 系统返回符合当前组织、数据范围和筛选条件的用户，并回到第 1 页。
9. 管理员可点击“重置”清除人员筛选条件，但保留当前组织节点和数据范围选择。

### 6.2 新增用户

1. 管理员点击“新增用户”。
2. 系统打开新增用户表单，形式建议为右侧抽屉。
3. 管理员填写必填字段并提交。
4. 系统完成字段校验和唯一性校验。
5. 创建成功后关闭抽屉，刷新列表，并提示“用户创建成功”。
6. 创建失败时保留已填写内容，并在对应字段或表单顶部说明原因。

### 6.3 编辑用户

1. 管理员点击某一行的“编辑”。
2. 系统打开编辑抽屉并回填当前数据。
3. 管理员修改允许编辑的字段并保存。
4. 保存成功后刷新当前行并提示“用户信息已更新”。
5. 若数据已被其他管理员修改，系统提示刷新后重试，具体并发策略待技术评审。

### 6.4 停用用户

1. 管理员勾选一个或多个正常用户。
2. “批量停用”按钮变为可用。
3. 管理员点击按钮后，系统弹出二次确认对话框。
4. 对话框说明停用影响，并展示选中人数。
5. 管理员确认后，系统执行停用并返回成功、失败数量。
6. 停用成功的用户状态更新为“已停用”。

### 6.5 启用用户

1. 管理员打开已停用用户行的更多操作菜单。
2. 点击“启用账号”。
3. 系统二次确认后恢复账号状态。
4. 操作成功后刷新当前行并记录审计日志。

## 7. 页面功能需求

### 7.1 全局导航与顶部栏

| 编号 | 需求 |
| --- | --- |
| NAV-01 | 左侧导航展示产品名称“澄客 CRM”。 |
| NAV-02 | “系统管理”默认展开，“用户管理”显示选中状态。 |
| NAV-03 | 顶部面包屑显示“系统管理 / 用户管理”。 |
| NAV-04 | 顶部右侧显示全局搜索、通知、当前用户头像、姓名和角色。 |
| NAV-05 | 退出登录放入用户下拉菜单，不作为顶部常驻文字操作。 |
| NAV-06 | 支持收起侧边栏，收起状态是否缓存待确认。 |
| NAV-07 | “收起菜单”固定在侧栏底部，使用双箭头图标和文字标签，点击后切换为 72px 收起侧栏。 |
| NAV-08 | “收起菜单”直接使用侧栏背景和 Ghost 菜单行，不设置顶部横向分隔线、独立 Footer 表面、卡片或阴影。 |
| NAV-09 | 收起入口默认使用侧栏次级文字色，Hover、Focus 和按下状态必须可辨识；图标按钮具有 Tooltip、`aria-label` 和足够点击热区。 |

### 7.2 组织树导航区

组织树位于内容主区域左侧，仅展示集团、公司和部门节点，不在树内直接展示人员。人员始终在右侧表格中管理。

#### 7.2.1 布局规格

| 项目 | 规格 | 说明 |
| --- | --- | --- |
| 组织树卡片宽度 | 280px | 独立卡片，与右侧用户工作区间隔 16px |
| 卡片最小高度 | 与右侧筛选卡片和列表卡片总高度对齐 | 内容超出时卡片内部滚动 |
| 卡片标题 | “组织架构” | 标题右侧展示收起与刷新按钮 |
| 搜索框 | 卡片内容区满宽，高 40px | 占位提示“搜索部门” |
| 树节点行高 | 40px | 满足点击面积与扫描效率 |
| 层级缩进 | 每级 20px | 展开图标、节点图标、名称和人数保持对齐 |
| 选中状态 | 浅蓝背景、蓝色文字 | 整行高亮，不仅高亮节点名称 |
| 人数 | 节点右侧弱化数字 | 表示当前管理员权限范围内该节点及其下级的用户总数 |

#### 7.2.2 节点与展开规则

| 编号 | 需求 |
| --- | --- |
| TREE-01 | 根节点展示集团名称，例如“澄客集团”。 |
| TREE-02 | 有子节点时展示展开图标，无子节点时保留对齐空间但不展示无效图标。 |
| TREE-03 | 点击展开图标只切换展开状态；点击节点名称选择该组织。 |
| TREE-04 | 首次进入默认展开当前用户所属节点的祖先路径。 |
| TREE-05 | 组织层级较多时按节点懒加载子节点，已加载节点在当前会话内缓存。 |
| TREE-06 | 搜索部门时展示匹配节点及其完整祖先路径，并高亮匹配文字。 |
| TREE-07 | 清空搜索后恢复搜索前的展开和选中状态。 |
| TREE-08 | 节点人数只统计管理员有权查看的用户，不能泄露无权限部门人数。 |
| TREE-09 | 当前选中节点被停用、删除或移出权限范围后，自动回退到最近的可见祖先节点。 |
| TREE-10 | 不允许在组织树中直接勾选人员或执行停用、编辑等人员操作。 |

#### 7.2.3 当前组织与数据范围

当前组织上下文在用户列表卡片头部展示，例如“华东事业部，共 56 位用户”。完整祖先路径由组织树选中状态和 Tooltip 提供，避免在筛选区重复占用一整行。

筛选卡片提供数据范围切换：

| 选项 | 含义 | 可用条件 |
| --- | --- | --- |
| 仅当前部门 | 仅查询归属当前节点的用户 | 所有可查看组织节点均可使用 |
| 包含下级部门 | 查询当前节点及所有可见后代节点的用户 | 当前节点存在可见下级且管理员拥有对应数据权限 |

默认值为“仅当前部门”。用户切换组织节点时保留当前范围选择；如果新节点没有可见下级，自动切换到“仅当前部门”并禁用“包含下级部门”。切换范围后清空已勾选人员并回到第 1 页。

筛选区使用独立卡片。宽屏单行展示关键词、状态、数据范围、重置和查询；中等宽度允许换为两行，但不得压缩到无法识别或遮挡按钮。

| 编号 | 字段 | 控件 | 规则 |
| --- | --- | --- | --- |
| FILTER-01 | 关键词 | 文本输入框 | 支持姓名和用户名模糊查询；手机号查询规则待确认；前后空格自动去除 |

| FILTER-03 | 查询 | 主按钮 | 在当前组织和数据范围内执行查询并回到第 1 页 |
| FILTER-04 | 重置 | 次按钮 | 清空关键词和状态，保留当前组织节点和数据范围 |

交互要求：

- 查询期间按钮进入加载状态，避免重复提交。
- 关键词输入框支持 Enter 查询，占位提示为“姓名 / 用户名 / 手机号”。
- 已使用的筛选条件在分页和编辑返回后保持不变。
- 是否需要将筛选条件同步到 URL，待技术方案确认。

### 7.4 操作工具栏

| TOOL-06 | 工具栏右侧提供刷新列表和表格设置图标按钮，并展示 Tooltip。 |

### 8.1 表单容器与尺寸规范

| 单行控件高度 | 40px | 文本框、选择器、密码框统一高度 |
| 单行控件宽度 | 100%，内容区约 512px | 不使用内容长度决定控件宽度 |

抽屉标题分别为“新增用户”和“编辑用户”。底部操作区固定在抽屉底部，左侧为“取消”，右侧为“创建用户”或“保存修改”。

### 8.2 新增用户字段

| 顺序 | 字段 | 字段键建议 | 必填 | 控件 | 尺寸 | 默认值 | 输入与校验规则 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 头像 | `avatarUrl` | 否 | 图片上传 | 80px × 80px | 姓名首字占位头像 | 支持 JPG、JPEG、PNG、WebP；单文件不超过 2MB；推荐 1:1；上传后裁剪为正方形 |
| 2 | 姓名 | `name` | 是 | 文本输入框 | 512px × 40px | 空 | 2-30 个字符；去除首尾空格；允许中文、英文、空格和间隔号；不允许纯空格或控制字符 |
| 3 | 用户名 | `username` | 是 | 文本输入框 | 512px × 40px | 空 | 4-32 个字符；必须以英文字母开头；仅允许字母、数字、点、下划线和连字符；忽略大小写做唯一性校验 |

| 8 | 账号状态 | `status` | 是 | 单选按钮组 | 内容自适应，高 40px | 正常 | 选项为“正常”和“已停用”；新增时允许创建停用账号 |
| 9 | 初始密码 | `initialPassword` | 是 | 密码输入框 | 512px × 40px | 空 | 8-32 个字符；至少包含字母、数字、特殊字符中的两类；不允许包含连续空格；支持显示与隐藏密码 |

| 11 | 首次登录修改密码 | `forcePasswordChange` | 是 | 开关 | 高 24px | 开启 | 开启后，用户首次成功登录必须设置新密码后才能进入系统 |

编辑表单复用新增表单的基础字段，但必须遵守以下差异：

| 顺序 | 字段 | 编辑状态 | 控件与尺寸 | 规则 |
| --- | --- | --- | --- | --- |
| 1 | 头像 | 可编辑 | 80px × 80px 图片上传 | 沿用新增校验；删除头像后恢复姓名首字占位头像 |
| 2 | 姓名 | 可编辑 | 512px × 40px 文本输入框 | 沿用新增校验 |
| 3 | 用户名 | 只读 | 512px × 40px 只读输入框 | v1.0 创建后不可修改；展示只读原因“用户名创建后不可修改” |
| 4 | 手机号 | 可编辑 | 512px × 40px 手机号输入框 | 沿用新增校验；唯一性校验排除当前用户 |
| 5 | 邮箱 | 可编辑 | 512px × 40px 邮箱输入框 | 沿用新增校验 |

| 7 | 角色 | 可编辑 | 512px × 40px 单选器 | 沿用新增规则；当前角色已停用时仍展示原值并要求改选有效角色后才能保存 |
| 8 | 账号状态 | 可编辑 | 高 40px 单选按钮组 | 当前登录用户本人和系统唯一超级管理员不可改为“已停用” |

### 8.4 枚举与动态选项

#### 8.4.1 固定枚举

| 枚举名称 | 字段键 | 提交值 | 中文显示 | 使用位置 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 用户状态 | `status` | `active` | 正常 | 新增、编辑、筛选、列表 | 用户可正常登录并使用授权功能 |
| 用户状态 | `status` | `disabled` | 已停用 | 新增、编辑、筛选、列表 | 用户不可登录；历史业务数据继续保留 |
| 是否强制改密 | `forcePasswordChange` | `true` | 开启 | 新增、重置密码 | 下次登录必须修改密码 |
| 是否强制改密 | `forcePasswordChange` | `false` | 关闭 | 新增、重置密码 | 下次登录无需修改密码 |

固定枚举由前后端共享稳定编码。前端不提交“正常”“已停用”等中文显示值，后端也不使用中文作为枚举键。

筛选项中的“全部”是查询界面的空条件，不属于用户状态枚举。选择“全部”时，请求不传 `status`，不得传递 `all` 作为用户状态。

#### 8.4.2 动态选项

| 选项 | 值 | 显示文本 | 数据来源 | 过滤规则 |
| --- | --- | --- | --- | --- |
| 部门 | `departmentId` | 部门名称 | 部门管理接口 | 仅展示管理员有权分配且状态可用的部门 |
| 角色 | `roleId` | 角色名称 | 角色管理接口 | 仅展示管理员有权分配且状态可用的角色 |

部门和角色不是固定枚举，禁止在前端写死。接口需要同时返回稳定 ID 与中文名称，提交时只传 ID。

### 8.5 字段联动与校验时机

| 场景 | 规则 |
| --- | --- |
| 输入姓名 | 头像为空时，根据姓名首个有效字符更新占位头像预览 |
| 用户名失焦 | 前端先校验格式，格式通过后调用唯一性校验；输入未变化时不重复请求 |
| 手机号失焦 | 前端先校验 11 位手机号，格式通过后调用唯一性校验 |
| 切换部门 | 不自动清空或修改角色；如未来角色限制部门范围，再补充联动规则 |
| 选择已停用状态 | 若为当前用户本人或唯一超级管理员，立即阻止并说明原因 |
| 初始密码变化 | 实时展示密码强度规则是否满足；确认密码已填写时同步校验一致性 |
| 提交表单 | 执行全量前端校验，通过后提交；服务端必须再次执行格式、唯一性、权限和保护账号校验 |

唯一性校验接口失败或超时时，不得默认视为校验通过。用户可重试，表单保留当前输入。

### 8.6 表单交互与状态

- 抽屉打开后，焦点移动到标题或第一个可编辑字段；关闭后焦点返回触发按钮。
- 编辑数据加载期间展示匹配表单结构的骨架屏，不展示空白表单。
- 抽屉关闭前，如存在未保存修改，需要二次确认。
- 字段失焦时执行格式和唯一性校验，提交时执行完整校验。
- 错误信息显示在对应字段下方，服务端通用错误显示在表单顶部。
- 第一次提交失败时，自动聚焦或滚动到第一个错误字段。
- 提交期间禁用关闭、取消和重复提交，按钮文字显示“创建中”或“保存中”。
- 创建或修改成功后，记录操作人、操作时间和变更内容。
- 编辑提交只发送发生变化的字段，具体采用 PATCH 或完整更新由接口设计决定。

### 8.7 新增用户验收场景

- [ ] 必填字段为空时不能提交，并在对应字段下方显示错误。
- [ ] 用户名不符合格式或已存在时不能提交。
- [ ] 手机号格式错误或已存在时不能提交。
- [ ] 两次密码不一致时不能提交。
- [ ] 部门或角色已停用时不能提交。
- [ ] 创建成功后关闭抽屉、刷新列表，并清除密码字段。
- [ ] 创建失败后保留除密码安全策略要求外的已填写内容。

### 8.8 编辑用户验收场景

- [ ] 编辑表单正确回填用户资料，用户名保持只读。
- [ ] 编辑表单不展示初始密码和确认密码字段。
- [ ] 当前登录用户不能停用自己。
- [ ] 系统唯一超级管理员不能被停用。
- [ ] 未修改任何字段时，“保存修改”按钮保持禁用。
- [ ] 保存成功后刷新当前行，并保持原筛选条件和分页位置。
- [ ] 数据加载、保存失败和并发冲突均有可恢复的反馈。

## 9. 状态与反馈

### 9.1 加载状态

- 首次进入页面时，表格展示与最终行结构一致的骨架屏。
- 查询和分页时保留表头，表格内容进入加载状态。
- 加载期间不清空已有筛选条件。
- 组织树首次加载时在树区域展示节点骨架，不阻塞页面标题和顶部栏。
- 懒加载子节点时仅在对应节点下方显示局部加载反馈，不刷新整棵树。

### 9.2 空数据状态

- 无任何用户时：提示“暂无用户”，并在有权限时提供“新增用户”入口。
- 筛选无结果时：提示“未找到符合条件的用户”，并提供“重置筛选”入口。
- 当前组织无直属人员时：提示“当前部门暂无直属人员”；若存在可见下级，提供“查看下级部门人员”入口。
- 管理员无任何可见组织节点时：组织树显示“暂无可查看的组织”，右侧不发起用户列表请求。

### 9.3 错误状态

- 列表加载失败时，在表格区域显示错误说明和“重新加载”按钮。
- 组织树加载失败时，在左侧面板显示错误说明和“重新加载组织”按钮，右侧保持不可用状态。
- 单个树节点的子节点加载失败时，仅在该节点下方提供重试入口。
- 提交失败时保留用户输入，不自动关闭表单。
- 批量操作部分失败时，展示成功数、失败数和失败原因摘要。
- 网络超时使用清晰的可重试提示，不仅依赖短暂 Toast。

### 9.4 操作反馈

- 创建、编辑、启用和停用成功后显示简短成功提示。
- 删除、停用等高风险操作必须二次确认。
- 所有按钮应具备悬停、按下、禁用和键盘聚焦状态。

## 11. 审计与安全要求

- 新增、编辑、启用、停用、重置密码和删除操作必须写入系统日志。
- 日志至少包含操作人、目标用户、操作类型、操作时间和操作结果。
- 密码不得以明文展示、存储或写入日志。
- 手机号是否脱敏应由权限和合规策略决定。
- 后端必须再次验证权限，不能只依赖前端隐藏按钮。
- 停用账号后，已有会话是否立即失效待安全方案确认。
- 删除能力上线前必须确定软删除、数据保留和业务数据归属策略。

## 12. 非功能需求

### 12.1 性能

- 常规网络环境下，用户列表首屏目标在 2 秒内完成可用渲染。
- 查询、分页和状态切换应避免重复请求。
- 列表数据量较大时必须使用服务端分页，不一次性加载全部用户。
- 组织树默认只加载根节点、当前用户祖先路径和必要的首层节点，其余节点按展开操作懒加载。
- 已加载组织节点和人数可在当前会话内缓存；组织变更事件发生后必须使相关缓存失效。
- 组织树搜索使用服务端检索并返回完整祖先路径，不能要求前端先加载整棵组织树。

### 12.2 可用性与无障碍

- 正文和交互文字满足 WCAG AA 对比度要求。
- 不能只用颜色表达账号状态，应同时展示状态文字。
- 表单、按钮、下拉菜单和表格选择框支持键盘操作。
- 焦点状态清晰可见。
- 图标按钮提供可访问名称或悬停说明。

### 12.3 兼容性

- 优先支持最近两个主要版本的 Chrome 和 Edge。
- 设计基准宽度为 1440px。
- 内容宽度 ≥1440px 时组织树默认展开为 280px。
- 内容宽度 1200–1439px 时恢复用户上次展开或收起状态。
- 内容宽度 1024–1199px 时组织树默认收起，通过“组织架构”按钮临时打开。
- 内容宽度 <1024px 时组织树通过 Drawer 打开，表格允许受控横向滚动。
- 任何宽度都必须保留用户列和操作列，不采用把主要操作裁出可视区的方案。

## 13. 埋点建议

本期埋点主要用于验证功能使用情况，不采集输入框中的姓名或手机号明文。

| 事件建议 | 触发时机 | 关键参数 |
| --- | --- | --- |
| `user_list_view` | 进入用户管理页 | 来源页面 |
| `organization_node_select` | 选择组织节点 | 节点层级、节点类型，不记录部门名称 |
| `organization_scope_change` | 切换仅当前部门或包含下级 | 范围类型、结果数量 |
| `organization_search` | 搜索组织节点 | 是否有结果，不记录搜索词原文 |
| `user_search` | 执行查询 | 使用了哪些筛选项，不记录具体值 |
| `user_create_submit` | 提交新增表单 | 成功或失败、失败类型 |
| `user_update_submit` | 提交编辑表单 | 成功或失败、修改字段类型 |
| `user_status_change` | 启用或停用用户 | 操作类型、数量、结果 |
| `user_batch_action` | 执行批量操作 | 操作类型、选择数量、结果 |

是否需要埋点及事件命名规范，以项目现有分析体系为准。

## 14. 验收标准

### 14.1 列表与查询

- [ ] 进入页面后可以正确加载用户列表、总数和分页信息。
- [ ] 组织树仅展示管理员权限范围内的节点和人数。
- [ ] 首次进入默认选中管理员所属部门，并展开其祖先路径。
- [ ] 点击组织节点后，右侧用户列表、总数和分页同步更新。
- [ ] “仅当前部门”不包含下级，“包含下级部门”只包含有权限的后代节点。
- [ ] 组织树搜索可以定位匹配节点并展示完整祖先路径。
- [ ] 关键词和状态筛选可以单独或组合生效。
- [ ] 点击“重置”后清除人员筛选条件，但保留当前组织节点和数据范围。
- [ ] 查询和重置后分页位置符合需求。
- [ ] 切换组织节点或数据范围后清空已勾选人员并回到第 1 页。
- [ ] 加载、空数据、失败和无权限状态均有明确反馈。

### 14.2 用户操作

- [ ] 有权限的管理员可以新增和编辑用户。
- [ ] 表单校验失败时展示明确错误且保留已填写内容。
- [ ] 未选择用户时批量操作不可点击。
- [ ] 停用和启用操作需要二次确认并正确刷新状态。
- [ ] 当前登录用户和唯一超级管理员受到保护。
- [ ] 部分失败的批量操作可以明确指出失败数量和原因。

### 14.3 权限与安全

- [ ] 不同角色只能看到其权限范围内的页面、数据和操作。
- [ ] 无权限接口请求被服务端拒绝。
- [ ] 集团根节点普通员工不会因组织位置自动获得全部下级部门数据。
- [ ] `department` 只包含当前部门，`department_and_descendants` 才包含下级部门。
- [ ] `selected_departments` 只包含明确选择的部门及其配置的下级范围。
- [ ] 用户列表、筛选部门、结果总数和导出数据使用相同的数据权限范围。
- [ ] 管理员不能创建、移动或编辑自己数据范围之外的用户。
- [ ] 管理员不能给他人分配高于自身的功能权限或数据范围。
- [ ] 无手机号完整查看权限时，列表和详情均返回脱敏号码。
- [ ] 角色变更、部门调动和组织树调整后，旧权限缓存及时失效。
- [ ] 关键用户操作均生成可追溯的系统日志。
- [ ] 密码仅能在受控密码输入框中短暂输入，不以明文回填，也不进入列表、详情、日志或埋点。

### 14.4 界面一致性

- [ ] 产品名称统一为“澄客 CRM”。
- [ ] 侧栏底部“收起菜单”直接融入侧栏背景，上方没有横向分隔线，也没有独立底栏或卡片效果。
- [ ] “收起菜单”的图标、文字、Hover、Focus、按下状态和键盘操作符合全局导航规范。
- [ ] 左侧组织树宽度、节点行高、层级缩进和右侧表格对齐符合统一规格。
- [ ] 组织树、筛选和用户列表使用三个层级清晰的独立卡片，页面不再使用单一联合大边框。
- [ ] 组织树在不同断点按展开、记忆、默认收起和 Drawer 规则工作，状态切换不丢失筛选条件。
- [ ] 人员不会直接混入组织树，组织树只承担组织定位和范围切换。
- [ ] 用户管理与角色管理使用独立页面；用户页只能分配已有角色，不能修改角色权限。
- [ ] 用户信息合并展示头像、姓名和用户名。
- [ ] 高风险操作收纳在更多菜单中，不长期使用红色文字占据主视觉。
- [ ] 表格、表单、按钮和状态标签符合统一颜色与圆角规范。
- [ ] 页面在 1280px 及以上桌面视口中可正常使用。

## 15. 待确认项

以下事项会影响最终范围、交互或接口设计，需要在进入开发前确认：

1. 组织树是否需要在 v1.0 区分集团、子公司和部门三种节点类型。
2. 子公司之间是否默认完全隔离，集团级角色能否跨公司授权。
3. v1.0 已按单部门、单角色设计，后续是否升级为多部门或多角色。
4. 线索、客户和商机的归属部门以负责人当前部门为准，还是保留创建时部门。
5. 员工调岗后，历史业务数据自动随人转移、留在原部门，还是进入交接流程。
6. 手机号查询是精确匹配还是模糊匹配。
7. 哪些角色默认拥有手机号完整查看权限。
8. 初始密码的线下交付方式，以及后续是否接入短信、邮件或单点登录激活。
9. 停用账号后，当前登录会话是否立即强制退出。
10. 停用前是否必须转移线索、客户、商机等业务数据。
11. 是否保留删除用户能力；如保留，采用软删除还是物理删除。
12. 用户列表是否需要列设置、密度切换、排序和导出。
13. 是否接入单点登录或第三方组织通讯录。
14. 侧边栏收起状态是否需要本地缓存或账号级同步。
