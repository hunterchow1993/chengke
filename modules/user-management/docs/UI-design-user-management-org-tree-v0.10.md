## 1. 页面目标与设计结论

本页帮助集团或部门管理员先确定组织范围，再检索和维护该范围内的系统用户。页面采用以下已确认方案：

- 左侧组织树使用独立卡片，右侧筛选区和用户列表分别使用独立卡片。
- 组织树只承担组织定位，不在树中混排人员；人员统一在右侧列表中管理。
- 宽屏保留组织树的高效定位能力，中等宽度允许折叠，小屏通过 Drawer 临时打开。
- Header 面包屑是唯一页面标题，不重复展示“用户管理”和说明文案。
- 用户管理只允许选择已有角色；角色、菜单权限和数据权限在独立角色管理模块维护。

Vben 的“左树右表”和角色独立路由值得借鉴，但不复制其多页签 Header、密集筛选项和中等宽度下的横向裁切。

侧栏底部收起入口参考 Vben 的轻量处理：不使用横向分隔线，也不形成独立底栏；入口直接融入深色侧栏背景，通过图标、文字和 Hover 状态表达可操作性。

## 2. 信息架构

```text
管理端框架
├── 左侧全局菜单
├── 顶部 Header
│   ├── 系统管理 / 用户管理
│   └── 搜索、通知、账号
└── 页面内容区
    ├── 组织架构卡片
    │   ├── 标题、收起、刷新
    │   ├── 部门搜索
    │   └── 组织树
    └── 用户工作区
        ├── 筛选卡片
        └── 用户列表卡片
            ├── 列表上下文与操作
            ├── 表格
            └── 分页
```

## 3. 桌面端布局

- 使用 `MASTER` 定义的应用侧栏、Header、页面背景和内容边距。
- Header 下方 20–24px 直接进入内容区，不保留重复标题所产生的空白。
- 内容区使用两列 Grid：左列 280px，右列 `minmax(0, 1fr)`，列间距 16px。
- 左侧组织卡片与右侧工作区顶部对齐；卡片使用同一边框、圆角和背景 Token。
- 右侧工作区由筛选卡片和列表卡片组成，垂直间距 16px。
- 筛选卡片保持单行紧凑布局；列表卡片承载标题、操作、表格和分页，不与筛选区共用一个大边框。

## 4. 组织架构卡片

### 4.1 卡片头部

- 左侧标题为“组织架构”。
- 右侧依次放置收起组织树和刷新图标按钮，均使用 Lucide 图标及 Tooltip。
- 收起只改变页面布局，不清除当前组织、筛选条件、展开节点和分页状态。

### 4.2 搜索与节点

- 部门搜索占满卡片内容宽度，占位提示为“搜索部门”。
- 集团、事业部和部门通过缩进、展开箭头和 `Building2` 表达层级。
- 箭头只切换展开状态；名称所在整行用于选择组织。
- 当前节点使用 `--primary-subtle` 选中面，人数在最右侧弱化显示并使用等宽数字。
- 搜索命中时显示祖先路径并高亮匹配文字；清空后恢复搜索前的展开状态。

## 5. 用户工作区

### 5.1 筛选卡片

桌面宽屏采用一行布局，字段顺序固定为：

1. 关键词：姓名、用户名或手机号。
2. 状态：全部、正常、已停用。
3. 数据范围：仅当前部门、包含下级部门。
4. 重置：次按钮。
5. 查询：主按钮。

“包含下级部门”不可用时显示禁用态并提供原因 Tooltip。Enter 触发查询；查询、重置、组织切换和范围切换均遵循 PRD 的分页与勾选清理规则。

### 5.2 用户列表卡片头部

- 左侧主标题为“用户列表”。
- 主标题下方或右侧以弱化文字显示当前上下文，例如“华东事业部，共 56 位用户”。
- 右侧操作顺序为：新增用户、批量停用、刷新、表格设置。
- “新增用户”是唯一主按钮；未选择人员时“批量停用”禁用。
- 刷新和表格设置使用图标按钮，分别提供“刷新列表”和“表格设置”Tooltip。

### 5.3 表格与分页

- 列顺序：选择框、用户、部门、角色、手机号、状态、最近更新、操作。
- 用户列使用头像、姓名和用户名两行结构。
- 表头高 48px；本页数据行高采用 60px，作为介于默认与紧凑模式之间的业务列表规格。
- 手机号和时间使用等宽数字；完整或脱敏值由后端敏感字段权限决定。
- “编辑”为常用操作；停用、启用、重置密码放入 `Ellipsis` 更多菜单。
- 分页位于卡片底部右侧，总数与每页条数在页码之前展示。

### 5.4 新增与编辑抽屉

- 新增和编辑统一使用 560px 右侧 Drawer，打开时保留用户列表上下文并使用全局遮罩。
- Header 和 Footer 固定，表单主体独立滚动；Footer 右侧依次为次按钮和主按钮。
- 表单保持单列、常驻 Label、40px 控件和 20px 字段间距，不为追求单屏展示压缩为两列。
- 新增字段较多，以[上半段](../prototypes/user-create-drawer-v1.png)和[下半段](../prototypes/user-create-drawer-security-v1.png)两个滚动状态共同表达完整表单。
- 新增默认“账号状态”为“正常”，“首次登录修改密码”为开启；密码只显示空输入和规则，不出现明文示例。
- 编辑态使用“周八 / zhouba”作为示例，用户名为只读，并显示“用户名创建后不可修改”。
- 编辑态不展示初始密码、确认密码和首次登录改密；密码操作必须进入独立的“重置密码”流程。
- 修改部门或角色时使用信息提示说明保存后权限更新，不在用户抽屉内展示角色权限配置。

## 6. 角色管理边界

- 用户新增和编辑抽屉只展示当前管理员有权授予且状态正常的角色。
- 用户页不能创建角色、修改角色权限或修改数据范围。
- 需要维护角色时进入“系统管理 / 角色管理”独立页面。
- 用户列表中的角色名称只用于识别和筛选，不提供内联权限编辑入口。

## 7. 响应式规则

| 内容宽度 | 组织树行为 | 用户工作区行为 |
| --- | --- | --- |
| ≥1440px | 默认展开，宽 280px | 筛选单行，展示完整核心列 |
| 1200–1439px | 恢复用户上次展开或收起状态 | 必要时隐藏低优先级列，不裁切主要操作 |
| 1024–1199px | 默认收起，在列表区域提供“组织架构”按钮 | 筛选允许换为两行，表格保留用户与操作列 |
| <1024px | 通过左侧 Drawer 打开，选择节点后可自动关闭 | 表格受控横向滚动；非一期移动端优化范围 |

组织树展开状态可以存入本地偏好；当前组织和权限范围必须以服务端返回为准。切换设备或权限变化时，不得因为恢复旧状态访问无权节点。

## 8. 页面状态

| 状态 | 页面处理 |
| --- | --- |
| 首次加载 | 组织树、筛选和表格按区域展示结构一致的 Skeleton |
| 组织为空 | 组织卡片提示“暂无可查看的组织”，用户列表不发起请求 |
| 部门无用户 | 保留筛选条件和列表头，展示“该部门暂无用户” |
| 筛选无结果 | 展示筛选摘要和“清空筛选”操作 |
| 局部请求失败 | 失败区域内展示原因和重试，不遮挡整页 |
| 无权限 | 不渲染受限字段和操作，显示无权限状态与返回入口 |
| 批量操作 | 展示选择数量，并反馈成功数、失败数及失败原因 |

## 9. 原型验收标准

- 页面可明确识别为“左侧组织定位、右侧用户维护”，三块卡片层级清楚。
- 侧栏、Header、内容卡片之间有明确明度差异，但不新增页面私有配色。
- Header 已有面包屑，正文不重复“用户管理”标题和说明。
- 组织卡片、筛选卡片和列表卡片的边距、标题和操作对齐一致。
- “用户列表”和“华东事业部，共 56 位用户”能解释当前结果上下文。
- 页面不出现角色权限配置；角色配置通过独立角色管理模块完成。
- 侧栏底部“收起菜单”上方不存在横线，入口与侧栏保持同一背景和左侧对齐节奏。
- 产品名必须准确显示为“澄客 CRM”，不得生成或写成“清客 CRM”。
- 姓名、用户名、手机号、时间、组织人数与 PRD 示例数据一致。
