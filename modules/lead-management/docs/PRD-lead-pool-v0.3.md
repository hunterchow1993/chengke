## 1. 页面目标与边界

线索池是带成员、角色、领取限额和回收规则的独立业务容器，不是线索列表中的普通状态筛选。

本页面负责：

- 展示后端授权的线索池和池内未归属线索。
- 支持成员领取、管理员分配、跨池转移和池内无效处理。
- 展示领取额度、持有上限、冷却和自动回收规则。
- 承接员工主动退回、管理员收回和系统自动回收的线索。

本期不提供线索池配置页面、可视化自动分配规则设计器、多层保护期、公海撞单、导入导出和 AI 评分。

## 2. 核心归属模型

### 2.1 池内约束

活动池内线索必须满足：

```text
holderType = pool
ownerId = null
currentPoolId != null
status = unassigned
```

- `ownerId` 和 `currentPoolId` 不能同时有值，也不能同时为空。
- 领取或分配将线索从池移动给员工，并记录 `sourcePoolId`。
- 退回、收回和自动回收将员工线索移回来源池或指定池。
- 转商机和已无效线索不参与常规领取和自动回收。
- 前端不得直接修改负责人、池 ID 或状态模拟业务动作。

### 2.2 关键流转

```text
新录入 / 退回 / 收回 / 自动回收 / 转池
                    ↓
               线索池·待领取
               ├── 成员领取 ──> 线索列表·待跟进
               ├── 管理员分配 -> 线索列表·待跟进
               ├── 转移线索池 -> 目标池·待领取
               └── 判定无效 ──> 当前池·已无效
```

## 3. 用户、角色与权限

### 3.1 功能权限

| 权限编码 | 能力 |
| --- | --- |
| `lead:pool:view` | 进入线索池并查看授权池 |
| `lead:pool:claim` | 从授权池领取线索 |
| `lead:pool:assign` | 将池内线索分配给员工 |
| `lead:pool:return` | 主动退回本人负责的线索 |
| `lead:pool:reclaim` | 管理员或主管收回已归属线索 |
| `lead:pool:transfer` | 在线索池之间转移线索 |
| `lead:mark-invalid` | 将池内线索判定无效 |
| `lead:restore` | 恢复池内无效线索 |

### 3.2 池成员角色

用户必须同时具备功能权限和目标池成员身份。池角色不能仅由前端推断。

| 池角色 | 查看脱敏摘要 | 领取 | 退回本人线索 | 分配 | 收回 | 转池 | 池内无效审计 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `viewer` 查看者 | 是 | 否 | 否 | 否 | 否 | 否 | 否 |
| `member` 成员 | 是 | 按配置 | 是 | 否 | 否 | 否 | 否 |
| `manager` 管理员 | 是 | 按配置 | 是 | 是 | 是 | 是 | 按功能权限 |

- 超级管理员也只能看到后端授权上下文返回的池，前端不根据角色名默认放开全部池。
- 组织数据范围用于限制管理员可分配的员工；池成员身份用于限制可访问的池，两者不能互相替代。
- 修改 URL 中的 `poolId` 不得绕过池成员校验。

### 3.3 敏感字段

- 领取前无论用户是否有完整字段权限，联系方式默认固定脱敏。
- 池管理员默认也不能查看完整联系方式，除非后续合规评审明确增加独立权限。
- 领取或被分配后进入线索列表，再按敏感字段权限重新计算展示。
- 手机号筛选值不写入 URL、缓存、日志或埋点。

## 4. 页面结构

桌面端采用左右结构：

| 区域 | 尺寸 | 内容 |
| --- | --- | --- |
| 池导航 | 240px，可收起到 48px | 搜索、池分组、池名称、待领取数量 |
| 主内容 | 自适应 | 池信息、额度、视图、筛选、工具栏、表格和分页 |

- 页面设计基准 1440px，最低支持 1280px。
- 左侧是授权池列表，不是组织树。
- 池导航和主内容分别加载；单个池失败不影响切换其他池。
- 1280px 下允许表格横向滚动并固定线索摘要和操作列。

## 5. 池导航交互

### 5.1 展示规则

- 只展示后端返回的授权池。
- 池超过 10 个时显示搜索，并按地区、行业、渠道、业务线或其他分组折叠。
- 池名称右侧显示待领取数量；数量同样经过池权限校验。
- 首次进入优先选择最近访问且仍有权限的池，否则选择第一个授权池。
- 最近访问池只在本租户、本用户范围缓存；权限变化后必须失效。
- 不提供越过权限的全局“全部线索池”数据集合。

### 5.2 切换规则

- 切换池时取消上一池未完成查询并清空勾选项。
- 当前筛选默认不跨池继承，来源、意向等通用筛选可在后续提供“跨池记忆”设置。
- 当前池被停用或权限撤销时，切换至下一个授权池；没有授权池时进入空状态。
- URL 可携带 `poolId` 方便分享，但后端必须校验访问权限。

### 6.1 池头部

| 池说明 | 最多两行，说明适用范围和领取条件 |
| 待领取数量 | 后端实时或短时缓存统计 |
| 今日可领取 | “今日还可领取 N 条” |
| 当前可持有 | “当前还可持有 N 条” |
| 自动回收规则 | 例如“领取后 24 小时未跟进将自动回收” |
| 我的池角色 | 查看者、成员或管理员，只读展示 |

### 6.2 工作视图

| 视图 | 可见人 | 内容 |
| --- | --- | --- |
| 待领取 | 所有授权角色 | `unassigned` 的池内活动线索 |
| 已无效 | `manager` 且有 `lead:mark-invalid` | 当前池已无效线索及恢复入口 |

普通成员不展示“已无效”。视图数量由后端按当前池权限计算。

## 7. 筛选交互

筛选控件统一高度 36px。池内不提供负责人筛选，因为待领取线索必须没有负责人。

| 字段 | 字段键 | 控件 | 宽度 | 规则 |
| --- | --- | --- | --- | --- |
| 关键词 | `keyword` | 搜索输入 | 240px | 匹配编号、名称、联系人和企业名称 |
| 线索编号 | `leadNo` | 文本输入 | 180px | 精确匹配 |
| 手机号 | `mobile` | 电话输入 | 180px | 后端精确查询，结果仍脱敏 |
| 来源分类 | `sourceCategory` | 多选下拉 | 180px | 后端字典 |
| 具体来源 | `source` | 多选下拉 | 200px | 随分类联动 |
| 意向等级 | `intentionLevel` | 多选下拉 | 160px | 高、中、低、未知 |
| 入池方式 | `entryMethod` | 多选下拉 | 180px | 使用入池方式枚举 |
| 入池时间 | `enteredPoolAtRange` | 日期范围 | 260px | 最长 366 天 |

- 查询或按 Enter 后回到第 1 页。
- 重置只清空当前池筛选，不改变当前池。
- 筛选、视图、排序、分页或池变化时清空勾选项。
- 手机号不持久化，其他非敏感筛选可在当前会话恢复。

## 9. 查看详情

池内详情使用 720px 右侧抽屉，展示线索摘要、脱敏联系方式、来源、地区、需求摘要、入池信息和允许公开的历史动作。

- 领取前不展示完整联系方式。
- 隐藏不必要的历史负责人个人信息，但保留退回或回收原因摘要。
- 抽屉内领取成功后关闭池内详情，并按权限打开线索列表详情或提供跳转。
- 抽屉打开期间线索被他人领取时，显示“已被领取”并禁用操作。

## 10. 领取交互

### 10.1 前置条件

用户必须同时满足：

1. 拥有 `lead:pool:claim`。
2. 是当前池的 `member` 或 `manager`。
3. 当前池允许主动领取。
4. 未达到每日领取上限和活动线索持有上限。
5. 线索仍在当前池、无负责人、未锁定且不在当前用户冷却期。

### 10.2 单条领取

- 默认点击后出现轻量确认，展示领取后首次跟进时限。
- 后端使用事务或原子条件更新，多人同时领取时只有一人成功。
- 成功后写入负责人和部门快照，清空 `currentPoolId`，状态改为 `pending_follow_up`。
- 成功后当前行移除、池数量和额度同步刷新。
- 联系方式按线索列表字段权限重新加载，不在领取响应中无条件返回明文。

### 10.3 批量领取

- 只有池配置允许时展示；默认单次最多 10 条。
- 提交前展示已选数量和预计剩余额度。
- 后端逐条原子领取，允许部分成功。
- 失败原因稳定返回：已被领取、冷却中、今日额度不足、持有量已满或池已停用。

## 11. 管理员分配

- 可选择 1-100 条线索，目标员工使用可搜索选择器。
- 候选员工必须同时满足组织管理范围、账号正常和池分配规则。
- 员工活动线索持有上限默认必须校验。
- 管理员分配默认不占用员工每日主动领取额度，最终由池配置决定。
- v1.0 不提供强制超额分配。
- 后端允许部分成功并返回逐条失败原因；成功线索进入目标员工线索列表。

分配弹窗建议 520px，字段包括目标员工、分配原因和可选备注；批量分配时显示数量及可能的持有上限提示。

## 12. 退回、收回与转池

| 动作 | 操作者 | 入口 | 规则 |
| --- | --- | --- | --- |
| 主动退回 | 当前负责人 | 线索列表 | 原因必填；优先返回 `sourcePoolId` |
| 管理员收回 | 池管理员或授权主管 | 线索列表或管理入口 | 原因必填；校验当前归属 |
| 自动回收 | 后端定时任务 | 无前端入口 | 按池配置幂等执行 |
| 转移线索池 | 当前池管理员 | 池内更多菜单 | 目标池必须有管理权限 |

- 退回或收回后清空负责人，写入目标池、入池方式和入池时间，状态变为 `unassigned`。
- 跟进历史保留；新负责人获得详情权限后可查看必要历史。
- 主动退回者默认 24 小时内不能重新领取同一线索。
- 已转商机或已无效线索不能执行常规退回、收回或转池。
- 转池支持 1-100 条并逐条校验，记录前后池及原因。

## 13. 池内无效与恢复

- `manager` 同时拥有 `lead:mark-invalid` 时，可以把池内垃圾线索判定无效。
- 无效原因：联系方式无效、重复线索、确认无需求、垃圾或恶意提交、不属于业务范围、测试数据、其他。
- 无效线索保留 `currentPoolId` 和完整审计，进入当前池“已无效”视图。
- 恢复时默认回到当前池待领取状态；如池已停用，必须选择另一个有管理权限的活动池。
- 普通成员不能看到已无效视图和恢复入口。

## 14. 自动回收与限额

| 配置 | 字段 | 建议默认值 |
| --- | --- | --- |
| 首次跟进时限 | `firstFollowUpWithinHours` | 24 小时 |
| 连续无有效跟进 | `inactiveRecycleDays` | 7 天 |
| 下次跟进逾期宽限 | `overdueGraceHours` | 24 小时 |
| 每日主动领取上限 | `dailyClaimLimit` | 10 条 |
| 活动线索持有上限 | `activeLeadLimit` | 50 条 |
| 同线索重新领取冷却 | `sameLeadCooldownHours` | 24 小时 |

- 数值均由后端配置，前端不得写死。
- 自动回收由后端定时任务执行，并以线索 ID、规则版本和执行窗口保证幂等。
- 管理员锁定的重要线索不参与自动回收。
- 自动回收写入原因、原负责人、目标池、规则和执行时间。
- 是否在回收前通知负责人属于待确认项。

## 16. 后端一致性与并发

| 能力 | 后端要求 |
| --- | --- |
| 授权池查询 | 根据会话返回可见池、角色和额度，不信任前端成员信息 |
| 池内列表 | 固定校验池权限并脱敏联系方式 |
| 领取 | 校验池、成员、限额、冷却和状态，使用原子更新 |
| 分配 | 校验管理员、员工组织范围、账号和持有上限 |
| 退回或收回 | 校验当前归属、目标池和原因后原子更新 |
| 自动回收 | 按配置幂等执行并写审计 |
| 转池 | 同时校验来源池和目标池管理权限 |

稳定错误码：

| 错误码 | 含义 |
| --- | --- |
| `POOL_FORBIDDEN` | 无目标池权限 |
| `LEAD_ALREADY_CLAIMED` | 已被他人领取 |
| `CLAIM_DAILY_LIMIT_REACHED` | 当日领取额度已用完 |
| `ACTIVE_LEAD_LIMIT_REACHED` | 活动线索持有量达到上限 |
| `CLAIM_COOLDOWN_ACTIVE` | 重新领取冷却中 |
| `ASSIGNEE_OUT_OF_SCOPE` | 目标员工不在可分配范围 |
| `POOL_DISABLED` | 当前池已停用 |
| `LEAD_LOCKED` | 线索已被管理员锁定 |

## 17. 页面状态与反馈

| 场景 | 处理 |
| --- | --- |
| 导航加载 | 池导航骨架，主区域保持空白占位 |
| 池内容加载 | 保留池导航，表格使用行骨架 |
| 无授权池 | “暂无可访问的线索池”，提供联系管理员和返回列表 |
| 当前池为空 | “当前线索池暂无待领取线索” |
| 筛选无结果 | 提供重置筛选 |
| 领取冲突 | 提示已被其他成员领取并移除当前行 |
| 额度不足 | 展示具体是每日额度还是持有上限 |
| 池被停用 | 禁用操作并切换其他授权池 |
| 批量部分失败 | 显示成功数、失败数及脱敏失败清单 |

## 18. 审计、埋点与非功能要求

- 领取、分配、退回、收回、自动回收、转池、锁定、无效和恢复必须记录审计日志。
- 审计记录操作人、线索 ID、动作、前后归属、原因、时间和结果，不记录完整联系方式。
- 建议埋点：`lead_pool_view`、`lead_claim_submit`、`lead_pool_assign`、`lead_pool_return`、`lead_pool_reclaim`、`lead_pool_transfer`。
- 埋点不记录池名称、联系人、企业名称、联系方式或需求原文。
- 领取接口目标 1 秒内返回明确成功或冲突结果。
- 池导航可短时缓存，但权限或成员关系变化后必须失效。
- 表格、池导航、抽屉和弹窗支持键盘操作，状态不可只依赖颜色。

## 19. 验收标准

- [ ] 只展示后端返回的授权池，修改 `poolId` 不能越权。
- [ ] 池内活动线索无负责人且有当前池，联系方式固定脱敏。
- [ ] 功能权限与池角色同时满足时才展示并允许相应动作。
- [ ] 普通成员看不到已无效视图，池管理员按功能权限审计和恢复。
- [ ] 领取同时校验成员、池状态、额度、持有量、冷却、锁定和线索状态。
- [ ] 多人同时领取同一条线索时最多一人成功。
- [ ] 领取或分配成功后线索进入目标员工线索列表并变为待跟进。
- [ ] 管理员只能分配给组织范围内的正常员工。
- [ ] 退回、收回、转池和自动回收保存原因及完整归属变更。
- [ ] 自动回收幂等，锁定线索不参与回收。
- [ ] 无授权池、池为空、池停用、额度不足和领取冲突都有明确反馈。
- [ ] 日志、埋点和失败清单不泄露完整联系方式。

## 20. 待确认项

1. v1.0 首批线索池清单及地区、行业、渠道或业务线划分方式。
2. 每个池的领取上限、持有上限、首次跟进和自动回收时限。
3. 管理员分配是否占用员工每日主动领取额度。
4. 自动回收前是否提醒负责人，以及站内通知或企业即时通讯渠道。
5. 普通成员领取前是否展示意向等级，避免集中挑选高意向线索。
6. 员工调岗或离职后回到来源池还是专门交接池。
7. 无来源池的历史线索由谁选择退回目标池。
8. 池管理员是否需要独立的完整联系方式查看权限，默认不提供。
