## 1. 页面目标与边界

线索列表用于管理当前用户本人负责或按组织数据权限可查看的已归属线索，覆盖查询、新建、编辑、跟进、负责人转移、退回线索池、转商机、判定无效和恢复。

本页面不是线索池的状态筛选：

- 活动线索进入列表时必须有 `ownerId`，且 `currentPoolId` 为空。
- 退回或收回成功后，线索从列表消失并进入目标池。
- 新增、编辑、详情和跟进通过抽屉承载，不新增左侧菜单。
- 页面不负责线索池配置、自动分配规则、导入导出、线索合并和批量转商机。

## 2. 用户、权限与数据范围

### 2.1 功能权限

| 权限编码 | 能力 |
| --- | --- |
| `lead:view` | 查看列表和详情 |
| `lead:create` | 新建线索 |
| `lead:update` | 编辑非终态线索基础资料 |
| `lead:follow-up` | 添加跟进记录 |
| `lead:transfer-owner` | 转移负责人 |
| `lead:pool:return` | 当前负责人主动退回线索池 |
| `lead:pool:reclaim` | 主管或管理员收回线索 |
| `lead:convert` | 转为商机 |
| `lead:mark-invalid` | 判定无效 |
| `lead:restore` | 恢复无效线索 |
| `lead:mobile:full` | 查看完整手机号 |
| `lead:contact:full` | 查看完整微信、QQ 和邮箱 |

按钮是否展示由后端返回的授权上下文决定；提交接口必须再次鉴权，前端隐藏按钮不能替代后端权限校验。

### 2.2 组织数据权限

列表查询沿用以下数据范围：

| 提交值 | 可见范围 |
| --- | --- |
| `self` | 仅本人负责 |
| `department` | 本部门负责人名下 |
| `department_and_descendants` | 本部门及授权下级部门 |
| `selected_departments` | 指定部门集合及配置的下级范围 |
| `all` | 当前租户全部 |

- 集团普通员工不会因为位于集团根节点而自动看到下级部门线索。
- “我下属的”只在后端返回可管理范围时显示。
- 工作视图数量、筛选结果、详情、导出候选和批量动作必须使用同一数据权限。
- 用户调岗、角色变更或权限撤销后，后端实时拒绝旧页面中的越权请求。

### 2.3 敏感字段

- 有完整字段权限时展示完整联系方式，否则展示脱敏值，例如 `138****8006`。
- 手机号查询值不写入 URL、缓存、埋点或前端日志。
- 重复线索但无数据权限时，只提示存在重复，不返回负责人、部门或完整联系方式。
- 复制完整联系方式可记录独立安全审计事件。

## 3. 状态与归属模型

### 3.1 列表状态

| 提交值 | 中文名称 | 说明 | 可编辑 |
| --- | --- | --- | --- |
| `pending_follow_up` | 待跟进 | 已有负责人，尚无有效跟进 | 是 |
| `following` | 跟进中 | 已产生至少一条有效跟进 | 是 |
| `converted` | 已转商机 | 已创建唯一关联商机 | 否，仅只读 |
| `invalid` | 已无效 | 不再继续跟进 | 否，可按权限恢复 |

### 3.2 归属约束

已归属活动线索必须满足：

```text
holderType = user
ownerId != null
currentPoolId = null
```

状态、负责人和池归属只能通过后端业务动作修改，前端不得直接更新字段模拟成功。所有写操作携带 `version`，冲突时返回最新数据并要求用户确认后重试。

## 4. 页面结构

页面从上到下由以下区域组成：

1. 页面标题、说明和“新建线索”主按钮
2. 固定工作视图及数量
3. 紧凑筛选区和更多筛选
4. 批量操作栏
5. 数据表格和服务端分页
6. 详情、编辑、跟进抽屉及业务弹窗

设计基准为 1440px，最低支持 1280px；页面边距 24px，筛选区域内边距 16px。1280px 下允许表格受控横向滚动，并固定“线索”和“操作”列。

## 5. 固定工作视图

| 视图 | 后端查询语义 | 默认排序 |
| --- | --- | --- |
| 我负责的 | `ownerId = currentUserId`，排除终态 | 更新时间倒序 |
| 待我跟进 | 本人负责且为待跟进或跟进中 | 下次跟进升序 |
| 已逾期 | 本人负责且 `nextFollowUpAt < now`，排除终态 | 逾期时间升序 |
| 我下属的 | 数据权限内且负责人属于可管理下级 | 更新时间倒序 |
| 全部可见 | 数据权限内全部已归属线索 | 更新时间倒序 |
| 已转商机 | 数据权限内已转商机线索 | 转化时间倒序 |
| 已无效 | 数据权限内已无效线索 | 无效时间倒序 |

- 默认进入“我负责的”；无本人业务权限时进入后端指定的第一个视图。
- 数量由后端按相同权限独立统计，前端不拉取全量数据计算。
- 切换视图保留非冲突筛选，清空行选择并回到第 1 页。

筛选控件高度统一为 36px。首行最多展示 6 个条件，其余进入“更多筛选”。

| 字段 | 字段键 | 控件 | 宽度 | 规则 |
| --- | --- | --- | --- | --- |
| 关键词 | `keyword` | 搜索输入 | 240px | 模糊匹配编号、名称、联系人和企业名称 |
| 手机号 | `mobile` | 电话输入 | 180px | 标准化后精确匹配，不写入 URL |
| 状态 | `status` | 多选下拉 | 180px | 仅显示当前视图允许的状态 |
| 来源分类 | `sourceCategory` | 多选下拉 | 180px | 使用来源分类字典 |
| 具体来源 | `source` | 多选下拉 | 200px | 随来源分类联动 |
| 跟进人 | `ownerId` | 可搜索员工选择 | 200px | 只返回数据权限范围内员工 |
| 所属部门 | `ownerDepartmentId` | 组织树选择 | 220px | 可选择是否包含授权下级 |
| 意向等级 | `intentionLevel` | 多选下拉 | 160px | 高、中、低、未知 |
| 创建时间 | `createdAtRange` | 日期范围 | 260px | 最长 366 天 |

交互规则：

- 点击“查询”或在关键词中按 Enter 执行查询并回到第 1 页。
- “重置”清空筛选，但保留当前工作视图。
- 更多筛选收起后，已生效条件以筛选标签展示并可单独移除。
- 页面刷新可恢复非敏感筛选；手机号不持久化。
- 改变视图、筛选、排序或页码时清空已勾选行。

### 8.2 批量操作

- 单次最多选择 100 条；跨页选择不在 v1.0 范围内。
- 已转商机线索不可进入批量操作。
- 后端逐条校验并允许部分成功，返回成功数、失败数和稳定失败原因。
- 失败清单只含线索编号和原因，不包含完整联系方式。
- 批量转商机不在 v1.0 范围内。

- 前端失焦预检只用于提前反馈，保存时由后端最终检查。
- 无权查看重复记录时不得泄露负责人、部门或记录详情。

## 10. 详情与跟进

### 10.1 详情抽屉

### 10.2 添加跟进

| 字段 | 必填 | 控件与尺寸 | 规则 |
| --- | --- | --- | --- |
| 跟进时间 | 是 | 日期时间，100% × 40px | 默认当前时间，不早于创建时间 |
| 跟进方式 | 是 | 下拉，100% × 40px | 电话、微信、QQ、短信、邮件、面谈、其他 |

## 11. 业务弹窗

### 11.1 转移负责人

- 选择目标员工和转移原因；目标员工仅返回当前操作者可管理的正常账号。
- 后端校验目标员工组织范围、账号状态和活动线索持有上限。
- 成功后保留历史跟进，更新负责人及部门快照，并记录前后归属。

### 11.2 退回或收回

- 当前负责人主动退回必须选择原因；默认回到 `sourcePoolId`。
- 无来源池时只能从后端返回的可投放池中选择。
- 管理员收回需拥有权限和目标池管理能力。
- 成功后清空负责人，设置目标池和 `unassigned`，并从当前列表移除。
- 已转商机或已无效线索不能退回。

### 11.3 转商机

560px 弹窗至少包含商机名称、预计需求、商机阶段和预计成交日期；预计金额和意向产品可选。

- 后端事务处理重复检查、字段映射、商机创建、状态更新和审计。
- 商机创建失败时线索状态不变。
- 同一线索只允许成功转化一次；重复提交返回已有关联商机。
- 成功后线索只读，不直接创建正式客户。

### 11.4 判定无效与恢复

无效原因：联系方式无效、重复线索、确认无需求、垃圾或恶意提交、不属于业务范围、测试数据、其他。

- 原因必填；选择“其他”时补充说明 1-300 字必填。
- 已转商机不能判定无效。
- 恢复时必须选择“归属员工”或“进入线索池”，并填写恢复原因。

## 13. 后端一致性与错误码

| 能力 | 后端要求 |
| --- | --- |
| 列表查询 | 功能权限、组织范围、敏感字段、筛选、排序和分页统一处理 |
| 新建或编辑 | 字段、枚举、重复、归属目标及 `version` 校验 |
| 跟进 | 校验负责人或主管范围，更新最近和下次跟进时间 |
| 转移、退回、收回 | 原子更新归属并写审计 |
| 转商机 | 事务保证商机和线索状态一致 |
| 批量动作 | 逐条鉴权，支持部分成功 |

稳定错误码：`LEAD_FORBIDDEN`、`LEAD_VERSION_CONFLICT`、`LEAD_DUPLICATE_CONTACT`、`LEAD_ALREADY_CONVERTED`、`ASSIGNEE_OUT_OF_SCOPE`、`ACTIVE_LEAD_LIMIT_REACHED`。

## 14. 页面状态与反馈

| 场景 | 处理 |
| --- | --- |
| 首次加载 | 使用与最终行一致的表格骨架 |
| 列表为空 | 显示“暂无线索”；有权限时提供新建入口 |
| 筛选无结果 | 显示“未找到符合条件的线索”和重置操作 |
| 查询失败 | 内容区错误提示和重新加载 |
| 表单失败 | 保留输入，不关闭抽屉 |
| 版本冲突 | 提示数据已更新，提供刷新并重新编辑 |
| 权限失效 | 清理当前选择并跳转后端指定首页 |
| 批量部分失败 | 显示成功数、失败数和失败清单 |

## 15. 审计、埋点与非功能要求

- 新建、编辑、跟进、转移、退回、收回、转商机、判定无效和恢复必须记录审计日志。
- 日志和埋点不得记录完整联系方式、需求摘要或跟进内容原文。
- 建议埋点：`lead_list_view`、`lead_search`、`lead_create_submit`、`lead_follow_up_submit`、`lead_convert_submit`、`lead_pool_return`。
- 所有列表使用服务端分页；常规网络首屏目标 2 秒内可用。
- 表格、筛选、抽屉和弹窗支持键盘操作，状态满足 WCAG AA 对比度。
- 支持最近两个主要版本的 Chrome 和 Edge。

## 16. 验收标准

- [ ] 只展示本人负责或组织数据权限可见的已归属线索。
- [ ] 工作视图数量、列表、详情和批量动作使用相同数据权限。
- [ ] 集团普通员工不会自动看到全部下级部门线索。
- [ ] 联系方式按后端字段权限返回，手机号查询不进入 URL 和日志。
- [ ] 筛选、排序和分页由后端执行，切换条件时清空选择。
- [ ] 新建、编辑、跟进、转移、退回、转商机、无效和恢复按权限显示并由后端鉴权。
- [ ] 已转商机线索不可编辑、退回或再次转化。
- [ ] 退回成功后负责人为空，线索进入目标池并从列表消失。
- [ ] 重复校验不会向无权用户泄露记录信息。
- [ ] 乐观锁冲突、批量部分成功、空数据和加载失败都有明确反馈。
- [ ] 所有关键写操作生成审计日志。
