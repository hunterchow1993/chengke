## 1. 文档目标

本文档定义角色列表、角色新增与编辑、功能权限、数据权限、敏感字段权限、角色成员、启停保护和后端授权规则，作为产品、设计、前端、后端和测试共同执行的需求基线。

角色管理回答以下问题：

1. 一个角色可以进入哪些菜单、页面，并执行哪些操作。
2. 角色可以访问哪个组织范围内的业务数据。
3. 角色能否查看手机号等敏感字段的完整值。
4. 哪些用户正在使用该角色，以及角色变化何时生效。

## 2. 产品目标

- 通过角色集中维护权限，避免给每个用户配置不可追踪的个人权限。
- 把“可以做什么”和“可以看哪些数据”分开配置，降低管理员误授权风险。
- 让高风险授权有明确影响摘要、二次确认和审计记录。
- 让前端只负责授权结果的展示，后端成为菜单、接口和数据权限的唯一权威。
- 让角色管理和用户管理职责清楚，减少重复入口和配置冲突。

## 3. 一期决策

| 决策项 | v1.0 结论 |
| --- | --- |
| 用户与角色关系 | 一个用户只能拥有一个角色 |
| 用户级额外权限 | 不支持 |
| 权限合并 | 不涉及多角色并集或拒绝优先规则 |
| 功能权限 | 菜单、页面和操作权限使用一棵资源树配置 |
| 接口权限 | 后端把操作权限码映射到接口，不在页面维护 URL |
| 数据权限 | 角色只能选择一种组织数据范围 |
| 敏感字段权限 | 独立配置，由后端返回明文或脱敏值 |
| 角色成员 | 用户管理可为单个用户选角色；角色管理可批量调整成员 |
| 停用角色 | 立即停止授权并撤销相关用户会话，不允许继续分配 |
| 删除角色 | 仅无成员、非内置、非保护角色可软删除 |
| 超级管理员 | 使用唯一系统内置角色保护，不允许删除、停用或降低权限 |

## 4. 范围与模块边界

### 4.1 本期范围

- 分页查询和筛选角色。
- 新增、查看和编辑角色。
- 配置功能权限、数据权限和敏感字段权限。
- 查看角色成员，添加已有用户、移除成员或替换成员角色。
- 启用、停用和删除符合条件的角色。
- 处理系统内置角色、超级管理员角色和并发编辑保护。
- 权限变更后刷新后端缓存、撤销必要会话并记录审计日志。

### 4.2 非本期范围

- 一个用户拥有多个角色。
- 用户级权限例外、临时权限和权限有效期。
- 权限申请、审批和自动到期流程。
- 角色模板、复制、导入、导出和版本回滚。
- 跨租户共享角色和普通管理员跨租户授权。
- 线索池等业务资源的成员角色；该类权限由对应业务模块维护。

### 4.3 与用户管理的分工

| 业务场景 | 负责模块 |
| --- | --- |
| 新增账号、编辑资料、调整部门、启停账号 | 用户管理 |
| 为一个用户选择一个已有角色 | 用户管理 |
| 新增角色、修改角色名称和状态 | 角色管理 |
| 配置菜单、页面和操作权限 | 角色管理 |
| 配置组织数据范围与敏感字段权限 | 角色管理 |
| 按角色批量查看或调整成员 | 角色管理 |

用户管理不得出现权限树或数据权限编辑器。角色管理不得编辑姓名、手机号、部门和登录凭证等用户资料。

## 5. 角色与权限模型

### 5.1 权限分层

| 权限层 | 回答的问题 | 示例 |
| --- | --- | --- |
| 功能权限 | 能否进入页面或执行操作 | 查看用户、新增线索、停用账号 |
| 组织数据权限 | 可以访问哪些组织范围的数据 | 仅本人、本部门、华东事业部及下级 |
| 敏感字段权限 | 返回完整值还是脱敏值 | 完整手机号、完整邮箱 |
| 业务资源权限 | 是否为具体业务资源成员 | 线索池 manager；不在本模块配置 |

一次请求必须同时通过账号状态、功能权限、租户边界、数据范围、业务资源权限和敏感字段权限校验。前端隐藏菜单或按钮只能改善体验，不能替代后端鉴权。

### 5.2 后端权威原则

- 登录或刷新授权上下文时，后端统一返回用户摘要、菜单树、功能权限码、数据范围、敏感字段权限和授权首页。
- 前端不得根据角色名称推导菜单，不得自行扩大权限，不直接使用后端 URL 生成路由。
- 每个受保护接口由 Spring Security 方法权限或等价机制重新校验功能权限。
- 数据范围必须进入 MyBatis 查询条件，不允许先查全量再由前端或 Java 内存过滤。
- 敏感字段必须由后端决定返回完整值或脱敏值，完整值不得先返回前端再遮挡。
- 租户 ID 从认证上下文取得，不接受请求参数中的租户 ID 作为授权依据。

### 5.3 授权不超过自身

后端为当前操作者计算 `grantablePermissionCodes`、`grantableDepartmentNodes`、`grantableFieldPermissionCodes` 和可操作角色能力，页面只能展示该范围：

- 新角色的功能权限集合必须是操作者可授予功能权限的子集。
- 指定部门只能从后端返回的可授权组织树中选择。
- 操作者不能授予比自身更大的组织数据范围；`all` 仅超级管理员可授予。
- 敏感字段权限必须是操作者可授予字段权限的子集。
- 即使伪造请求提交未展示的权限码或部门 ID，后端也必须拒绝整个保存请求。
- 普通管理员不能编辑其无权完整查看或无权授予的角色，不能通过“先减少再扩大”绕过校验。

## 6. 目标用户与模块权限点

| 权限编码 | 权限说明 |
| --- | --- |
| `system:role:view` | 查看角色列表、角色详情和可见成员 |
| `system:role:create` | 新增角色 |
| `system:role:update` | 编辑角色基本信息 |
| `system:role:permission:update` | 修改功能权限 |
| `system:role:data-scope:update` | 修改组织数据范围 |
| `system:role:field-permission:update` | 修改敏感字段权限 |
| `system:role:member:view` | 查看角色成员 |
| `system:role:member:update` | 添加、移除或替换角色成员 |
| `system:role:status` | 启用或停用角色 |
| `system:role:delete` | 删除角色 |

模块入口要求 `system:role:view`。新增、编辑和高风险操作分别按权限点展示，接口仍需重新鉴权。

## 7. 信息架构

```text
系统管理 / 角色管理
├── 角色筛选卡片
└── 角色列表卡片
    ├── 结果数量与工具栏
    ├── 角色表格
    └── 分页

新增 / 编辑角色 Drawer
├── 基本信息
├── 功能权限
├── 数据权限
├── 敏感字段权限
└── 角色成员（新增首次保存前不可用）
```

角色管理和用户管理为两个独立路由，不使用页内 Tab 互相切换。Header 面包屑是页面唯一定位，不在主体重复展示同名大标题。

## 8. 角色列表

### 8.1 默认行为

- 进入页面后请求第 1 页，默认每页 10 条。
- 默认排序为最近更新时间倒序，内置角色不强制置顶。
- 所有筛选和分页均由服务端执行。
- 列表只返回操作者可查看的角色，并返回每个角色当前可执行能力。
- 查询失败保留筛选条件，展示重试入口，不用空数据状态掩盖错误。

### 8.2 筛选项

| 字段 | 查询参数 | 控件与尺寸 | 枚举或校验 | 交互 |
| --- | --- | --- | --- | --- |
| 关键词 | `keyword` | 文本输入，240px × 36px | 最长 50 字符；匹配角色名称或编码 | Enter 可查询 |
| 状态 | `status` | 单选 Select，160px × 36px | 全部、`active` 正常、`disabled` 已停用 | 默认全部 |
| 数据范围 | `dataScope` | 单选 Select，200px × 36px | 全部及第 11 节五种范围 | 默认全部 |
| 查询 | — | Primary Button，88px × 36px | — | 回到第 1 页并查询 |
| 重置 | — | Secondary Button，88px × 36px | — | 清空筛选并查询第 1 页 |

关键词仅输入空格时按空值处理。前端可对连续查询去重，但服务端仍需处理重复请求。

### 8.3 工具栏

- 左侧显示“角色列表”和当前查询结果总数。
- 右侧依次显示“新增角色”、刷新和表格设置；无创建权限时不展示新增按钮。
- 刷新保留筛选、排序和当前页；若当前页已无数据，则回退到最后一个有效页。
- 表格设置只能控制非必需列显隐，不允许隐藏角色名称、状态和操作列。
- 齿轮按钮的含义只能是“表格设置”，Tooltip 和 `aria-label` 均使用该名称。它不进入角色权限配置，避免管理员把页面显示设置误认为业务授权。

### 8.4 表格列

| 列 | 宽度建议 | 展示规则 |
| --- | ---: | --- |
| 角色名称 | 180px | 显示名称；系统角色附“系统内置”中性标签 |
| 角色编码 | 180px | 使用等宽字体；完整值可复制 |
| 成员数 | 96px | 展示操作者可见成员数；点击打开成员页签；不能泄露不可见成员数量 |
| 数据范围 | 160px | 使用五种中文枚举；指定部门附已选数量 |
| 状态 | 96px | “正常”或“已停用”，同时使用文字和状态样式 |
| 最近更新 | 176px | `YYYY-MM-DD HH:mm:ss`，使用等宽数字 |
| 操作 | 128px | “编辑”常驻；权限设置、成员管理、启停和删除收纳在更多菜单 |

后端同时返回 `capabilities`，前端按 `canEdit`、`canManageMembers`、`canChangeStatus` 和 `canDelete` 控制操作。不能只根据是否为内置角色在前端推断。

### 8.5 角色操作入口

| 操作 | 入口 | 打开位置 | 权限与说明 |
| --- | --- | --- | --- |
| 新增角色 | 列表工具栏主按钮 | 新增角色 Drawer / 基本信息 | 需要 `system:role:create` |
| 编辑 | 行内常驻文字按钮 | 编辑角色 Drawer / 基本信息 | 需要 `system:role:update`；只读角色显示“查看” |
| 权限设置 | 行内更多菜单 | 编辑角色 Drawer / 功能权限 | 需要任一权限配置权限；直接定位功能权限页签 |
| 成员管理 | 行内更多菜单或成员数 | 编辑角色 Drawer / 角色成员 | 需要成员查看或维护权限 |
| 启用/停用 | 行内更多菜单 | 二次确认 Dialog | 需要 `system:role:status` |
| 删除角色 | 行内更多菜单末项 | 危险确认 Dialog | 需要 `system:role:delete` 且满足删除条件 |

“编辑”“权限设置”和“成员管理”使用同一个角色 Drawer，通过初始页签区分入口，不能创建三个互不共享草稿的弹层。角色 Drawer 打开后可在有权限的页签之间切换。

### 8.6 分页

- 使用服务端分页，默认 10 条/页，可选 10、20、50 条/页。
- 切换每页条数后回到第 1 页。
- 筛选条件变化后回到第 1 页。
- 总数只能反映当前操作者可查看的角色，不泄露其他租户数据。

## 9. 新增与编辑容器

### 9.1 Drawer 规则

- 桌面端宽 720px；1024–1199px 最大宽度为 `70vw`；小于 1024px 占满可用宽度。
- Header 固定展示“新增角色”或角色名称；Footer 固定展示“取消”和“保存”。
- 中间区域独立滚动，切换页签不清空未提交草稿。
- 页签顺序为基本信息、功能权限、数据权限、敏感字段权限、角色成员。
- 新增角色首次保存前，角色成员页签为禁用状态并说明“请先保存角色后再添加成员”。
- 关闭存在未保存变化的 Drawer 时，提示“放弃修改”或“继续编辑”。
- 保存校验失败后，自动切到第一个错误页签并聚焦第一个错误字段。
- 编辑详情包含 `version`；保存发生并发冲突时禁止覆盖，提示重新加载最新内容。

### 9.2 保存策略

- 新增角色使用一次原子提交保存基本信息和全部权限配置。
- 编辑角色使用一次原子提交保存本次变化；任一权限校验失败时整体不落库。
- 角色成员使用独立接口调整，避免成员分页数据混入角色配置提交。
- 保存按钮在提交期间进入 Loading 并禁止重复提交。
- 保存成功后关闭 Drawer、刷新列表并定位该角色；成功 Toast 不替代字段错误或风险确认。

### 9.3 新增角色完整流程

#### 9.3.1 打开与默认值

1. 管理员点击工具栏“新增角色”。
2. 系统校验 `system:role:create`，并并行请求可授权功能权限树、组织树和敏感字段权限。
3. 打开“新增角色”Drawer，默认停留在“基本信息”。
4. 初始化以下默认值：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 角色名称 | 空 | 必填 |
| 角色编码 | 空 | 必填，创建后不可修改 |
| 显示顺序 | `100` | 越小越靠前 |
| 状态 | `active` | 默认创建为正常角色 |
| 备注 | 空 | 选填 |
| 功能权限 | 空集合 | 管理员必须主动勾选，不复制自己的全部权限 |
| 数据范围 | `self` | 使用最小权限默认值，避免误授权 |
| 指定部门 | 空集合 | 仅选择指定部门时使用 |
| 敏感字段权限 | 空集合 | 默认只返回脱敏字段 |
| 角色成员 | 不可操作 | 首次保存成功后才可添加成员 |

权限树或组织树仍在加载时，对应页签显示 Skeleton；加载失败时禁止用空集合替代真实权限并提交。

#### 9.3.2 填写顺序

管理员可以自由切换页签，但建议顺序为：

1. 填写基本信息。
2. 勾选功能权限，至少选择一个可访问页面；不允许只选择没有实际页面的目录节点。
3. 选择数据范围；选择指定部门时至少添加一个部门。
4. 按需选择敏感字段权限；敏感字段权限必须依赖所属页面的查看权限。
5. 检查页签上的错误数量和底部权限摘要。
6. 点击“保存”。

Footer 只保留“取消”和“保存”两个操作，不增加“下一步”按钮。页签不是强制步骤条，避免管理员为了修改某一个权限被迫逐页点击。

#### 9.3.3 新增校验

保存时按以下顺序校验：

1. 基本字段必填、格式、长度和唯一性。
2. 至少选择一个有效页面权限；目录半选状态不计入有效权限。
3. 数据范围配置完整且没有超过操作者可授权边界。
4. 敏感字段权限均存在所属页面查看权限。
5. 功能、数据和字段权限都是操作者可授予权限的子集。

前端校验失败时切换到第一个错误页签并聚焦错误字段；后端任一校验失败时整体不创建角色。

#### 9.3.4 新增成功

- 保存成功后关闭 Drawer，列表回到第 1 页并按最近更新时间显示新角色。
- Toast 显示“角色已创建”，可提供非主按钮式“添加成员”操作；点击后重新打开该角色的成员页签。
- 新角色在分配成员前不会影响任何用户权限。
- 后端写入角色创建和首次授权审计日志。

### 9.4 编辑与权限设置完整流程

#### 9.4.1 打开方式

- 点击“编辑”：打开 Drawer 并定位“基本信息”。
- 点击“权限设置”：打开同一个 Drawer 并定位“功能权限”。
- 点击成员数或“成员管理”：打开同一个 Drawer 并定位“角色成员”。
- 打开 Drawer 时并行请求角色详情和当前操作者可授权资源；详情加载完成前不显示可编辑的旧缓存数据。
- 后端返回 `capabilities` 决定页签可见、只读或隐藏状态。前端不得只根据角色编码推断。

#### 9.4.2 页签级保存权限

| 页签 | 所需权限 | 无权限行为 |
| --- | --- | --- |
| 基本信息 | `system:role:update` | 只读展示，不显示可编辑控件 |
| 功能权限 | `system:role:permission:update` | 只读展示已授权摘要 |
| 数据权限 | `system:role:data-scope:update` | 只读展示当前范围 |
| 敏感字段权限 | `system:role:field-permission:update` | 只读展示当前字段权限 |
| 角色成员 | `system:role:member:view` | 无查看权限时隐藏；有查看无更新权限时只读 |

只读页签必须与禁用控件视觉区分：使用只读摘要，不把整个页面渲染成大量灰色 Disabled 输入框。

#### 9.4.3 变更差异与确认

管理员点击“保存”后，前端先生成易读差异摘要，后端重新计算权威差异：

| 变化类型 | 示例 | 是否二次确认 |
| --- | --- | --- |
| 基本信息 | 修改名称、顺序或备注 | 否 |
| 普通增权 | 新增一个普通查看页面 | 是，展示新增权限数量 |
| 高风险增权 | 全集团数据、用户管理、角色管理、完整联系方式 | 是，使用警告级确认 |
| 减少权限 | 取消菜单、操作或字段权限 | 是，展示受影响成员数 |
| 缩小数据范围 | 全集团改为指定部门 | 是，说明成员将失去的数据范围 |
| 未发生变化 | 打开后未修改 | 不发请求，提示“没有需要保存的修改” |

确认 Dialog 展示角色名称、变更前后摘要和受影响成员数。不得只显示“确定要保存吗”。

#### 9.4.4 保存与生效

1. 提交角色 ID、`version` 和变更后的完整配置。
2. 后端重新校验权限边界、角色保护规则和版本号。
3. 在事务中保存角色及权限关系并记录审计差异。
4. 事务成功后清理该角色成员的 Redis 权限缓存，并将租户授权版本 +1（与用户 / 部门同一 Redis key `chengke:authorization:version:{tenantId}`）。**改角色权限定义（功能权限、数据范围、敏感字段）必须加版本，不只在改用户角色绑定时才加。**
5. 高风险权限、数据范围或敏感字段变化时，撤销相关 Refresh Token Family；旧 Access Token 在下一次业务请求因授权版本不一致而 HTTP 409 `PERMISSION_VERSION_CHANGED`，不能继续按旧 `scope` 执行业务。
6. 前端关闭 Drawer、刷新当前列表页并显示成功反馈。

发生 `409` 版本冲突时，保留当前编辑草稿并提供“查看最新版本”和“放弃本地修改”。一期不支持自动合并权限树。

### 9.5 Drawer 页签内容摘要

| 页签 | 主要内容 | 必填/最小要求 | 主要风险 |
| --- | --- | --- | --- |
| 基本信息 | 名称、编码、顺序、状态、备注 | 名称、编码、顺序、状态必填 | 重名、编码不可修改 |
| 功能权限 | 目录、页面、操作资源树 | 至少一个有效页面 | 菜单和接口越权 |
| 数据权限 | 五种范围、指定部门树 | 必选一种；指定部门至少一项 | 集团或下级数据扩权 |
| 敏感字段权限 | 按模块分组的字段 Checkbox | 可为空 | 手机号等明文泄露 |
| 角色成员 | 成员查询、添加、改派 | 新增首次保存前不可用 | 单角色替换、当前用户降权 |

## 10. 基本信息

### 10.1 字段定义

| 序号 | 字段 | 提交字段 | 必填 | 控件与尺寸 | 默认值 | 校验与说明 |
| ---: | --- | --- | --- | --- | --- | --- |
| 1 | 角色名称 | `name` | 是 | Input，满宽 × 40px | 空 | 去除首尾空格后 2–30 字符；同租户不重名 |
| 2 | 角色编码 | `code` | 是 | Input，满宽 × 40px | 空 | 2–50 字符；创建后不可修改；同租户唯一 |
| 3 | 显示顺序 | `sort` | 是 | Number Input，200px × 40px | `100` | 整数 0–999；越小越靠前 |
| 4 | 状态 | `status` | 是 | Radio Group 或 Switch | `active` | `active` 正常、`disabled` 已停用 |
| 5 | 备注 | `remark` | 否 | Textarea，满宽 × 96px | 空 | 最多 200 字符；显示字数计数 |

### 10.2 角色编码规则

- 正则：`^[a-z][a-z0-9:_-]{1,49}$`。
- 必须以小写字母开头，只允许小写字母、数字、冒号、短横线和下划线。
- 建议业务角色使用 `sales_manager`、`group_auditor` 等稳定编码。
- 角色编码用于程序和审计识别，创建后不可编辑；角色名称允许修改。
- 编码唯一性由数据库唯一约束保证，前端异步校验只用于提前反馈。

### 10.3 内置角色

- `super_admin` 为唯一超级管理员角色，拥有租户内全部功能、全集团数据范围和全部敏感字段权限。
- 内置角色返回 `builtIn=true` 和能力标记。
- 超级管理员角色不得删除、停用、修改编码、减少权限或移除最后一名成员。
- 其他内置角色允许修改哪些字段由后端能力标记决定，前端不写死保护规则。

## 11. 数据权限

### 11.1 数据范围枚举

| 提交值 | 中文名称 | 实际范围 | 典型角色 |
| --- | --- | --- | --- |
| `self` | 仅本人 | 仅负责人或创建人为当前用户的数据 | 普通销售 |
| `department` | 仅本部门 | 当前用户直属组织节点的数据，不含下级 | 部门专员 |
| `department_and_descendants` | 本部门及下级 | 当前用户直属节点及全部授权后代节点 | 部门经理、事业部负责人 |
| `selected_departments` | 指定部门 | 明确选择的一个或多个部门，可逐项包含下级 | 区域运营、跨部门协作 |
| `all` | 全集团 | 当前租户全部组织节点 | 超级管理员、集团审计员 |

组织归属不等于数据范围。员工挂在集团根节点不会自动看到所有下级部门；只有明确配置 `department_and_descendants` 或 `all` 才能访问相应范围。

### 11.2 页面交互

- 五种范围使用纵向单选卡片，每项展示名称和明确说明。
- 选择 `selected_departments` 后显示可搜索组织树，至少选择一个部门。
- 每个已选部门独立配置 `includeDescendants`，不使用一个含义模糊的全局开关。
- 已选择父部门并包含下级时，子部门显示“已由上级覆盖”，避免重复提交。
- 无权授权的组织节点不返回前端；为了展示路径，可返回不可选祖先节点，但不得返回无权节点人数。
- 从 `selected_departments` 切换到其他范围时，提交不携带历史部门；当前 Drawer 会话可保留草稿，切回时恢复。

### 11.3 指定部门提交结构

```json
{
  "dataScope": "selected_departments",
  "selectedDepartments": [
    {
      "departmentId": "dept_1001",
      "includeDescendants": true
    }
  ]
}
```

### 11.4 扩权确认

以下情况视为扩大数据范围：

- 改为 `all`。
- 从 `self` 改为任一部门范围。
- 从 `department` 改为 `department_and_descendants`。
- 指定部门新增节点、扩大到祖先节点，或开启“包含下级”。

扩大范围时保存前展示二次确认，说明角色、变化前后范围和受影响成员数。后端必须再次判断是否属于扩权，不能信任前端结论。

## 12. 功能权限

### 12.1 权限资源模型

功能权限使用一棵后端返回的资源树，不把菜单与按钮拆成互相难以理解的两个编辑页签：

| 资源类型 | `type` | 示例 | 作用 |
| --- | --- | --- | --- |
| 目录 | `directory` | 系统管理 | 组织导航层级，不直接对应接口 |
| 菜单/页面 | `menu` | 用户管理 | 控制菜单可见和页面访问 |
| 操作 | `action` | 新增用户 | 控制按钮、命令与后端接口 |

每个节点至少包含 `id`、`parentId`、`name`、`type`、`permissionCode`、`routeKey`、`iconKey`、`selectable`、`children`。目录节点可没有 `permissionCode`，页面和操作使用稳定权限编码。

### 12.2 权限树交互

- 支持关键词定位、展开全部、收起全部、全选可授权项和清空。
- 节点最小高度 40px，展开箭头、复选框和节点文字拥有清楚的点击区域。
- 勾选页面时默认勾选其必要祖先目录，但不自动授予页面下全部操作。
- 勾选操作时自动补齐其所属页面和必要祖先。
- 取消页面时取消该页面下全部操作，并在保存前纳入减少权限摘要。
- 部分子节点选中时父节点显示半选；半选只表达汇总状态，不作为独立提交值。
- 无权授予但为理解层级所需的祖先可只读展示；不可授权权限不得通过全选选中。
- 前端只提交叶级有效权限编码集合；后端按资源模型规范化并返回最终授权结果。

### 12.3 权限减少确认

取消菜单、页面或操作可能影响现有成员。保存前摘要至少展示：

- 删除的菜单和操作数量。
- 受影响成员数量。
- 角色成员下次请求或重新登录后将失去的核心入口。

减少普通权限使用确认提示；减少高风险管理权限或影响当前操作者时，后端直接拒绝或要求具备更高管理权限。

## 13. 敏感字段权限

### 13.1 一期权限项

| 权限编码 | 中文名称 | 未授权行为 |
| --- | --- | --- |
| `system:user:mobile:full` | 查看用户完整手机号 | 返回 `138****8006` |
| `system:user:email:full` | 查看用户完整邮箱 | 返回部分脱敏邮箱 |
| `crm:contact:mobile:full` | 查看客户联系人完整手机号 | 返回脱敏手机号 |
| `crm:contact:wechat:full` | 查看客户联系人完整微信号 | 返回脱敏微信号 |

权限项以后端权限资源为准，页面不得写死为只有四项；一期至少实现已有业务字段对应的权限。

### 13.2 页面交互与安全

- 按业务模块分组展示 Checkbox，每项包含字段名称和未授权时的脱敏说明。
- 只有已选择对应页面查看权限时，该模块的字段权限才可选择。
- 取消页面查看权限时，自动取消其下敏感字段权限。
- 新增完整联系方式权限属于扩权，需要纳入保存确认和审计差异。
- 列表、详情、导出、搜索建议、日志和通知必须使用相同字段权限，不能只保护某一个页面。
- Tooltip、URL、埋点和前端错误日志不得记录后端返回的敏感明文。

## 14. 角色成员

### 14.1 成员列表

| 字段 | 说明 |
| --- | --- |
| 关键词 | 按姓名、用户名或手机号查询；无字段权限时手机号按脱敏值查询规则处理 |
| 用户 | 头像、姓名和用户名 |
| 部门 | 当前所属组织路径的末级部门 |
| 状态 | 正常或已停用 |
| 加入时间 | 用户被分配到当前角色的时间 |
| 操作 | 移出角色或更换角色 |

成员使用服务端分页，默认每页 10 条。数量和列表仅统计操作者有权查看的用户；若角色还包含不可见成员，页面不得泄露其精确数量。

### 14.2 添加成员

- 点击“添加成员”打开用户选择 Dialog。
- 候选用户只包含操作者有权管理、状态正常且允许被授予当前角色的用户。
- v1.0 为单角色：已拥有其他角色的用户也可选择，但确认时必须展示“原角色 → 新角色”。
- 支持批量选择，单次最多 100 人；每个用户由后端独立校验。
- 批量操作允许部分成功，结果展示成功数、失败数和逐项原因。

### 14.3 移除与替换成员

- 用户不能处于无角色状态，因此“移出角色”必须同时选择一个状态正常的替代角色。
- 唯一超级管理员不能被移出保护角色。
- 当前操作者不能通过成员操作修改自己的角色。
- 目标用户在确认期间被调离可管理范围时，后端拒绝该用户的变更。
- 成员角色变更成功后，立即刷新该用户的授权缓存并撤销旧会话。

## 15. 启用、停用与删除

### 15.1 状态枚举

| 提交值 | 中文名称 | 是否可分配 | 授权行为 |
| --- | --- | --- | --- |
| `active` | 正常 | 是 | 正常参与登录授权计算 |
| `disabled` | 已停用 | 否 | 不再提供任何业务授权 |

### 15.2 停用角色

- 仅具备 `system:role:status` 且后端返回 `canChangeStatus=true` 时可操作。
- 确认框展示角色名称、可见受影响成员数和“成员将无法继续使用该角色权限”。
- 后端原子更新状态、失效权限缓存并撤销该角色成员的登录会话。
- 成员关系保留，便于管理员迁移或重新启用；停用角色不能分配给新用户。
- 超级管理员角色和其他受保护角色不可停用。

### 15.3 启用角色

- 启用后恢复可分配状态，但不会自动恢复已迁移成员。
- 后端更新角色版本并清理相关缓存。

### 15.4 删除角色

只有同时满足以下条件才显示删除入口并允许删除：

1. `builtIn=false`。
2. `protected=false`。
3. 实际成员数为 0；该判断使用后端全量成员关系，不能只看操作者可见成员数。
4. 操作者拥有删除权限且角色处于其可管理范围。

删除使用软删除，确认框要求输入角色名称进行确认。删除后编码默认不可在短期内复用，具体保留周期由后端数据策略确定。

## 16. 页面状态与反馈

| 状态 | 页面处理 |
| --- | --- |
| 首次加载 | 使用结构一致的筛选、表格 Skeleton |
| 列表为空 | 展示“暂无角色”；有创建权限时提供“新增角色” |
| 筛选无结果 | 展示当前筛选摘要和“清空筛选” |
| 列表失败 | 保留筛选条件并提供重试 |
| 权限树失败 | 当前页签展示错误和重试，不清空其他页签草稿 |
| 组织树失败 | 数据权限页签展示错误和重试，禁止以空树保存 |
| 保存中 | 禁止重复提交和直接关闭 Drawer |
| 403 | 展示无权限状态，不回显受保护对象详情 |
| 409 | 提示角色已被他人修改，提供重新加载，不覆盖新版本 |
| 部分成员失败 | 展示成功、失败数量和每个失败对象的稳定原因 |

## 17. 后端接口能力建议

| 能力 | 方法与路径建议 | 关键说明 |
| --- | --- | --- |
| 分页查询角色 | `GET /api/v1/system/roles` | 返回能力标记和可见成员数 |
| 查询角色详情 | `GET /api/v1/system/roles/{id}` | 返回版本号和规范化权限配置 |
| 新增角色 | `POST /api/v1/system/roles` | 基本信息与权限原子保存 |
| 更新角色 | `PUT /api/v1/system/roles/{id}` | 携带 `version` 防并发覆盖 |
| 修改角色状态 | `PATCH /api/v1/system/roles/{id}/status` | 服务端处理缓存和会话失效 |
| 删除角色 | `DELETE /api/v1/system/roles/{id}` | 服务端按实际成员关系校验 |
| 查询可授权权限树 | `GET /api/v1/system/roles/grantable-permissions` | 后端裁剪可授权节点 |
| 查询可授权组织树 | `GET /api/v1/system/roles/grantable-organizations` | 可返回只读祖先路径 |
| 查询角色成员 | `GET /api/v1/system/roles/{id}/members` | 服务端分页和数据权限过滤 |
| 添加或替换成员 | `POST /api/v1/system/roles/{id}/members` | 单次最多 100 人，返回逐项结果 |
| 移除并改派成员 | `POST /api/v1/system/roles/{id}/members/reassign` | 必须提交替代角色 |

接口路径以最终后端设计为准，但权限树、组织树、角色能力和可操作成员必须由服务端计算。

  "code": "east_sales_manager",
  "sort": 100,

### 18.2 保存校验顺序

1. 校验登录、账号状态和租户边界。
2. 校验操作者对应操作权限。
3. 校验角色是否存在、版本是否一致、是否为保护对象。
4. 校验基本字段格式与租户内唯一性。
5. 校验功能权限、数据范围、部门和字段权限未超出可授权边界。
6. 计算扩权或减权差异及受影响成员。
7. 在同一事务中保存角色与权限关系。
8. 提交事务后清理缓存、撤销必要会话并写入审计结果。

## 19. 审计、安全与缓存

- 创建、编辑、启停、删除、功能授权、数据授权、字段授权和成员调整必须写审计日志。
- 日志至少记录租户、操作人、角色、操作类型、变更前后差异、受影响成员数、时间、结果和失败原因。
- 高权限变化需要结构化记录增加和删除的权限编码与部门范围，不能只记录“修改成功”。
- 角色变化后删除或更新 Redis 权限缓存，并递增租户授权版本；失败时不得继续使用旧授权静默放行。
- 停用角色、修改角色权限定义或调整成员角色时，旧 Access Token 在下一次业务请求因版本不一致返回 HTTP 409 `PERMISSION_VERSION_CHANGED`。高风险变化仍按上文撤销 Refresh Token Family。
- 批量成员操作逐项校验目标用户的租户、数据范围和保护状态。
- 任何 ID 猜测、跨租户请求和请求体权限码伪造均返回稳定错误，不泄露对象是否存在。

## 20. 可访问性与响应式

- 字段均使用常驻 Label，Placeholder 不替代字段名。
- 权限树、组织树、页签、Dialog 和 Drawer 支持键盘操作，焦点顺序与视觉顺序一致。
- Checkbox 半选状态使用原生或等价 `aria-checked="mixed"`。
- 图标按钮具有 Tooltip、`aria-label` 和足够点击热区。
- 状态和风险不能只用颜色表达。
- ≥1200px 筛选单行、Drawer 720px；1024–1199px 筛选可换行、隐藏低优先级列；<1024px Drawer 占满可用宽度，表格滚动限制在表格容器内。
- 移动端不是一期核心场景，但不得出现页面级横向溢出或无法触达保存按钮。

## 21. 验收标准

### 21.1 角色列表

- [ ] 可按名称/编码、状态和数据范围查询，查询和重置均回到第 1 页。
- [ ] 表格字段、状态、分页和操作能力符合本文档。
- [ ] 成员数和角色总数不会泄露操作者无权查看的数据。
- [ ] 加载、空数据、无结果、失败、403 和并发冲突均有明确反馈。

### 21.2 新增与编辑

- [ ] 基本字段的必填、长度、正则、唯一性、尺寸和枚举符合本文档。
- [ ] 新增角色首次保存前不能管理成员。
- [ ] Drawer 切换页签不丢失草稿，关闭未保存内容会确认。
- [ ] 版本冲突不会覆盖其他管理员的最新修改。

### 21.3 权限

- [ ] 功能权限树正确处理祖先、页面、操作和半选关系。
- [ ] 后端返回并校验可授权范围，伪造权限码或部门 ID 无法越权。
- [ ] 五种数据范围均按服务端 SQL 条件生效，集团节点员工不会自动扩权。
- [ ] 指定部门可逐项配置是否包含下级，父级覆盖不会产生重复范围。
- [ ] 敏感字段由后端明文或脱敏返回，前端日志和埋点不泄露明文。
- [ ] 扩权和大范围减权展示影响摘要并写入审计日志。

### 21.4 成员与角色状态

- [ ] 一个用户只能拥有一个角色，替换时明确展示原角色和新角色。
- [ ] 移除成员必须选择替代角色，用户不会处于无角色状态。
- [ ] 当前操作者和唯一超级管理员受到降权保护。
- [ ] 停用角色后不再授权、不再可分配，并及时失效成员缓存和会话。
- [ ] 仅实际无成员、非内置、非保护角色允许删除。

### 21.5 后端权威

- [ ] 登录后的菜单、操作、数据范围和字段权限由后端统一返回。
- [ ] 前端路由与按钮控制不能替代接口鉴权。
- [ ] 数据范围进入查询条件，导出与列表复用同一权限规则。
- [ ] 权限和成员变化均可从系统日志追溯完整差异。
