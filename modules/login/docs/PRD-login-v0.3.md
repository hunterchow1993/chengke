## 1. 产品概述

登录页是澄客 CRM 的统一身份入口，面向集团和各级部门的授权员工。页面需要完成账号认证、账号状态校验、首次登录改密判断和登录会话创建，并保持与系统管理后台一致的品牌、配色和组件语言。

## 2. 背景与设计原则

澄客 CRM 属于企业内部客户经营系统，登录页首先承担身份验证和安全提示职责，不承担公开获客、注册转化或营销展示职责。

设计遵循以下原则：

1. 与后台统一遵循项目级设计系统中的灰岩蓝品牌色、字体、圆角和 Icon 规范。
2. 页面只保留一个主要操作“登录”，避免注册、社交登录等无关入口分散注意力。
3. 所有字段使用常驻标签，不使用占位文字代替字段名称。
4. 错误信息清晰但不过度泄露账号是否存在等敏感信息。
5. 默认状态简洁，验证码等风控控件按风险条件出现。
6. 桌面端强调品牌识别，窄屏端优先保证表单可用性。

## 3. 产品目标

### 3.1 本期目标

- 授权员工可以使用用户名或手机号和密码登录系统。
- 系统能够校验账号状态、密码状态和首次登录改密状态。
- 支持安全的 7 天登录保持机制。
- 登录失败时提供可恢复的错误说明。
- 异常登录和连续失败行为可被限制并记录。
- 登录页与用户管理后台视觉一致。

### 3.2 非本期目标

- 不支持用户自主注册。
- 不支持微信、飞书、钉钉等第三方扫码登录。
- 不支持短信验证码直接登录。
- 不支持单点登录。
- 不支持多因素认证。
- 不支持用户通过短信或邮件自助重置密码。
- 不展示公开产品介绍、客户案例或营销信息。

## 4. 目标用户与前置条件

| 用户类型 | 登录诉求 | 前置条件 |
| --- | --- | --- |
| 普通员工 | 进入个人权限范围内的业务页面 | 已由管理员创建账号，状态正常 |
| 部门管理员 | 进入部门管理和授权业务页面 | 已分配有效角色和数据范围 |
| 系统管理员 | 管理系统用户、部门和角色 | 已分配系统管理权限 |
| 超级管理员 | 进入全集团管理范围 | 账号状态正常且超级管理员身份有效 |

所有用户均由管理员在用户管理模块中创建，不存在前台注册流程。

## 5. 页面结构与视觉规范

### 5.1 页面布局

宽屏采用左右分屏：左侧为品牌区，右侧为登录操作区。平板竖屏与手机使用单列表单，不能通过等比缩放桌面布局实现响应式。

| 区域 | 桌面端规格 | 职责 |
| --- | --- | --- |
| 页面容器 | 最小高度 100dvh | 覆盖完整可用视口，避免移动端地址栏引发布局跳动 |
| 左侧品牌区 | 宽屏约 44%，中等桌面约 36% | 展示品牌标识、产品定位和克制的组织关系图形 |
| 右侧登录区 | 占据剩余宽度 | 展示帮助入口、登录表单、安全提示和版权信息 |
| 登录表单 | 最大宽度 400px | 在右侧区域内垂直居中，不使用额外悬浮卡片 |
| 页面边距 | 桌面端最少 48px | 保持呼吸感和大屏稳定性 |

### 5.2 品牌区内容

| 内容 | 文案或规则 |
| --- | --- |
| 品牌标识 | 盾牌标识与“澄客 CRM”，使用白色 |
| 主标题 | “客户经营，从清晰开始” |
| 说明文字 | “统一管理线索、商机、客户与团队协作。” |
| 图形 | 使用同色系抽象组织结构图形，不展示真实数据或虚构产品界面 |
| 底部说明 | “企业客户经营管理平台” |

### 5.3 登录区内容

| 内容 | 文案或规则 |
| --- | --- |
| 帮助入口 | “遇到问题？联系管理员” |
| 页面标题 | “登录澄客 CRM” |
| 页面说明 | “使用公司账号继续” |
| 安全提示 | “仅限授权员工使用” |
| 页脚 | “© 2026 澄客 CRM” |

### 5.4 颜色规范

登录页必须遵循[澄客 CRM Web 设计系统](../../../design-system/chengke-crm/MASTER.md)，不在本 PRD 中维护第二套色值。左侧品牌区使用全局侧栏深灰岩蓝，登录按钮、链接和焦点使用全局品牌主色；表单区使用全局背景、表面、文字、边框和错误语义 Token。

登录页不创建新的强调色，不使用紫色、彩色渐变、外发光或玻璃拟态。错误色只用于真实错误状态，不视为第二品牌色。

### 5.5 组件尺寸

| 组件 | 宽度 | 高度 | 圆角 | 说明 |
| --- | --- | --- | --- | --- |
| 账号输入框 | 100%，最大 400px | 44px | 6px | 左侧用户图标 |
| 密码输入框 | 100%，最大 400px | 44px | 6px | 左侧锁图标，右侧显示密码图标 |
| 登录按钮 | 100%，最大 400px | 44px | 6px | 文字保持单行 |
| 复选框 | 20px | 20px | 4px | 点击区域不小于 40px × 40px |
| 字段标签 | 自适应 | 20px | 无 | 与控件间距 8px |
| 字段间距 | 100% | 20px | 无 | 错误信息出现时保留稳定间距 |

### 5.6 响应式规则

| 视口 | 布局规则 |
| --- | --- |
| ≥1440px | 44% / 56% 左右分屏；品牌内容最大宽度 560px；表单最大宽度 400px |
| 1280-1439px | 保持左右分屏；品牌区约 40%；缩小组织图形但不改变文案层级 |
| 1024-1279px | 品牌区约 36%；隐藏大型组织图形和底部说明；表单最大宽度 384px |
| 768-1023px | 取消分屏；使用浅色单列页面和紧凑品牌 Header；表单最大宽度 400px，水平居中 |
| 480-767px | 单列移动布局；左右内边距 24px；品牌、帮助入口、表单和页脚进入同一自然滚动流 |
| 360-479px | 左右内边距 20px；表单占满可用宽度；输入文字不小于 16px |
| <360px | 左右内边距 16px；保持 44px 控件和 8px 最小交互间距，不横向溢出 |

响应式必须同时满足：

- 使用 `<meta name="viewport" content="width=device-width, initial-scale=1" />`，不得禁止用户缩放。
- 页面容器使用 `min-height: 100dvh`，不使用固定 `100vh` 裁切移动浏览器可用区域。
- 手机横屏与高度小于 700px 的视口采用顶部对齐和自然滚动，不强制垂直居中。
- 移动端页脚不得固定在视口底部；软键盘弹出后，账号、密码和登录按钮均能通过自然滚动访问。
- 页面底部内边距需要叠加 `env(safe-area-inset-bottom)`，顶部品牌区兼容 `env(safe-area-inset-top)`。
- 账号输入设置合理的 `autocomplete` 与 `inputmode`；密码输入支持密码管理器，不阻止粘贴。
- 断点切换不得清空已输入账号、密码、保持登录选择和已显示的错误状态。

## 6. 登录字段规范

### 6.1 默认字段

| 顺序 | 字段 | 字段键建议 | 必填 | 控件 | 默认值 | 输入和校验规则 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 账号 | `account` | 是 | 文本输入框 | 空 | 接受用户名或 11 位中国大陆手机号；去除首尾空格；最大 32 个字符；不自动改变字母大小写 |
| 2 | 密码 | `password` | 是 | 密码输入框 | 空 | 8-32 个字符；默认隐藏；不去除用户主动输入的内部空格；不进行自动格式化 |
| 3 | 7 天内保持登录 | `rememberMe` | 否 | 复选框 | 未选中 | 选中后创建最长 7 天的受控登录会话，不保存明文账号密码 |

### 6.2 风控字段

连续登录失败达到风控阈值后，在密码字段下方动态增加验证码字段。

| 字段 | 字段键建议 | 控件 | 规则 |
| --- | --- | --- | --- |
| 图形验证码 | `captchaCode` | 160px 输入框加验证码图片 | 4-6 位；不区分大小写；60 秒后自动失效 |
| 验证码凭证 | `captchaToken` | 隐藏字段 | 由服务端签发；一次使用后失效 |

验证码不在默认原型中常驻显示，避免为所有正常用户增加操作成本。

### 6.3 输入状态

每个输入控件必须提供以下状态：

- 默认
- 悬停
- 键盘聚焦
- 已填写
- 禁用
- 校验错误
- 浏览器自动填充

浏览器自动填充状态不得使用与整体风格冲突的黄色或蓝色实心背景，应确保文字和焦点环仍清晰可见。

## 7. 交互规则

### 7.1 页面初始化

1. 页面加载后，焦点默认进入账号输入框。
2. 如果浏览器存在安全的账号记忆记录，可以自动填入账号，但不自动提交。
3. 密码始终以掩码显示。
4. 如果用户因会话过期被重定向到登录页，页面顶部显示“登录已失效，请重新登录”。
5. 页面不展示上一次失败密码或任何敏感信息。

### 7.2 密码显示与隐藏

- 点击密码框右侧图标切换显示状态。
- 切换后输入焦点和光标位置保持不变。
- 离开页面或刷新页面后恢复隐藏状态。
- 图标必须提供“显示密码”或“隐藏密码”的可访问名称。

### 7.3 表单提交

- 点击“登录”或在账号、密码、验证码输入框中按 Enter 均可提交。
- 提交前执行必填和格式校验。
- 提交期间登录按钮禁用，文字变为“登录中”。
- 提交期间不可重复发起相同登录请求。
- 网络请求完成后恢复可操作状态。
- 首个校验错误出现时，焦点移动到对应字段。

### 7.4 保持登录

- 未勾选时，使用常规会话策略，浏览器关闭后的会话时长由安全策略决定。
- 勾选后，服务端签发最长 7 天的可撤销刷新凭证。
- 前端不得使用 Local Storage 保存密码或长期访问令牌。
- 用户主动退出、密码重置、账号停用、角色失效或管理员强制下线时，保持登录凭证立即失效。
- 公共设备不建议使用保持登录，是否增加提示待确认。

### 7.5 忘记密码

v1.0 不提供短信或邮件自助找回密码。

点击“忘记密码”后打开轻量对话框：

- 标题：“无法登录？”
- 说明：“请联系系统管理员重置密码。”
- 主操作：“联系管理员”
- 次操作：“我知道了”

如果项目已配置管理员联系方式，“联系管理员”打开对应联系方式；未配置时只展示说明文字。管理员通过用户管理模块中的“重置密码”完成处理。

### 7.6 联系管理员

页面右上角“遇到问题？联系管理员”和忘记密码对话框复用同一联系配置。支持的联系方式可以是内部工单地址、企业即时通讯链接或管理员电话，具体方式待确认。

## 8. 登录流程

### 8.1 正常登录

1. 用户输入账号和密码。
2. 用户选择是否保持登录。
3. 用户提交表单。
4. 服务端验证验证码要求、账号、密码和账号状态。
5. 服务端校验用户角色是否有效。
6. 服务端创建会话并记录成功日志。
7. 如果 `forcePasswordChange` 为 `true`，跳转到首次登录修改密码页面。
8. 首次改密完成或无需改密时，前端请求后端授权上下文。
9. 后端根据用户、有效角色和权限配置统一生成菜单树、功能权限码和数据范围摘要。
10. 前端根据后端返回的菜单树渲染左侧菜单，不根据角色名称自行推断菜单。
11. 系统校验目标路径是否在授权菜单中；不在授权范围时跳转到后端指定的默认首页。

### 8.2 首次登录修改密码

- 首次登录使用管理员设置的初始密码。
- 认证成功但 `forcePasswordChange` 为 `true` 时，不允许直接进入业务系统。
- 用户完成新密码和确认密码校验后，系统更新密码并撤销其他旧会话。
- 修改成功后创建新的登录会话并进入首页。
- 首次改密页面需要另行设计原型，本 PRD 仅定义跳转规则。

### 8.3 登录失败

| 场景 | 页面提示 | 行为 |
| --- | --- | --- |
| 账号或密码错误 | “账号或密码错误，请重新输入” | 清空密码，保留账号 |
| 账号已停用 | “账号已停用，请联系管理员” | 清空密码，提供联系管理员入口 |
| 角色已停用或无有效角色 | “账号暂时无法访问系统，请联系管理员” | 不创建会话 |
| 需要验证码 | “请完成验证码后重试” | 展开验证码字段并聚焦 |
| 验证码错误 | “验证码错误或已失效” | 刷新验证码 |
| 请求过于频繁 | “操作过于频繁，请稍后再试” | 临时禁用提交并展示剩余等待时间 |
| 网络异常 | “网络连接失败，请检查网络后重试” | 保留账号和复选框状态，清空密码 |
| 服务异常 | “系统暂时不可用，请稍后重试” | 提供重新登录操作 |

账号或密码错误时使用统一提示，避免未通过密码验证的请求判断账号是否存在。

## 9. 风控与安全要求

### 9.1 登录失败限制

建议首版基线规则：

- 同一账号 15 分钟内连续失败 5 次后，下次登录必须完成图形验证码。
- 同一账号 15 分钟内连续失败 10 次后，临时锁定 30 分钟。
- 同一 IP 的请求频率需要服务端限制，具体阈值由安全评审确定。
- 登录成功后清除当前账号的连续失败计数。
- 管理员重置密码后清除临时锁定状态，是否允许由管理员单独解锁待确认。

阈值必须由后端配置，不允许写死在前端。

### 9.2 凭证安全

- 全程使用 HTTPS。
- 密码只能在提交登录请求时短暂存在于内存，不写入日志、埋点、URL、缓存或持久化存储。
- 服务端使用安全密码哈希算法保存密码，不保存可逆明文。
- 访问令牌和刷新凭证优先使用 `HttpOnly`、`Secure`、`SameSite` Cookie。
- 登录响应和错误日志不得返回密码、密码哈希或完整会话凭证。
- 密码重置、账号停用和强制下线后立即撤销相关会话。

### 9.3 会话安全

- 普通会话和 7 天保持登录会话使用不同有效期。
- 服务端支持主动撤销指定用户的全部会话。
- 同一账号允许同时登录的设备数量待确认。
- 长时间无操作后的会话超时时间待安全评审确定。
- 用户权限或数据范围发生变化后，权限缓存及时失效，不允许旧会话继续使用已撤销权限。

### 9.4 审计日志

登录日志至少记录：

- 用户 ID，无法识别账号时不记录用户 ID
- 登录时间
- 登录结果
- 失败原因分类
- IP 地址
- 设备或浏览器摘要
- 会话创建或撤销结果

日志禁止记录账号输入原文之外的敏感凭证，手机号是否脱敏按系统日志权限执行。

## 10. 状态与反馈

### 10.1 加载状态

- 页面首屏不使用全屏旋转加载图标。
- 品牌标识和表单结构优先渲染。
- 登录请求期间仅登录按钮进入加载状态。

### 10.2 错误状态

- 字段格式错误显示在对应字段下方。
- 登录业务错误显示在表单顶部的上下文提示区。
- 短暂提示不得作为唯一错误反馈。
- 错误出现后不得导致表单大幅跳动。

### 10.3 维护状态

系统计划维护时，登录区显示维护说明、预计恢复时间和管理员联系方式。维护时间必须来自真实配置，不使用虚构时间。

### 10.4 无障碍要求

- 表单标签与输入框建立程序化关联。
- 错误提示通过 `aria-describedby` 关联对应字段。
- 登录失败后使用无障碍实时区域播报错误。
- 所有控件支持键盘操作。
- 焦点状态清晰可见。
- 正文和控件满足 WCAG AA 对比度要求。
- 不仅通过颜色表达错误，必须同时显示错误文字或图标。

## 11. 数据与接口字段建议

### 11.1 登录请求

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `account` | string | 是 | 用户名或手机号 |
| `password` | string | 是 | 用户输入密码，仅用于本次认证 |
| `rememberMe` | boolean | 是 | 是否申请 7 天保持登录 |
| `captchaCode` | string | 条件必填 | 风控要求验证码时提交 |
| `captchaToken` | string | 条件必填 | 验证码服务端凭证 |

### 11.2 登录结果

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `success` | boolean | 是否认证成功 |
| `errorCode` | enum nullable | 失败原因稳定编码 |
| `requiresCaptcha` | boolean | 下次提交是否需要验证码 |
| `forcePasswordChange` | boolean | 是否必须先修改密码 |
| `authContextRequired` | boolean | 是否需要获取最新授权上下文，登录成功后固定为 `true` |

错误信息由前端根据稳定错误编码映射，服务端不返回包含敏感内部信息的原始异常文本。

### 11.3 登录错误枚举

| 提交值 | 中文含义 | 页面处理 |
| --- | --- | --- |
| `INVALID_CREDENTIALS` | 账号或密码错误 | 使用统一错误提示 |
| `ACCOUNT_DISABLED` | 账号已停用 | 联系管理员 |
| `ROLE_UNAVAILABLE` | 无有效角色 | 联系管理员 |
| `CAPTCHA_REQUIRED` | 需要验证码 | 展开验证码字段 |
| `CAPTCHA_INVALID` | 验证码错误或失效 | 刷新验证码 |
| `ACCOUNT_TEMP_LOCKED` | 账号临时锁定 | 显示剩余时间或稍后重试提示 |
| `RATE_LIMITED` | 请求过于频繁 | 临时禁用提交 |
| `SYSTEM_UNAVAILABLE` | 系统不可用 | 展示重试入口 |

错误枚举使用稳定英文编码，前端不得依赖后端中文文本判断状态。

## 12. 登录后的菜单与权限加载

### 12.1 统一授权原则

登录后的左侧菜单、页面路由、按钮操作和数据范围均以后端授权结果为准。

- 后端是权限配置和权限判断的唯一可信来源。
- 前端不维护“角色名称对应哪些菜单”的映射。
- 前端不根据用户所属部门、是否管理员等字段自行扩展菜单。
- 前端隐藏菜单或按钮只用于界面呈现，不能替代后端接口鉴权。
- 每个业务接口必须由后端校验会话、功能权限和数据权限。
- 数据范围由后端查询条件统一处理，前端不得先获取全量数据再自行过滤。

### 12.2 后端授权计算

v1.0 一个用户只分配一个角色。后端按以下顺序生成授权上下文：

1. 获取当前会话对应用户。
2. 校验用户状态是否为 `active`。
3. 获取用户当前有效角色。
4. 获取角色关联的功能权限编码。
5. 根据功能权限筛选可访问菜单和页面路由。
6. 删除没有任何可访问子菜单的空目录节点。
7. 根据角色数据范围计算数据权限摘要。
8. 计算用户可进入的默认首页。
9. 生成权限版本 `permissionVersion`。
10. 返回完整授权上下文。

超级管理员同样通过该流程获取菜单，不允许前端使用“超级管理员显示全部菜单”的特殊判断。

### 12.3 授权上下文加载时机

前端必须在以下时机向后端获取最新授权上下文：

- 登录成功且无需首次改密时。
- 首次改密完成后。
- 浏览器刷新或重新打开仍有效的登录会话时。
- 后端返回权限已变更状态时。
- 用户主动切换组织或租户时，后续能力如支持。

授权上下文建议使用独立接口获取，便于页面刷新时复用。技术实现可以将登录与授权结果合并返回，但必须保持相同的后端统一计算规则。

### 12.4 授权上下文响应

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `user` | object | 当前用户基础信息，不包含密码等敏感字段 |
| `user.id` | string | 当前用户 ID |
| `user.name` | string | 当前用户姓名 |
| `user.avatarUrl` | string nullable | 当前用户头像 |
| `role` | object | 当前有效角色摘要 |
| `role.id` | string | 角色 ID |
| `role.name` | string | 角色名称，仅用于展示，不参与前端权限判断 |
| `menus` | MenuNode[] | 后端生成并排序后的左侧菜单树 |
| `permissionCodes` | string[] | 页面和按钮功能权限编码集合 |
| `dataScope` | object | 数据权限摘要，仅用于界面说明，实际过滤由后端完成 |
| `homeRoute` | string nullable | 后端计算的默认首页路由 |
| `permissionVersion` | string | 当前权限版本，用于判断前端权限缓存是否过期 |

### 12.5 菜单节点结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 菜单节点唯一标识 |
| `parentId` | string nullable | 父菜单 ID，根节点为空 |
| `type` | enum | `directory` 或 `page` |
| `name` | string | 菜单中文名称，例如“系统管理” |
| `routeName` | string nullable | 前端稳定路由名称；目录可为空 |
| `path` | string nullable | 系统内路由路径；目录可为空 |
| `iconKey` | string nullable | 前端图标库中的稳定图标键 |
| `permissionCode` | string nullable | 访问页面所需功能权限编码 |
| `order` | integer | 同级菜单排序值，由后端统一排序 |
| `children` | MenuNode[] | 子菜单列表 |

菜单节点不直接返回远程组件代码、脚本地址或任意图标 URL。前端只允许将 `routeName` 和 `iconKey` 映射到本地已注册的安全组件。

### 12.6 左侧菜单渲染规则

- 前端严格按照后端返回的 `menus` 渲染左侧菜单。
- 后端未返回的菜单不得展示，即使前端存在对应页面组件。
- 菜单顺序以后端返回顺序为准。
- `directory` 节点负责展开和收起，不直接进入业务页面。
- `page` 节点点击后进入对应授权路由。
- 当前路由对应菜单显示选中状态，其祖先目录自动展开。
- 后端返回空子节点目录时，前端忽略该目录并记录数据异常。
- 菜单加载完成前显示匹配侧边栏结构的骨架，不短暂展示全部菜单。
- 菜单加载失败时展示“菜单加载失败”和“重新加载”，不得回退为固定全量菜单。

### 12.7 功能权限和按钮权限

菜单权限只控制页面入口，按钮和接口需要使用独立功能权限编码。

例如用户管理页面：

| 操作 | 权限编码 |
| --- | --- |
| 查看用户页面 | `system:user:view` |
| 新增用户 | `system:user:create` |
| 编辑用户 | `system:user:update` |
| 停用或启用用户 | `system:user:disable` |
| 重置密码 | `system:user:reset-password` |
| 查看完整手机号 | `system:user:mobile:full` |

前端可以根据 `permissionCodes` 隐藏或禁用按钮，但后端对应接口必须使用相同权限编码再次校验。前端拥有权限码不代表接口可以跳过校验。

### 12.8 数据权限处理

`dataScope` 可以向前端返回当前范围摘要，例如“仅本人”“本部门及下级”，用于页面提示和组织树展示。实际数据处理规则如下：

- 用户列表、线索、客户、商机和系统日志均由后端加入数据权限条件。
- 前端不得接收超出权限范围的数据。
- 列表总数、筛选项人数、导出数据和详情接口使用同一数据权限规则。
- 用户通过修改请求参数、路由或部门 ID 不能突破数据范围。
- 后端需要校验目标数据是否处于当前用户的数据范围内。

具体数据范围枚举和组织树规则以用户管理模块 PRD v0.4 为准。

### 12.9 默认首页与路由跳转

- 未登录用户访问受保护页面时，跳转登录页并保存安全的站内目标路径。
- 登录成功后仅允许跳转到后端菜单树包含的系统内页面。
- 如果原目标路径仍在授权菜单中，优先恢复原目标路径。
- 原目标无权限时，跳转到 `homeRoute`。
- `homeRoute` 为空时，进入菜单树中的第一个可访问 `page` 节点。
- 已登录用户访问登录页时，先刷新授权上下文，再跳转到有效默认页面。
- 禁止使用外部 URL 或未注册路由作为登录后跳转目标。
- 退出登录后返回登录页，并清除当前会话的菜单和权限缓存。

### 12.10 无可用菜单

账号认证成功但后端计算出的菜单树为空时：

- 不进入空白后台框架。
- 展示独立无权限页面，标题为“暂无可用功能”。
- 说明文字为“当前账号尚未分配可访问功能，请联系管理员。”
- 提供“联系管理员”和“退出登录”。
- 记录 `NO_AVAILABLE_MENU` 授权异常日志。
- 不允许前端默认补充首页或其他菜单。

### 12.11 权限变更与缓存失效

- 角色权限、用户角色或账号状态变更后，后端更新 `permissionVersion` 并使相关权限缓存失效。
- 前端授权上下文仅在当前会话内缓存，不使用长期 Local Storage 保存。
- 页面刷新时重新从后端获取授权上下文。
- 业务接口发现权限版本已变化时，返回稳定状态码，前端重新获取授权上下文。
- 当前页面权限被撤销时，前端跳转到新的 `homeRoute` 或无权限页面。
- 账号被停用时，后端撤销会话，前端返回登录页。
- 权限扩大后，需要重新获取授权上下文才能展示新增菜单和按钮。
- 权限收回必须由后端即时生效，不能依赖用户手动刷新前端页面。

### 12.12 异常枚举

| 错误编码 | 中文含义 | 前端处理 |
| --- | --- | --- |
| `AUTH_CONTEXT_LOAD_FAILED` | 授权上下文加载失败 | 展示重试，不渲染固定菜单 |
| `NO_AVAILABLE_MENU` | 无可用菜单 | 进入无权限页面 |
| `ROUTE_FORBIDDEN` | 当前路由无权限 | 跳转默认首页并提示 |
| `ACTION_FORBIDDEN` | 当前操作无权限 | 隐藏或禁用入口，接口返回时提示权限不足 |
| `PERMISSION_VERSION_CHANGED` | 权限已更新 | 重新获取授权上下文 |
| `SESSION_REVOKED` | 会话已撤销 | 清除前端状态并返回登录页 |

## 13. 埋点建议

登录埋点不记录账号、手机号、密码、验证码、令牌或管理员联系方式原文。

| 事件 | 触发时机 | 参数 |
| --- | --- | --- |
| `login_page_view` | 登录页可用 | 来源类型、是否会话过期 |
| `login_submit` | 提交登录 | 是否勾选保持登录、是否出现验证码 |
| `login_result` | 登录请求完成 | 成功或失败、稳定错误分类 |
| `password_visibility_toggle` | 切换密码显示 | 显示或隐藏 |
| `forgot_password_click` | 点击忘记密码 | 是否配置管理员联系方式 |
| `admin_contact_click` | 点击联系管理员 | 联系方式类型，不记录具体值 |
| `auth_context_load` | 请求授权上下文完成 | 成功或失败、耗时、触发场景、稳定错误分类 |
| `menu_render` | 左侧菜单首次渲染完成 | 菜单节点数量、顶级目录数量，不记录菜单业务数据 |
| `route_forbidden` | 用户进入未授权路由 | 目标路由名称、来源类型，不记录 URL 查询参数 |
| `permission_context_refresh` | 权限版本变化并刷新授权上下文 | 刷新原因、成功或失败 |

## 14. 验收标准

### 14.1 视觉一致性

- [ ] 登录页使用与后台相同的品牌蓝和冷灰中性色。
- [ ] 页面不存在紫色、暖色强调、彩色渐变、玻璃拟态和外发光。
- [ ] 品牌标识、标题、输入框和按钮符合统一字体与圆角规范。
- [ ] 页面只有“登录”一个主要操作。
- [ ] 登录按钮文字和背景满足对比度要求且不会折行。
- [ ] 所有字段标签始终可见，占位文字不替代标签。

### 14.2 登录功能

- [ ] 用户名或手机号和正确密码可以完成登录。
- [ ] 必填字段为空或格式错误时不能提交。
- [ ] Enter 可以提交表单。
- [ ] 提交期间不能重复发送登录请求。
- [ ] 登录成功后按首次改密状态和权限跳转。
- [ ] 已登录用户访问登录页时自动进入系统。

### 14.3 安全与风控

- [ ] 错误账号和错误密码使用统一提示。
- [ ] 达到失败阈值后按规则显示验证码或临时锁定账号。
- [ ] 保持登录不会保存明文密码或长期访问令牌。
- [ ] 密码重置、账号停用和主动退出后旧会话失效。
- [ ] 登录日志不包含密码、验证码和完整会话凭证。
- [ ] 重定向目标不能跳出系统白名单。

### 14.4 状态与兼容性

- [ ] 网络失败、系统失败、账号停用、无有效角色和请求频繁均有明确反馈。
- [ ] 1024px 以下按规则切换为单列登录布局，不出现被压缩的左右分屏。
- [ ] 320、360、375、414、768、1024、1280 和 1440px 视口均无页面级横向滚动。
- [ ] 手机竖屏和横屏中，软键盘弹出后仍可滚动到登录按钮和错误信息。
- [ ] 移动端输入文字不小于 16px，聚焦时页面不会发生非预期缩放。
- [ ] 刘海、圆角屏和底部手势区域不会遮挡品牌、表单、按钮或页脚。
- [ ] 视口尺寸或方向变化不会清空用户已输入内容。
- [ ] 键盘、自动填充和密码管理器可以正常工作。
- [ ] 所有交互控件具备清晰焦点状态。
- [ ] 最近两个主要版本的 Chrome 和 Edge 可以正常使用。

### 14.5 菜单与权限

- [ ] 登录或有效会话恢复后，前端从后端获取授权上下文，再渲染左侧菜单。
- [ ] 左侧菜单的节点、层级和顺序与后端返回的 `menus` 一致，前端不按角色名称推导菜单。
- [ ] 后端未授权的菜单、路由和按钮不在前端展示，直接输入未授权地址时也不能访问。
- [ ] 所有业务接口由后端独立校验功能权限，不能通过调用接口绕过前端限制。
- [ ] 列表、详情、统计数量、筛选项和导出均由后端按同一数据权限规则过滤。
- [ ] 浏览器刷新后重新获取授权上下文，加载期间不短暂展示全量菜单。
- [ ] 角色权限或用户角色变化后，旧权限及时失效；当前页面被撤权时跳转至新的默认首页或无权限页。
- [ ] 账号被停用或会话被撤销后，业务接口不可继续访问，前端返回登录页。
- [ ] 后端返回空菜单时展示“暂无可用功能”，前端不自行补充默认菜单。
- [ ] 授权上下文加载失败时允许重试，但不得降级成固定全量菜单。

## 15. 待确认项

1. 登录账号是否同时支持用户名和手机号，或还需要支持工号。
2. 同一账号允许同时登录的设备数量。
3. 普通会话和无操作超时的具体时长。
4. 连续失败、验证码和临时锁定阈值是否采用本文建议值。
5. 管理员联系方式使用内部工单、企业即时通讯还是电话。
6. 是否允许管理员手动解除临时锁定。
7. 是否需要在公共设备场景提示用户不要选择 7 天保持登录。
8. 登录后默认进入首页还是恢复上次访问页面。
9. 首次登录修改密码页面是否与登录页使用同一分屏布局。
10. 后续优先接入单点登录、扫码登录还是短信登录。
11. 授权上下文采用独立接口，还是与登录响应合并返回。
12. 权限变更从后台保存到在线会话生效的最大允许延迟。
13. 默认首页由角色配置、菜单配置还是单独的首页规则决定。
14. 前后端共同维护的 `routeName`、`iconKey` 和权限编码字典由哪一方负责发布与版本管理。
